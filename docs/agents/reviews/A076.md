# A076 — Windows portability review

**Evidence boundary.** This is a static review. The integrator reports hosted
Windows success at commit `f4116856abf482066ffdb9ad2bac4c7c4212671e`, run
`45170843821`; I did not execute Windows or fetch its logs.

**Build configuration.** [CMakeLists.txt](../../../CMakeLists.txt) and
[CI](../../../.github/workflows/ci.yml) correctly pair multi-configuration builds
with `--config Release` and CTest with `-C Release`. Target names and
`$<TARGET_FILE:rhodes_render>` avoid hard-coded executable locations in tests.
[Development instructions](../../DEVELOPMENT.md) correctly identify
`build/Release/`; Ninja presets instead use their configured build directories.
MSVC receives `/W4`, `/permissive-`, `/fp:precise`, and optional `/WX`, without GNU
warning flags. The sanitizer preset excludes Windows, but manually enabling
`RHODES_ENABLE_SANITIZERS` under MSVC silently adds no instrumentation: document
or reject that unsupported combination.

**Filesystem and text contracts.** [The renderer](../../../apps/render.cpp)
opens WAV output in binary mode and writes explicit little-endian fields, avoiding
text newline translation. [Git attributes](../../../.gitattributes) require LF;
the project/campaign writers explicitly use UTF-8 and LF. These contracts should
remain distinct from platform-native CLI stdout newlines.
[Both](../../../apps/render.cpp) [CLIs](../../../apps/benchmark.cpp) consume
narrow `argv`: the benchmark demands UTF-8 labels, while the renderer constructs
filesystem paths directly from argument bytes. No explicit Windows argument
conversion or non-ASCII CLI test establishes that arbitrary Unicode labels and
paths work. Benchmark JSON uses the classic locale, protecting decimal syntax.

**Actionable coverage gap.** CI's Windows job exercises C++/CTest only; Python
state, provenance, and ledger checks run on Ubuntu. Documentation appropriately
substitutes `python` for `python3` on Windows. Add a Windows Python 3.11 job and
CLI cases for spaced/Unicode paths and labels, then parse emitted JSON and inspect
WAV bytes. Current smoke tests establish process success, not those contracts.

**Checks performed.** Targeted `cat`/`sed`/`rg` inspection; report word-count,
UTF-8, and LF checks. No build, platform execution, Git, or shared-state mutation.

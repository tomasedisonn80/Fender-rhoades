# A010 — Documentation integrity checker

## Scope and changes

Added `tools/check_docs.py` and `tests/python/test_docs.py`. The standard-library
checker scans repository Markdown, including unstaged additions, without Git or
network access. It reports missing relative link targets, resolved paths escaping
the repository (including symlinks), absolute local targets, unclosed fences, and
missing final newlines with document and line numbers.

The documented subset supports inline/image links, reference definitions, link
titles, escaped paths, and matching backtick/tilde fences. Code examples,
standalone comments, explicit placeholders, external URLs, and heading fragments
are excluded. Generated output, virtual environments, and `.git` are skipped.

## Observed verification

- `python3 -m unittest discover -s tests/python -p test_docs.py -v`: **12 passed**.
  Cases cover missing targets, plain/encoded traversal, absolute targets,
  symlink escape, fence mismatches, final newlines, example exclusions, CLI
  failure diagnostics, and the current repository documents.
- `python3 tools/check_docs.py`: **passed** after implementation and review.
- Entry checks `project.py validate`, `sync --check`, and `next --json`: **passed**.

## Limits and handoff

This is a deliberately limited integrity scanner, not a CommonMark parser or
web-availability checker. It does not validate heading IDs, reference-label use,
HTML links, multiline links, or fences nested in lists/quotes. Archived research
text is not scanned; Markdown links to that text still require an existing file.
Only local Python verification was observed. No Git, canonical state, or CI
configuration was changed. Integrator next step: wire `python3 tools/check_docs.py`
into the repository checks.

# A068 — Crash recovery and publication durability

Assignment: review recovery guarantees; owned path: this report only. Baseline:
shared working tree, canonical revision 4. Inspected `AGENTS.md`, required startup
documents, `tools/project.py`, `tools/verify_payloads.py`,
`docs/agents/WORKFLOW.md`, and `tests/python/test_state_review.py`.

**Durability boundary.** `atomic_write` flushes/fsyncs its temporary file before
`os.replace`; `publish_report` similarly syncs file contents before linking.
Neither fsyncs the containing directory. Atomic visibility therefore does not
establish survival of pathname updates after machine failure or power loss.
This is a concrete missing durability step, not an observed power-loss failure.

**Recovery contract.** Canonical JSON precedes generated Markdown. An error after
the JSON replacement may leave a committed claim without its printed token;
recover the claim from JSON, then run `validate`, `sync`, and `sync --check`.
These are recovery instructions, not checks executed here. Evidence registration
precedes completion. Directory locks are cooperative, time out without stealing,
and require manual recovery. PID/timestamp metadata can be absent after abrupt
death or ambiguous after PID reuse; verify the actual writer has stopped before
removal. Expired task leases do not stop old processes editing files.

**Reproduced publication ambiguity.** Exclusive `os.link` refuses an existing
destination. However, injecting an `OSError` into temporary-file cleanup after
the link produced CLI status **2**, stderr “could not publish a report,” and an
existing complete report whose result was **pass**. One temporary hard link also
remained. A retry must inspect the existing final report rather than assume
nothing was published.

**Checks and next action.** Ran `python3 -B -` with a temporary one-byte payload,
matching SHA-256 manifest, mocked cleanup failure, and fsync-descriptor tracing;
exit **0**, assertions passed. Both write paths synced only regular files.
Existing regression tests were read, not rerun. No physical crash, adversarial
race, or other-platform testing occurred. Next: distinguish post-publication
cleanup failure and document or implement platform-specific directory durability.

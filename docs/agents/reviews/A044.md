## Changes and declared contract

Every evidence record now requires `profile_path` (a path or `null`) and
`session_paths` (a unique list, empty when inapplicable). The CLI exposes
`--profile` and repeatable `--session`. Each explicit path must also appear in the
same record's immutable artifact list and pass the existing path/hash checks.
Fields are never inferred from filenames or arbitrary JSON reports. The empty
foundation registry remains schema version 1; schema, validator, fixtures, and
documentation were updated together, with no populated registry migration.

| Evidence kind | Enforced declaration |
| --- | --- |
| `specimen_identity` | Valid `identified` profile, `specimen_id` equal to `profile_id`, and no acquisition sessions |
| `measurement` | The same identified profile requirement plus valid `measured` session manifests referring to that profile |
| `hardware_validation` | The same measured-session requirement, only `validation`/`test` splits, retained `independent: true`, and passing measurement references covering every linked observation |

Hardware coverage matches specimen ID and the profile's immutable SHA-256. Every
linked session must be covered by the union of qualifying measurement references,
using its `session_id` and manifest SHA-256. A different session or profile version
does not cover the observation. Identical manifest references count once for the
existing cross-session split checks; conflicting IDs, conditions, or payload
hashes retain the data validator's rejection behavior.

The implementation invokes the existing profile, session, and split functions
directly after strictly loading the source registry. It does not invoke the full
repository data validator or reread canonical task state. The latter's full
component/inventory checks remain a separate command. Ordinary evidence artifacts
remain opaque. Typed links are reserved for the three specimen evidence kinds;
other kinds use `profile_path: null` and `session_paths: []`.

The existing independent declaration, immutable-artifact restrictions, completion
gates, and `source_commit` syntax boundary remain. Project-schema identifier,
digest, and timestamp patterns also gained an absolute-end guard after `$`, as
requested during A045 integration, so JSON Schema search semantics cannot accept
an extra trailing line feed. Free-text patterns were preserved.

## Limits and handoff

These checks establish consistency between declared documents and immutable local
bytes. They cannot establish that a specimen exists, an acquisition occurred, a
calibration or rights reference is authentic, raw payloads match a manifest, or
conditions are statistically independent. Raw payloads are not opened or fetched.
`source_commit` remains syntax-checked only; neither Git object existence nor its
association with the tested source is certified. Acceptance relevance and
scientific sufficiency remain reviewer responsibilities. No C++ DSP, remote CI,
hardware measurement, or physical fidelity claim was exercised by this change.

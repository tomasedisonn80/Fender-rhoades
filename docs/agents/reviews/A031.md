# A031 — Callback workload bounds and deadlines

**Finding.** The [core](../../../src/research_engine.cpp) visits 73 keys × three modes and every pickup branch per sample, including silence. `process()` accepts an arbitrary span, so fixed sample work does not establish a callback bound without a maximum frame count. There is no event-list API or iterative solver yet. Note/pedal operations recompute damping transitions; sustain traverses all keys. The [benchmark](../../BENCHMARKING.md) excludes these operations, and its active-key parameter cannot establish polyphony scaling.

**Required contract.** Before host integration, declare maximum frames/events, integer offsets, tie ordering, bounded event validation, and an explicit overflow policy. Bound modes, coupling edges, internal substeps, nonlinear iterations, and every fallback/retry; preallocate their storage. Record residuals and cap exhaustion with a deterministic failure response. Reference convergence does not authorize unlimited callback iterations. Preserve all physical-key states and silent electrical branches when reducing coupled mechanics or circuits, consistent with the [runtime architecture](../../ARCHITECTURE.md#numerical-and-runtime-contracts).

**Proposed future stress case.** At 192 kHz and 64 frames, begin with all 73 keys ringing. Exercise a proposed 256-event budget: 73 releases and 73 maximum-strength retriggers at offset zero, then 110 alternating pedal events distributed deterministically over offsets 1–63. This budget is a test proposal, not current API support. Enable the maximum approved modes, coupling, contact, circuit complexity, internal rate, and solver caps; separately force nonconvergence and one-event overflow.

**Measurement/handoff.** The nominal block interval is approximately 333.3 µs. Measure scheduled wake-up lateness, complete callback/event time, completion deadlines, and device underruns separately. Retain revision/diff, model/event hashes, build flags, CPU/OS/power/load, affinity/priority, host/device settings, budgets, residual/cap counters, run length, raw timings, and reference error. Offline body maxima establish neither scheduling compliance nor CPU utilization or a guarantee. Source inspection only; no timing experiment ran. Next: specify these limits before extending the harness.

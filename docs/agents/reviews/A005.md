# A005 — CI and portability audit

## Scope and result

Reviewed the actual CMake targets, presets, GitHub Actions workflow, dependency
update configuration, documented build commands, and renderer portability.
The configured jobs refer to existing targets and supported command options.
Python CI selects 3.11, matching the documented minimum. Generic CMake commands
use `--config Release`, and CTest resolves target executable locations for
multi-configuration generators. The documented Windows renderer path correctly
includes `Release/` when using Visual Studio.

The workflow requests only `contents: read`; every checkout disables persisted
credentials. No job deploys, commits, or pushes. The checkout and setup-python
commit pins match the tag resolutions already observed by the integrator for
v4.2.2 and v5.6.0. Dependabot is limited to monthly GitHub Actions updates with
three open proposals. The sanitizer preset requires Ninja; local Ninja execution
was verified, while hosted availability remains subject to the actual CI run.

## Changes

Added `--no-tests=error` to both hosted CTest invocations so an accidentally empty
test selection fails. Added `UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1` to
the sanitizer job: undefined-behavior diagnostics must cause a failure instead of
continuing with a successful process exit. LeakSanitizer remains enabled under
the hosted defaults; no local environment suppression was carried into CI.

## Verification performed

Ran the following locally with GNU 14.2.0 and CMake 4.4.5:

```sh
cmake -S . -B 'build/a005 multi' -G 'Ninja Multi-Config'
cmake --build 'build/a005 multi' --config Release --parallel 2
ctest --test-dir 'build/a005 multi' -C Release --output-on-failure --no-tests=error
```

Configuration and compilation succeeded; **16/16 CTests passed**. A build path
containing a space exercised executable-path handling, including the negative
CLI wrappers. This verifies Linux multi-configuration behavior, not native
Windows/MSVC or macOS/Clang execution.

## Handoff

The documentation requires CMake 3.24+, but `CMakeLists.txt` declares 3.20 and the
presets declare 3.21. This is a consistency issue, not a tested failure; the
integrator was asked to align the declarations with the documented floor.
Native platform success and hosted sanitizer results must be reported only after
the corresponding jobs finish for the published commit.

Changed files: `.github/workflows/ci.yml` and this report. No canonical state,
evidence registry, commit, push, or release was modified by A005.

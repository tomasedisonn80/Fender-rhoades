**Owned changes:** [tools/verify_payloads.py](../../../tools/verify_payloads.py),

## Implemented behavior

The new standard-library CLI requires `--manifest`, `--payload-root`, and
`--report`. It opens only local filesystem paths and performs no network access,
execution of manifest content, import, or payload rewrite. Artifact paths are
relative to the explicitly supplied payload root. For example, with root
`data/raw`, artifact `session/take.wav` refers to `data/raw/session/take.wav`.

Only the manifest's artifact list is validated here. Full session/profile
validation remains the separate metadata check in `validate_data.py`. The list
must be nonempty; each entry must contain exactly `path`, `sha256`, and `bytes`.
Shared metadata helpers enforce canonical relative POSIX paths, including
traversal/control-character rejection. Digests must be 64 lowercase hexadecimal
characters and byte counts must be positive integers; booleans and duplicate
paths are rejected. JSON rejects duplicate keys, nonfinite values, overflow, and
invalid UTF-8. The manifest digest and parsed JSON come from the same captured
descriptor stream, avoiding a hash-then-reload gap.

Every filesystem component, including the payload root and its ancestors, is
checked with `lstat`; symlinks and Windows reparse points are rejected. Payloads
must be regular files contained within the resolved root. SHA-256 and actual
byte counts are streamed from one read-only descriptor in 1 MiB chunks. Descriptor
fingerprints before/after reading and the final pathname fingerprint compare
device, inode, mode, size, modification time and change time. Root identity is
also rechecked. `O_NOFOLLOW` and `O_NONBLOCK` are used where available; the latter
avoids a FIFO-open hang following an ordinary file-type replacement.

Each JSON report records its schema/tool version, UTC check time, manifest path
and observed hash/count, root, expected and observed payload values, read-complete
flags, and failures. A partial read retains its partial count/hash and is always
failed. Invalid manifests stop payload inspection; failures in one payload do
not prevent checking the remaining validly declared payloads.

The report parent must already exist. The destination must be outside the root,
must not alias the manifest, and must not already exist. Refusing every existing
object also rejects dangling symlinks and hard-link aliases of inputs. A complete
temporary report is flushed and fsynced in the report directory, then published
with an exclusive hard link. A competing destination is preserved. Temporary
files are removed after normal success or failure. Filesystems without hard-link
support cause an error; no partial final-file fallback is used.

Illustrative usage, requiring actual user-supplied local inputs and an existing
report directory:

```sh
python3 tools/verify_payloads.py --manifest path/to/session.json \
  --payload-root data/raw --report docs/validation/payload-check-001.json
```

Exit status `0` means all declared payloads passed. Status `1` means the newly
published report records an invalid manifest or failed inspection. Status `2`
means invalid invocation, unsafe/unavailable setup, or unsuccessful report
publication; the caller must not assume a report exists in that case.

## Actual verification

Run on Linux x86_64 with Python 3.12.14:

```sh
python3 -m unittest discover -s tests/python -p test_payloads.py -v
```

**Result:** Exit 0; 18 tests passed, no skips, in the final focused run. The tests
exercise multiple chunks/files, exact source-manifest hash binding, wrong digest
and size, missing/truncated/unreadable/interrupted files, directories and FIFOs,
file/directory/root/ancestor/manifest symlinks, symlink loops, traversal and URL
inputs, strict JSON/artifact contracts, in-place mutation, pathname replacement,
input aliases, existing reports, and a competing report publisher. Permission
and interrupted-read failures use controlled mocks; concurrency fixtures make
actual local file changes at deterministic read/stat boundaries. The success
and FIFO fixtures also invoke the actual CLI in subprocesses with timeouts.

Only the focused suite was run by A053. This report claims no Windows/macOS,
remote-storage, physical-instrument, or acquired-data verification.

## Limits and handoff

Directories must be trusted and quiescent. The implementation is **not hardened
against adversarial directory races on every platform**. Component checks and
timestamps detect ordinary changes, but do not create a multi-file filesystem
snapshot or establish that bytes remain unchanged after their inspection. Atomic
publication prevents an existing destination being replaced; it is not a
crash-durability guarantee for the containing directory or an access-control
barrier against someone subsequently editing the report.

Integrity agreement establishes only which inspected bytes matched the declared
hash/count. It does not establish specimen authenticity, acquisition rights,
calibration, independent partitions, or physical fidelity. No immutable importer
or coordinated ingestion-schema revision was implemented. The next action is
integrator review/documentation of this opt-in CLI, followed by the separate
schema, importer, and physical-acquisition gates described in the ingestion
contract. `SPEC-001` and `DATA-001` remain dependent on external evidence.

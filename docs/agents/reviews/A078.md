# A078 — Linux compiler and sanitizer configuration

**Finding and correction.** Confirmed [A076](A076.md): enabling sanitizers under
MSVC previously bypassed every sanitizer flag. [CMakeLists.txt](../../../CMakeLists.txt)
now rejects `RHODES_ENABLE_SANITIZERS=ON` for MSVC-style drivers, including
clang-cl, and compiler families outside GNU, Clang, and AppleClang. The guard
checks both `MSVC` and `CMAKE_CXX_COMPILER_FRONTEND_VARIANT`; an MSVC-style Clang
driver therefore cannot pass merely because its compiler ID is Clang. With the
option OFF, the guard is bypassed and ordinary MSVC options remain unchanged.
Supported GNU-style drivers retain the existing compilation and linking flags.
This is a compiler-family policy check, not a probe for installed sanitizer
runtimes or individual target support.

**Flags and minima.** Project warnings remain `-Wall -Wextra -Wpedantic
-Wconversion -Wshadow`, or MSVC `/W4 /permissive- /fp:precise`, with optional
warnings-as-errors enabled by default. CMake and [presets](../../../CMakePresets.json)
agree on minimum CMake 3.24; the core publicly requires C++20.
`CXX_EXTENSIONS OFF` applies only to the core: the observed executables use
`-std=gnu++20`. [Development](../../DEVELOPMENT.md) separately requires Python
3.11 for tooling. No minimum compiler release is established by this review.
Neither project options nor the observed generated flags enable fast-math;
caller-supplied flags are not prohibited, so this is not an enforced numerical
guarantee.

**Observed check.** On Linux, CMake 4.4.5 and GNU C++ 14.2.0 successfully ran:

```sh
cmake -S . -B /tmp/rhodes-a078-sanitize -G Ninja -DCMAKE_BUILD_TYPE=Debug -DRHODES_ENABLE_SANITIZERS=ON -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
```

`rg -n 'FLAGS =|LINK_FLAGS =' /tmp/rhodes-a078-sanitize/build.ninja` showed
`-fsanitize=address,undefined -fno-omit-frame-pointer` on all five compilation
targets and sanitizer flags on all four executable links. No project targets
were built or executed. Static control-flow inspection establishes the new
rejection condition; an actual MSVC rejection was not executed.

**Evidence boundary and handoff.** [CI](../../../.github/workflows/ci.yml)
configures Linux, Windows, and macOS release builds plus Ubuntu sanitizers.
Those definitions do not establish passing runs. Clang, AppleClang, MSVC,
minimum-version tools, runtime instrumentation, and hosted CI were not tested
here. Next: integrate this guard and observe its opt-in diagnostic when an
MSVC toolchain is available. Changed paths are this report and `CMakeLists.txt`;
no workflow, shared state, or Git operations were performed.

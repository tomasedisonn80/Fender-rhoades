## Added contract

The new standalone CMake script requires an existing absolute `BENCHMARK` path
and has no Python dependency. It runs one measured block of 64 samples at the
supported lower endpoint, 32000 Hz, with zero active keys. It checks:

- Successful exit and empty stderr; JSON object/array/scalar types and required
  schema, synthetic benchmark, platform, build, workload, and timing labels.
- Exact machine-label round trip containing an ASCII quote, backslash, tab,
  newline, and control byte `0x1f`.
- The requested sample rate, block size, and block count; 32 warmup blocks;
  73 fixed key slots, three modes per key, no active indices, and the documented
  excitation/retrigger policy.
- Zero checksum and output peak, nonnegative callback duration, and equality
  of mean, p50, p99, and maximum for the single observation.
- The exact 2000-microsecond nominal deadline and a miss count of one precisely
  when the observed duration is strictly greater than that deadline. Either
  outcome passes when the accounting is consistent.
- A nonempty array of nonempty limitation strings and rejection of `--blocks 0`
  with exit code 2, empty stdout, and a benchmark diagnostic on stderr.

Every `string(JSON)` call checks `ERROR_VARIABLE`, including the root parse,
so parse errors and missing members fail explicitly. There is no performance
pass/fail threshold. The 30-second process timeout guards against a hung test;
it does not compare callback timing with a speed target.

## Limits and next step

Only the local Linux run was executed. The ASCII argument deliberately avoids
making an unverified Windows Unicode argv claim. The fixture does not test
invalid UTF-8, active-key output, multi-sample percentile calculations, timer
resolution, sustained runtime, or a physical instrument. A083's broader
one-off observations remain separate evidence. After CTest registration, run
the focused test in each actual CI platform job before claiming that platform's
integration behavior is verified.

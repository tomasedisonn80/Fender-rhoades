## Implemented behavior

- Strict standard-library JSON validation, task DAGs, acceptance/evidence fields,
  dependency completion, UTC timestamps, sequential history and artifact hashes.
- Claim/renew/complete/release/block/unblock/reopen commands; matching live
  owner/token required for leased changes and safe expired-lease reclamation.
- Process serialization with a cooperative directory lock, atomic file
  replacement, explicit crash recovery, and safe relative paths including symlink
  escape rejection.
- Evidence registration records already-observed results. It does not execute
  command strings. Hardware validation requires independent conditions and
  same-specimen passing measurement references; synthetic/numerical records cannot
  masquerade as measured specimen evidence.
- Deterministic generated state document; every task mutation refreshes it.
  `sync --check` detects drift. Runtime `next` selection accounts for live leases.
- Twelve initial roadmap tasks. FND-001 remains in progress for root integration;
  SPEC-001 and DATA-001 remain explicitly blocked on missing actual specimen/data.
  No scientific tasks or fidelity gates were marked complete by this assignment.
- Precise continuation prompt and integration/handoff instructions that preserve
  physical-state and provenance invariants from the supplied research.

## Limits and integration handoff

Evidence consistency is not proof of truthful reporting or measurement quality.
An editor able to rewrite the repository can rewrite declarations and hashes;
review, acquisition provenance and CI are still necessary. Canonical JSON and
generated Markdown are separate atomic writes; `validate` then `sync` recovers a
crash between them. The tool never launches agents, executes evidence commands,
performs external mutations, or promotes fidelity automatically.

The root integrator should run the complete build/data/test suite, save immutable
integration reports, register documentary and numerical evidence, and complete
FND-001 via a live claim. PHY-001 can then be evaluated against its actual
acceptance criteria. This agent made no Git commit or push and no measurements.

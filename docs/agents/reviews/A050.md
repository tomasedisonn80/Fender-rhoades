# A050 — Specimen identity and numbering

**Current evidence.** The [profile](../../../profiles/mark-i-stage-73/specimen.json) correctly remains unidentified: serial, production date, construction revisions and load are null; wiring is unverified; 440 Hz is assumed. Documentary support for a keyboard convention is not observation of this instrument. The [schema](../../../schemas/specimen.schema.json) explicitly disclaims authenticity, and populated strings alone cannot close `SPEC-001`.

**Concrete gap.** The [measurement plan](../../MEASUREMENT_PLAN.md) requires a frozen configuration revision and replaced/repaired-part history, but the specimen schema has neither structured field. Its evidence list accepts nonempty strings without resolving photographs, inspection records or hashes. Consequently, schema acceptance does not establish a reproducible physical passport. The schema also requires a serial for `identified`, although the plan allows unavailable markings: preserve the unknown and resolve an explicit alternative identity policy before acceptance; never insert a guessed serial or use “unknown” as apparent evidence.

**Numbering.** [SRC-019, manual chapter 6](https://www.fenderrhodes.com/service-manuals/1979/ch6.html) describes original 73-key tonebar markings 1–73 and subsequent 8–80 numbering. Therefore, the source-ledger summary cannot justify assuming every observed tonebar bears 8–80. Keep physical index `i=0..72`, the project's MIDI mapping `28+i`, normalized piano-key number `8+i`, and verbatim observed stamping as separate columns. Missing, mixed or replaced markings remain explicit discrepancies; stamps do not establish octave or specimen revision.

**Passport acceptance.** Before closing `SPEC-001`, require a stable specimen/configuration ID; dated, attributed inspection and marking photographs; per-key mapping and replacement/regulation observations with uncertainty; resolvable evidence identifiers, hashes and rights; and verified wiring tied to named output nodes, cable/probe loading and receiving resistance/capacitance. Preserve `loaded_harp` versus `stage_jack`; the former cannot establish completed Stage controls. Every configuration change must reference the preceding revision.

**Verification:** inspected the named repository files and primary manual; no code changes or tests. Next: define the missing passport representation and acquire actual specimen evidence.

## Implemented behavior

`reopen` now records a task-local `revalidation` object containing its actual
`reopen_revision` and a sorted `excluded_evidence` snapshot of **all** IDs then
registered, including records never attached to that task. The existing registry,
artifacts, and task evidence are preserved. Subsequent reopens replace the gate
with the latest revision and the entire current registry snapshot.

Completion requires a passing attached record outside that snapshot for every
required kind. Old records may remain attached, but neither reuse of old records
nor a new record of an unrelated kind satisfies the gate. The gate remains after
completion. Registration in the same UTC second works because membership in the
snapshot, rather than a timestamp inequality, establishes the distinction.

Pure `validate()` checks apply to directly loaded state too. Gates must have
exactly the two defined fields, a positive existing integer revision, and a
nonempty array of unique known evidence IDs. They must bind to the latest
`reopen` event for that particular task. Missing gates after recorded reopens,
gates without any reopen, references to other tasks' events, references to
non-reopen events, and references to earlier reopens are rejected. Empty snapshots
are invalid because an actual reopen requires an already-completed task with
registered evidence. Never-reopened tasks keep their existing contract.

The schema and docs describe the optional field, retained gate, repeated-reopen
behavior, and trust boundary. The additive version 1 field required no canonical
migration because the inspected repository had no reopened tasks.

snapshot. It does not establish that a command ran again, a report describes the
corrected source, or every acceptance criterion is satisfied. A repository editor
can rewrite declarations; the validator cannot reconstruct past registrations
from a rewritten snapshot. Re-registering old bytes under a new ID is not itself
new scientific evidence. Reviewers must still assess actual results and criterion

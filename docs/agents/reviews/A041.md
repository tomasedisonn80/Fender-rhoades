# A041 — Evidence trust and cross-validation

**Scope.** Independently reviewed [project validation](../../../tools/project.py),
[data validation](../../../tools/validate_data.py), their schemas/tests, and the
[state format](../STATE_FORMAT.md), [workflow](../WORKFLOW.md), and
[validation contract](../../VALIDATION.md).

**Enforced boundary.** Project validation checks allowed evidence kinds, passing
results, required-kind coverage, dependencies, local artifact existence/path safety,
and SHA-256 contents. Synthetic/numerical records cannot declare specimens.
Hardware evidence requires an independence declaration and a passing measurement
reference with the same specimen string. Acceptance satisfaction and relevance to
the task remain reviewer obligations; matching kinds do not establish either.
`source_commit` accepts null or a correctly shaped hexadecimal ID, without checking
object existence or association with tested source. Artifact hashing establishes
byte identity, not provenance or scientific meaning.

**Reproduced structural gap.** An isolated `python3` script copied canonical state,
source IDs, the profile/component inventory, and `data/examples/synthetic-session.json`
into `TemporaryDirectory`. It constructed two test-only passing records pointing
at that unchanged manifest and its computed hash: `measurement`, and
`hardware_validation` referencing the former with `independent=True`. Both used
`specimen_id="mark-i-stage-73-unidentified"`, `source_commit="0"*40`, null command,
valid timestamp, and explicit audit-only summaries/limitations.
`project.validate(temp_root, state, registry)` accepted both;
`validate_data.validate_repository(temp_root)` returned `(1, 1)`. Thus the two
validators accept contradictory registry/manifest classifications together.
No canonical evidence was registered or task completed.

**Interpretation.** Data validation rejects measured sessions without identified
profiles, calibration, acquisition metadata, and appropriate splits, but project
records contain no typed acquisition-manifest/profile reference. Data validation
intentionally does not open raw payloads. These are distinct checks. The workflow
and state trust disclaimers correctly reject authenticity guarantees; synthetic
exclusion should explicitly describe declared kinds, not imply content detection.
Fabricating plausible reports is the acknowledged trust boundary, not a defect
that another metadata field can eliminate.

**Scoped next action.** Introduce reviewed, versioned profile/session references for
measurement evidence, with acquisition versus identity-documentation roles;
cross-check declared kind, identified profile, specimen agreement, and held-out
split where applicable. Preserve human review of relevance, authenticity, and
independence. Clarify commit verification scope. Add one focused regression for
the contradictory fixture. This review changed only this report; inspection and
the isolated reproduction exited successfully. No broad suite or Git operations ran.

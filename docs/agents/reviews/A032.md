# A032 — Core callback safety audit

**Evidence.** Static inspection covered `include/rhodes/research_engine.hpp`, `src/research_engine.cpp`, and `docs/BENCHMARKING.md` using `rg`, `cat`, and `nl`. No build, timing run, allocation detector, lock detector, or platform-library audit was performed.

**Confirmed source properties.** The engine owns fixed arrays of 73 keys and three modes per key; `sample()` uses a fixed 73-double local array. Caller-owned `std::span` output and inline `std::optional` results introduce no heap storage. Inspection finds no allocation, locking, blocking wait, I/O, recursion, or explicit throw sites. Operations are `noexcept`; failures use `false`/`nullopt`. Processing failure zeros the failed sample and remainder, retains partially advanced state, and requires reset before resuming (header, `process` contract; implementation, `sample`/`process`). Work scales with caller buffer length; silent keys still traverse every mode.

**Hidden control cost.** Construction calls `prepare()`, which builds/copies the complete candidate key array, evaluates 73 `exp2` calls, and configures 219 transitions. Each transition evaluates square root, sine, cosine, and exponential. `note_on()` and `note_off()` recompute three transitions; sustain, all-notes-off, and reset recompute 219, including unchanged pedal assignments (`update_transition`, `update_damping`). These operations are bounded but materially different from sample propagation.

**Callback restrictions and next guard.** Integration should construct/prepare outside callbacks, bound output length and event count, and serialize access to each engine's unsynchronized state. Handle failure without callback logging. The API currently enforces neither block/event budgets nor thread ownership. BENCHMARKING's measurement boundary explicitly excludes note-on and setup, and disclaims allocation detection and worst-case guarantees. Add a callback-scoped allocation/deallocation trap covering processing, failure handling, and bounded note/pedal bursts. That would supply runtime evidence for allocator behavior, while leaving locking and deadline claims separately unproven.

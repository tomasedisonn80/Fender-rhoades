# A009 — Synthetic callback benchmark harness

**Assignment:** Implement a bounded, dependency-free C++20 benchmark for the
existing synthetic research kernel. Owned paths: `apps/benchmark.cpp`,
`docs/BENCHMARKING.md`, and this report. This worker read the required agent,
README, project-state, roadmap, and canonical-state documents and inspected the
engine's public interface and implementation. No CMake, core, test-suite,
canonical-state, or Git changes were made by A009.

## Delivered behavior

- CLI bounds: `--blocks 1..100000` (default 1000), block size `64|128|256|512`
  (default 128), integer sample rate `32000..192000` Hz (default 48000), and
  `--active-keys 0..73` (default 73). Optional nonempty UTF-8 `--machine` defaults
  to `unknown`. Malformed/unsupported values fail before allocation or warmup.
- Preallocated output/timing storage; 32 warmup blocks; deterministic reset
  before recording; `steady_clock` timestamps immediately around `process()`.
  Strikes, checksum consumption, sorting and JSON formatting are excluded from
  callback timings and explicitly identified as such.
- Active keys span the keyboard, receive synthetic intensity 0.7 impulses, and
  are held and retriggered approximately every half second of simulated audio.
  All 73 key slots remain in processing even with zero active keys. Every output
  sample contributes to an observable squared-sample checksum; active silence
  and nonfinite results are rejected.
- JSON reports compiler/version, build configuration when supplied, `NDEBUG`,
  language level, machine label, sample rate, block count/size, exact workload,
  mean/p50/p99/maximum callback durations, nominal block deadline, and observed
  deadline misses. Strings escape JSON syntax/control bytes and preserve valid
  UTF-8. Quantiles use nearest rank; a callback misses only when its elapsed time
  is strictly greater than its nominal block duration.
- Documentation specifies portability, reproducibility and measurement limits.
  No hardware-fidelity percentage, CPU-utilization percentage, production-host
  guarantee, worst-case bound, or completed `RT-001` claim is made.

**Integration contract:** Add executable target `rhodes_benchmark` from
`apps/benchmark.cpp`, link `rhodes_core`, and apply `rhodes_target_options`.
Optionally define `RHODES_BUILD_CONFIGURATION="$<CONFIG>"` on this target;
without that definition the JSON honestly reports `unspecified`. The integrator
was notified of this contract. CMake integration remains outside this worker's
assigned ownership.

## Observed verification

Local environment: Linux, `c++ (Debian 14.2.0-19) 14.2.0`. These were functional
smoke checks, not a controlled hardware-performance study.

Before implementation:

```sh
python3 tools/project.py validate
python3 tools/project.py sync --check
python3 tools/project.py next --json
```

All three exited 0. Validation reported 12 tasks, zero evidence records, and
`fidelity=unvalidated`; generated state was current. The current bounded
foundation assignment was retained without independently claiming or changing
another task.

Strict manual compilation:

```sh
c++ -std=c++20 -O2 -DNDEBUG -Wall -Wextra -Wpedantic -Wconversion -Wshadow -Werror \
  -I include apps/benchmark.cpp src/research_engine.cpp \
  -o /tmp/rhodes_benchmark_a009
```

Exited 0 with no compiler diagnostics. A Python subprocess harness then ran
these four successful configurations and parsed each stdout as strict JSON:

| Blocks | Block size | Rate (Hz) | Active keys | Observed checksum sum of squares |
|---|---|---|---|---|
| 3 | 64 | 32000 | 1 | 0.0030439654338346943 |
| 1 | 128 | 48000 | 0 | 0 |
| 2 | 256 | 48000 | 73 | 3.1672870559562547 |
| 3 | 512 | 192000 | 73 | 11.798307864047374 |

The harness asserted fixed slot count 73, finite checksums, positive output for
active runs, zero output for the baseline, ordered p50/p99/max, mean no greater
than max, and deadline-miss counts within the measured block count. The
one-block run had identical mean, p50, p99, and max as required. A supplied
machine string containing quotes, backslash, newline, tab, an accented character,
and an emoji survived a JSON roundtrip exactly.

The same harness observed status 2, empty stdout and a diagnostic for all 14
invalid-input cases: zero/excessive/negative/fractional block count, unsupported
block size, sample rates immediately outside both endpoints, `nan` sample rate,
excessive/negative active-key count, empty machine label, missing option value,
unknown option, and a malformed UTF-8 machine byte. `--help` exited 0 and
identified the synthetic scope. All harness assertions passed; it was run
directly as an inline Python check and did not modify the repository test suite.

## Limits and next action

Only local GCC compilation was performed by this worker. MSVC, Clang, macOS,
Windows, CMake target integration, full-length timing runs, host scheduling,
allocation instrumentation, and hardware characteristics were not verified by
A009. Tiny-run timing values are intentionally not promoted to a performance
baseline. The next action is to integrate/build `rhodes_benchmark` through CMake,
then use the documented workload under a recorded machine/build environment
when collecting actual runtime evidence. The broader `RT-001` numerical-error,
convergence and representative-host gates remain open.

# A091 — Asset and schema migration audit

**Scope:** Static inspection; this report is the sole changed path.

The [state contract](../STATE_FORMAT.md) and
[`validate_specimen_links`](../../../tools/project.py) bind explicit immutable
profile/session paths to hashes. Hardware coverage matches profile hash and
session ID/hash. Corrections require new paths and records. However,
`specimen_id == profile_id` is the current identity rule; no distinct configuration
revision or hash exists in version-1 session bindings.

**Concrete migration gate:** [Discovery](../../../tools/validate_data.py) scans
`profiles/*/specimen.json` and `profiles/*/components.json`, requires one inventory
per profile, and rejects duplicate profile IDs. Every `data/**/*.json` except
paths containing a `raw` component is parsed as a session. Archived same-ID
profiles in sibling directories therefore fail; deeper profiles are undiscovered.
Calibration JSON and duplicate session snapshots inside the session search tree
also fail. Explicit evidence paths do not redefine this discovery policy.

Before accepting acquisitions, implement the
[ingestion upgrade](../../specs/DATA_INGESTION.md) with distinct stable specimen
identity, immutable configuration revisions/hashes, and session bindings. Version
schemas, validators, discovery rules, migration guidance, fixtures and evidence
gates together. Preserve version-1 bytes and their evidence meaning; current
schemas reject extra fields and unsupported versions. Retain unknown values as
null, including missing serials; alternative identification requires reviewed
policy, not an invented serial. Calibration or partition-policy changes require
dependent asset/fit/report reassessment, new records and reopening affected
completed gates, preserving historical observations.

The [runtime contract](../../specs/RUNTIME_AND_ASSETS.md) correctly remains future
work: there is no asset loader or serializer. Validate payload bytes,
schema/model/ABI, configuration/load identity and coordinate normalization before
publication; failed replacement retains the active engine. Structural/rate changes
require deactivation and reset. Version configuration recall and dynamic
checkpoints independently; checkpoints additionally bind sample rate, model,
scheduler and all dynamic states. Do not treat project-state schema version 1
as runtime compatibility.

**Verification:** Read-only `cat`, `rg`, `sed` and JSON inspection; no build or
tests run.

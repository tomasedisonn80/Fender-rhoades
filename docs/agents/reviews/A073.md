# A073 — Regression and reopening review

**Scope and baseline.** Reviewed `AGENTS.md`, the required startup documents,
[`project.py`](../../../tools/project.py),
[`test_state_review.py`](../../../tests/python/test_state_review.py),
[`WORKFLOW.md`](../WORKFLOW.md), and canonical state revision 4: no completed
tasks; fidelity remains `unvalidated`. This report is the only owned change.

**Dependencies and fidelity.** `reopen` rejects direct completed dependents.
Because validation requires every completed task's prerequisites to be completed,
this forces transitive reopening in reverse dependency order. For a fully
completed downstream graph, reopening `VAL-001` requires reopening the
`ACO-001 → CIR-001 → STG-001` chain and the `KEY-001` branch first.
Reopening `KEY-001` under `measured_keyboard`, or `VAL-001` under
`measured_one_note`, demotes fidelity to `unvalidated`. Existing focused tests
cover these demotions and preservation of the registry and old evidence IDs;
they do not exercise the multilevel dependency sequence.

**Confirmed freshness gap.** Completion checks passing results, required kinds,
dependencies, and intact hashes, but does not require evidence newer than a
reopening. An isolated temporary fixture executed with
`PYTHONDONTWRITEBYTECODE=1 python3 -` followed
`claim → complete(old-pass) → reopen → claim → complete(old-pass)`.
The command exited 0, reached `done`, and left the evidence registry unchanged.
Thus the workflow's instruction to create corrected evidence is a reviewer
obligation, not an enforced freshness gate. Old observations should remain
immutable, but should not automatically justify corrected work.

**Blockers and next action.** Reopening sets `todo`, clears blockers, and records
the regression reason only in history. Dependency-ready failures can therefore
appear in `next`. The integrator should claim/block the reopened prerequisite
with its failed criterion and repair action, preserve historical evidence, then
register new results before recompleting prerequisites and dependents. Add
focused tests for stale-evidence rejection and multilevel reopening; no repository
state, implementation, Git operation, or broad test suite was changed or run.

# A004 — Data contracts and provenance validation

## Assignment and result

Implemented stricter specimen, acquisition, and mechanism-inventory metadata
validation in the assigned paths. This is metadata integrity work; it supplies
no instrument measurements or physical accuracy evidence.

Concrete gaps fixed:

- Component inventories are now validated and required for every profile. IDs,
  scalar units, source/task references, provenance, uncertainty, and same-specimen
  measurement references are checked. Unknown quantities retain nulls.
- Measured/fitted parameter values require an identified specimen, uncertainty,
  and actual measured-session references assigned to the fit split. Held-out
  validation/test sessions cannot silently become parameter-fitting sources.
- Acquisition calibration references must exist and match channel units. Synthetic
  manifests cannot claim physical acquisition calibration or validation splits.
- Condition identities and identical observation hashes cannot cross data splits
  or be relabeled between synthetic and measured provenance.
- Duplicate JSON keys, nonfinite literals, numeric overflow, boolean numerical
  fields, unsafe/noncanonical artifact paths, missing rights, and incomplete
  measured acquisition metadata are rejected.

Added Draft 2020-12 JSON Schemas for specimen, session, and component contracts.
Their comments explicitly identify cross-document rules enforced by the Python
validator. The component schema represents mechanism requirements, not a verified
component-level circuit BOM or netlist. Mixed-unit placeholders cannot carry a
numeric scalar value.

## Remaining boundary and next step

The validator checks declared metadata and cross-references. It deliberately
does not open raw observation artifacts, recompute their hashes, inspect waveform
calibration, or prove that a specimen or measurement is authentic. Source claims,
rights, identification quality, and statistical independence still require review.
Artifact entries are observation payloads; shared calibration documents belong
in calibration references rather than duplicated train/test payload entries.

Next data-development work should ingest authorized acquired data, verify payload
hashes/lengths against its manifest, and bind measured records to actual specimen
evidence before completing measurement-dependent tasks. No commits, pushes, or
canonical state mutations were performed by A004.

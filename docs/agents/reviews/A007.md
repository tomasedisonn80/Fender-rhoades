# A007 — State transitions and recovery audit

**Assignment:** Audit `tools/project.py` and `tests/python/test_project.py` for
leases, owner/token checks, reopen behavior, locking, durable evidence, and stale
generation. Owned changes: `tests/python/test_state_review.py` and this report.
Inspected the working-tree implementation and the required agent, project-state,
roadmap, workflow, and format documents. No Git commands, core-code edits, or
canonical-state mutations were performed by A007; all mutation fixtures used
temporary directories.

## Findings and resolution

1. **Mutable evidence could invalidate otherwise successful writes.** Before the
   fix, registering `project/evidence.json` returned exit 0, followed immediately
   by validation exit 2 because registration changed its own artifact hash.
   Registering `project/state.json` or `docs/PROJECT_STATE.md` returned 0; a
   subsequent successful claim changed the artifact and made validation fail.
   Proposed fix: reject tool-managed mutable artifacts by resolved path, including
   transient lock contents. The integrator implemented the guard in registration
   and validation. Regression assertions now pass for all three files, the lock
   owner file, and a symlink alias of canonical state.
2. **Unicode token input escaped normal error handling.** A release with the
   matching owner and token `é` raised uncaught `TypeError` from string
   `compare_digest`. The integrator changed comparison to UTF-8 bytes. The new
   test observes normal rejection, exit 2, and unchanged canonical bytes.

## Observed checks

- `python3 -m unittest discover -s tests/python -p test_project.py -v`:
  **22 tests passed**, exit 0, before the integrator fix.
- `python3 -m unittest discover -s tests/python -p test_state_review.py -v`:
  **13 tests passed**, exit 0, after the fix; no skips or expected failures.

Additional coverage verifies exact expiry boundaries, all four active-claim
mutation commands rejecting wrong owners/tokens without writes, same-owner
reclamation rejecting the old token, both fidelity gates reverting on reopen
while retaining evidence, refusal to steal an existing lock, failed atomic rename
cleanup, and recovery after a generated-document write failure. The recovery
test confirms committed JSON survives, stale `sync --check` fails, and
`validate`/`sync`/`sync --check` recover without changing the revision.

Exception injection does not establish power-loss durability or cross-platform

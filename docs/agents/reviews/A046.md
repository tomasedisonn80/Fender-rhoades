# A046 — Split and provenance review

**Assessment:** The foundation enforces declared metadata boundaries; independent
hardware holdouts need a richer grouping contract before `DATA-001`.

In the [validator](../../../tools/validate_data.py), `validate_splits()` rejects
duplicate session IDs, conflicting splits for the same
`(specimen_profile, condition_id)`, and matching artifact SHA-256 values assigned
different `(kind, split)` pairs. Hash reuse within one pair is permitted; repeated
references must therefore not be counted as independent observations. Synthetic
sessions are restricted to `development`. Measured/fitted component values require
uncertainty and references to measured, same-specimen sessions assigned `fit`.

The [data tests](../../../tests/python/test_data.py) exercise condition and
identical-hash leakage, a permitted distinct-condition/distinct-hash pair, and
component rejection of validation, synthetic, foreign-specimen, and
missing-uncertainty inputs. They do not demonstrate protection for shared
acquisition/phrase groups or derived-data ancestry.

**Contract gap:** The [measurement plan](../../MEASUREMENT_PLAN.md), sections 2
and 5, requires immutable raw-to-derived provenance and whole condition,
acquisition-session, or phrase separation. Session manifests contain one condition
ID and one globally unique session ID, but no shared acquisition/phrase grouping
or artifact-parent references. Cropped or resampled exports have different hashes;
their relationship to a held-out parent cannot currently be represented and
checked structurally.

**Recommendation:** Before ingestion, version the contract with a frozen campaign
partition policy, stable group membership, and raw/derived artifact ancestry.
Enforce one split per selected group and inherited partition restrictions through
derivations. Add focused regressions for different-hash descendants crossing
splits and multiple records belonging to one declared group. Define whether
shared calibration artifacts are partition-independent references.

Operators still supply identities, group membership, and hashes. Validation can
detect inconsistent declarations, not certify independence or truthful acquisition;
the current command explicitly does not open artifact files. Keep that boundary
visible.

**Verification:** Static inspection using `rg`, `cat`, `sed`, and `nl`; no tests or
scientific experiments executed. Changed only this report.

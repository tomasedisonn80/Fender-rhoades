# A001 — C++ physical-model research foundation

## Assignment and scope

Implemented a dependency-free C++20 research kernel, a deterministic offline WAV
renderer, CMake configuration, and behavior tests. This assignment used the supplied
`docs/research/USER_RESEARCH.txt` as its architecture brief. No third-party source
was copied. No commit, push, project-state update, hardware measurement, or fidelity
evaluation was performed by this agent.

## Deliverables

- `include/rhodes/research_engine.hpp`: documented units, numerical domain, persistent
  state APIs, synthetic scope and missing physical interactions.
- `src/research_engine.cpp`: exact discrete transitions for linear underdamped
  oscillators, explicit impulse excitation, polynomial flux-linkage conversion,
  an equal-resistance candidate harp network, and fixed 73-key state storage.
- `apps/render.cpp`: validated CLI and explicit little-endian IEEE-float WAV output
  with format and fact chunks. Existing output requires `--force`. Gain is explicit;
  there is no automatic normalization, clipping, or recorded-note playback.
- `CMakeLists.txt`, `CMakePresets.json`: C++20, warning checks, CTest, development,
  release and sanitizer configurations. Direct configuration needs CMake 3.20;
  the version-3 presets need CMake 3.21. Presets use Ninja.
- `tests/cpp/research_engine_test.cpp`, `tests/cpp/expect_cli_failure.cmake`: 12 core
  behavior cases and four CLI checks. Negative CLI checks require intentional exit
  code 2, rather than accepting any failing process.

## Behavior and numerical boundary

The oscillator advances the exact solution of
`q'' + 2*beta*q' + omega_0^2*q = 0` for a constant underdamped coefficient set.
`q` is displacement in metres, velocity is metres/second, mass is kilograms and
the impulse is newton-seconds. Configuration rejects invalid/nonfinite parameters
and frequencies at or above `0.45 * sample_rate`. The accepted sample-rate range
is 32–192 kHz. Rejected configuration and explicit state/impulse changes leave the
previous state unchanged. A processing arithmetic failure returns `false` and
zeros the remaining output buffer; already advanced states are not rolled back.

The engine uses 73 keys and three modes per key. Its assumed equal-temperament
mapping is MIDI 28–100; it is an implementation fixture, not specimen evidence.
Retriggers add impulse momentum while preserving displacement and prior velocity.
Release changes a viscous-loss coefficient without resetting state. Sustain chooses
the free-loss setting even after key release. These mechanisms are explicitly
surrogates for future finite-mass hammer and damper-contact models.

Local modal displacement and velocity are summed before evaluating
`e = -(a1 + 2*a2*x + 3*a3*x^2)*velocity`. Coefficients represent flux linkage, with
turn count already included. The network retains the resistances of all 73 pickup
branches when their motional source voltage is zero. Its candidate grouping is
four parallel branches followed by 23 groups of three, connected in series.

All parameter values are synthetic. The source identifies each constant; none is
described as a measurement. The engine has no allocations, locks, I/O or unbounded
iterations in core operations. This structural property is not a callback deadline
benchmark or a production real-time guarantee.

## Limitations and next work

This is a testable foundation, not a physically complete Rhodes. It lacks measured
modal parameters, finite-mass hammer contact, contact dampers, magnetic reaction,
shared harp motion, pickup inductance/capacitance, specimen-verified topology,
passive Stage controls, cable loading, nonlinear circuit solvers, antialias filtering,
plug-in hosting and specimen listening tests. The polynomial pickup can alias;
keeping mechanical frequencies below the numerical domain does not prove electrical
alias control. There is no historical component calibration or realism percentage.

The next substantive DSP milestone is a tightly converged single-note reference
with explicit hammer/contact mechanics and an identified electrical load, followed
by held-out comparisons to synchronized mechanical and electrical measurements.
Independent Windows/MSVC and macOS/Clang execution remains for CI or available hosts.

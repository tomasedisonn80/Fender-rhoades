# A079 — Independent test-quality audit

**Finding: PHY-001 acceptance 2 lacks an engine-output oracle for combined modal flux.** In [the primitive tests](../../../tests/cpp/research_engine_test.cpp), `pickup_intermodulation` discriminates joint from separate conversion, but calls only `PolynomialPickup`. [The engine](../../../src/research_engine.cpp), `ResearchEngine::sample`, currently combines weighted modal displacement and velocity correctly. However, its output tests compare two executions of the same implementation, or check silence, finiteness, and signal presence. Moving nonlinear conversion inside the modal loop could escape those checks. This is a specific acceptance-evidence gap, not an observed implementation defect.

The scalar references are sufficiently independent for the present linear propagator: `exact_solution` and [regression](../../../tests/cpp/review_regression.cpp) `modal_boundaries` calculate trajectories at elapsed time instead of reproducing the stored transition matrix. Boundary cases exercise low frequency, near-critical damping, near-cutoff frequency, and three rates. Wider arithmetic helps only where `long double` exceeds double precision; these are sampled numerical checks, not physical validation.

Energy decay/conservation and partition invariance are useful invariants. Energy checks reuse the production getter, so they do not independently certify energy normalization or the impulse cross term. Primitive rejection compares subsequent trajectories against an untouched clone, covering coefficients as well as state; engine rejection also checks rate and continuation under sustain. Direct engine retrigger/release assertions cover mode zero, leaving other modes implicit. The network's analytic one-sixth and one-eighth outputs discriminate inactive-branch loading; extreme-divider cases cover representable results across large exponents.

**Next action:** after a strike and short warmup, read all three modal states, independently calculate their weighted sums, polynomial derivative, and loaded network voltage, then compare the next engine sample. Require the separately converted prediction to differ materially. This closes the identified acceptance gap without broad test proliferation.

Inspection used `cat`/`rg`; no suite was run. [NUMERICS](../../NUMERICS.md) accurately labels synthetic parameters, omitted interactions, aliasing, and arithmetic limits. Changed only this report; canonical state remains untouched.

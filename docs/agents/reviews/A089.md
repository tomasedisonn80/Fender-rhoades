## Implemented behavior

Project paths reject C0/DEL control characters, including NUL, before attempting
resolution. A shared resolution boundary converts filesystem, invalid-path, and
symlink-loop errors into `StateError`; it covers supplied roots, repository paths,
and mutable/lock artifact boundaries. Lexical `.git` components are compared
case-insensitively. Resolved paths also exclude Git-named components and the
resolved root `.git` location, including when that directory itself is a symlink.
These checks precede artifact existence checks and byte reads. Ordinary in-root
symlinks to eligible evidence remain usable.

Both JSON loaders normalize invalid UTF-8, malformed JSON, and decoder recursion
failures into their existing CLI diagnostic conventions. Both reject overflowing
float literals through a finite `parse_float` hook. Campaign additionally rejects
duplicate keys at every object level and `NaN`, `Infinity`, and `-Infinity`, including
inside otherwise-permitted extension fields. Legitimate finite extension fields
retain the existing schema and registration behavior. Campaign report-resolution
errors are normalized too. Its CLI also catches encoder recursion failures before
publishing a ledger; decoder and encoder depth limits can differ across Python
versions. No arbitrary nesting limit or schema migration was introduced.

Project failures retain exit status **2** and campaign failures retain **1**.
Actual subprocess checks verify these statuses without tracebacks for invalid
UTF-8. The input-rejection tests snapshot all five existing temporary files
(state, evidence, state dashboard, campaign ledger, campaign index) and verify
byte-identical contents after failure, with the project lock removed. Git-alias
tests additionally guard byte-opening or hashing to ensure exclusion happens
before reading the invented target. No A075 revalidation logic was changed.

## Limits and integration handoff

These are pathname and metadata checks under the existing trusted, quiescent
checkout assumption. They do not supply descriptor-based protection against
hostile directory replacement between resolution and opening, identify hard-link
aliases, or inventory private files elsewhere in a checkout. Campaign report
ancestor directories retain their existing trust assumption. The tools still do
not execute recorded commands or attest that an observation occurred. An editor
able to rewrite metadata and matching hashes can change declarations; A075's
fresh-registration gate is not proof of a new experiment.

Byte preservation here applies to rejected inputs and the tested pre-publication
encoding failure. Existing separate-file publication/recovery semantics remain:
an I/O error after committing canonical JSON can leave a stale generated document
for a subsequent `sync` to repair. The affected existing recovery tests passed.

The integrator should review these four files, include the new regression module
in its final integration checks, and register this actual result through its
normal campaign/evidence process. This report does not complete a scientific task
or promote fidelity.

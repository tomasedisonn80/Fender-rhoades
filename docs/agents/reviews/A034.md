# A034 — Event timing and host contract

**Current evidence.** Static inspection (`cat`, `rg`, `sed`) covered the [header](../../../include/rhodes/research_engine.hpp), [core](../../../src/research_engine.cpp), [NUMERICS](../../NUMERICS.md), and [architecture](../../ARCHITECTURE.md). Controls act at call boundaries; there is no timestamped event list. Each successful sample observes time `n`, then advances to `n+1`; a strike applied before sample `n` affects that sample. Release changes subsequent damping without resetting motion. The [renderer](../../../apps/render.cpp) rounds its release time to an integer frame and shortens its 256-frame chunks to stop exactly there, applying release before the next sample. Existing [partition tests](../../../tests/cpp/research_engine_test.cpp) cover strikes and release across differently sized calls, not general event scheduling.

**Proposed host contract.** Accept caller-owned output and bounded, prevalidated events with integer offsets `0 <= offset < N`, ordered by `(offset, sequence)`. Preserve producer sequence for equal timestamps, including note-off/note-on; never reorder by event type. Apply all events at an offset before observing that sample. An event at `N` belongs to the next block; an empty block accepts no events and advances nothing. The adapter owns an overflow-checked absolute frame cursor and carries future events forward. Reject late events, invalid offsets/order, or capacity overflow before mutation, return explicit status, and zero rejected output; never silently truncate releases. Distinguish these input failures from the existing partial-state arithmetic-failure contract. Bound block/event counts and allocate/sort outside callbacks.

**Independent fixture.** Render 130 frames at 48 kHz: key 17 on(0.8) at 0; off then on(0.4) at 63; pedal-down then off at 64; pedal-up at 128. Build expected samples using independent scalar closed-form modal trajectories, impulse jumps, and pickup/network equations. Compare tolerances plus final states; require identical output across valid partitions `[130]`, `[64,64,2]`, and single frames. Reverse the frame-63 tie to expose damping-order dependence. This fixture is proposed, not executed; implement it alongside the future adapter. No code, state, Git, or broad tests changed/run.

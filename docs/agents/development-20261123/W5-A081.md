# W5-A081 — Actual processor state-callback concurrency

2026-11-23. Bounded HOST-001 verification. Added only
`tests/cpp/vst3_state_concurrency_test.cpp` and this report; the integrator owns
CMake wiring. Canonical validation, generated-state check and work-selection
inspection passed before implementation. Production was unchanged.

## Retained behavior

`state_preflight_race` gates an actual host event getter while another thread
replaces a pending recall. Eight scenarios cover float/double, identical/newer
requests and successful/rejected transactions. A 256-note-plus-pedal dispatch
overflow rejects **after** mailbox consumption; its pending recall must survive
and reset mechanics on the next valid flush. Accepted output matches a separately
prepared processor, old ownership disappears, and subsequent processing proves
recall is consumed once. Full modal states are compared.

`state_callback_stress` runs one audio owner alongside a UI state writer/saver
and independent saver. Every thread owns its streams. Independently constructed
sixteen-byte packets recognize complete permitted gain/pedal pairs, avoiding the
production codec as the coherence oracle. Fragment sizes span 1–16 bytes;
unsupported-version recalls and post-consume dispatch rejection are interspersed
with automation. Final barriers establish an unambiguous last UI write, reset
and subsequent normal advancement. Lifecycle calls remain outside processing.

## Actual verification

GCC 14.2, Linux x86_64. The strict `-O3 -DNDEBUG -DRELEASE=1` build linked the
existing pinned SDK/core archives. `timeout 30s
build/a081/vst3_state_concurrency all` exited **0**:

| Selector | Process calls | Explicit checks |
| --- | ---: | ---: |
| `state_preflight_race` | 32 | 100, plus full mechanics checks |
| `state_callback_stress` | 2,052 | 188,428 |

Stress executes **49,156 threaded state callbacks**, at 48 kHz/float32 and
192 kHz/float64, with 64-frame processing. Checks remain active under NDEBUG.

The ThreadSanitizer build compiled the test, `processor.cpp`, `state_stream.cpp`
and `research_engine.cpp` using `-std=c++20 -O1 -g -DNDEBUG -DRELEASE=1
-Wall -Wextra -Wpedantic -Wconversion -Wshadow -Werror -fsanitize=thread
-fno-omit-frame-pointer -pthread`, project/SDK include paths and the pinned SDK
archives. Both selectors ran with `TSAN_OPTIONS=halt_on_error=1` and a 30-second
subprocess timeout: exits **0**, empty stderr, respectively **0.066 s** and
**3.332 s**. Results are retained in `build/a081/tsan-results.json`.

A scratch negative control removing the processor's sole
`mailbox_.abort_block(token)` call exited **1**: “restored recall did not reset
mechanical/ownership state.” Owned whitespace verification passed.

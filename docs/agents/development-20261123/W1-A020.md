# W1-A020 — Wave 2 integration design gate

2026-11-23. Bounded documentary review; no implementation acceptance claimed.

**Decision:** proceed with separate contact-reference and synthetic VST3 work,
subject to the integration decisions below. The frozen contact specification
preserves every required A005 fixture, independent-method agreement, refinement,
grazing and work-accounting gate. The host specification correctly keeps the
offline solver outside audio processing and leaves fidelity `unvalidated`.

## Actionable findings

1. **Resolve the translated-event cap explicitly.**
   [A010](W1-A010.md) caps translated events at 256 per block;
   [HOST_PROTOTYPE](../../specs/HOST_PROTOTYPE_20261123.md) permits dense pedal
   points with 256 physical events per sample. The existing
   `include/rhodes/event_processor.hpp` accepts only 256 events per invocation.
   Make the host contract's grouping override explicit: preflight the complete
   host block, then dispatch bounded per-sample groups with local offsets and
   strictly increasing sequences. Never reject otherwise valid dense automation
   merely because its whole-block translated count exceeds 256. Test a late
   invalid point leaves all earlier mechanics and ownership unchanged.

2. **Freeze recall versus rejection ordering.**
   [A011](W1-A011.md) consumes/reset-applies recall at the block boundary, while
   the host contract requires invalid input to preserve mechanics. Applying
   recall before ownership preflight violates that rule. Preflight against a
   provisional state corresponding to the loaded mailbox token before its
   single CAS; define a bounded failed-CAS path that revalidates against current
   live ownership or rejects without mutation. Do not reuse validation against
   a reset holder table when recall was not consumed. Add an interleaving test
   combining holder-capacity pressure, pending recall and malformed input.

3. **Specify automation edge semantics before the harness.**
   “Ordering” does not decide whether duplicate queue offsets are accepted;
   interpolation does not identify the previous-value anchor (`-1` versus `0`).
   Zero-frame parameter flushes also need an explicit allowed offset rule.
   Freeze these choices and binary32 gain quantization timing, then test offset
   zero, duplicate points, empty queues and block partitions independently.

4. **Resolve the stale-identity promise.**
   A011 says no stale release may affect newly owned notes; the host contract
   correctly acknowledges identical identity reuse cannot be distinguished.
   Mark the latter as the governing limitation. Test unknown stale identities
   as harmless, without claiming impossible same-identity protection.

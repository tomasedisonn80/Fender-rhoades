## Chosen policy

1. **Physical keys and validation.** One input bus, channels 0–15, MIDI pitches
   28–100 map to 73 permanent keys. Valid outside-range pitches are ignored.
   Invalid channel, pitch, velocity, offset, or ordering rejects the block.
   Velocity must be finite and in [0,1]. Normalize zero-velocity note-on to
   note-off, matching this prototype's existing core convention.

2. **Identified holders.** Maintain a fixed table of at most 256 active input
   holders, independent of the 73 mechanical states. An identified holder is
   `(channel,noteId)` plus its physical key. Every positive note-on strikes the
   existing key, preserving displacement and prior velocity before adding its
   impulse. Repeating the same identity/key retriggers but adds no holder.
   Reusing an active identity for a different playable key rejects the block.
   Distinct identities, including different channels, may hold the same key.
   An identified note-off removes its exact holder; a conflicting stored pitch
   rejects the block. An unknown identity is a harmless no-op.

3. **Anonymous holders.** Exactly `noteId == -1` selects anonymous handling.
   Each positive on adds one holder for `(channel,key)`; each anonymous off
   removes one anonymous holder for that pair, or does nothing if absent.
   Never consume an identified holder as fallback. Hosts must consistently
   supply IDs for a note's lifetime; mixed availability requires explicit
   compatibility work. Repeated anonymous ons therefore require matching offs.

4. **Release invariant.** Emit a physical note-off only when removal changes a
   key's total holders from positive to zero. Pedal-held resonances occupy no
   holder slots. No ordinary release or retrigger resets mechanical state.

5. **Common pedal.** CC64 controls one instrument-wide pedal: the last ordered
   message from any channel wins; values 64–127 mean down. Do not OR independent
   channel latches. Pedal lift damps released keys while held keys remain free.
   Merge host parameter and note streams deterministically; document the tie
   rule where the host supplies no common sequence.

6. **Release versus panic.** CC123 clears only its channel's holders, emitting
   releases only for newly unowned keys; sustain remains unchanged. Global
   all-notes-off clears all holders and respects sustain. Explicit panic/CC120
   resets the whole shared instrument: ownership, pedal and mechanical state.
   This intentionally permits an audible discontinuity. Reset recovery must
   work even when the processor already requires reset.

7. **Atomic bounds.** Cap input and translated events separately at 256.
   Preflight the complete block against a fixed-storage ownership copy,
   including expanded releases and every intermediate holder count. Overflow
   or invalid input zeros output and leaves live ownership, pedal, mechanics
   and frame cursor unchanged; never truncate or steal holders. Commit only
   an accepted transaction. Arithmetic faults instead enter reset-required
   recovery. Processing performs no allocation, locking or callback logging.

non-sentinel IDs; identity/pitch conflict; zero velocity; range edges; pedal
release with held and released keys; channel/global all-notes-off; panic followed

# W3-A057 — Contact auditor input boundaries

## Scope and result

Audited candidate handling in `tools/validate_contact_reference.py`; added
`tests/python/test_contact_auditor_inputs.py`. No implementation, acceptance
budget, canonical-state, CMake or Git changes. These are input-validation
observations, not physical-model acceptance.

The 13 retained standard-library tests pass both normally and under `python3 -O`.
They exercise non-finite compared scalars, time domain/order, unknown fixtures,
event classification/order/count, bracket containment/width, timing errors,
non-finite/excessive energy diagnostics, negative accumulated losses, explicit
candidate failure with samples, incomplete coverage and structured CLI errors.
A fixed analytic endpoint oracle replaces only the optional numerical backend;
production parsing and audit checks remain active. Tests prohibit numerical
backend access and leave missing extrema explicitly incomplete.

## Confirmed gaps

Separate probes used the actual NumPy/SciPy-backed analytic oracle, without
mocking, for a conservative-impact trajectory:

- NaN acceleration or modal-acceleration vectors of length 0/1/3 produce
  `incomplete` with zero run failures.
- Negative maximum-step/local tolerances and negative absolute/summed energy
  diagnostics are not identified as invalid. NaN/Inf tolerance metadata also
  bypasses per-run validation.
- `success=false` with empty samples discards the explicit failure.
- Short position/velocity vectors raise uncaught `IndexError`. NaN maximum-step
  metadata reaches JSON serialization and raises uncaught `ValueError`.

Eight real CLI invocations confirmed representative cases: valid baseline and
five malformed cases exit 2; the two uncaught exceptions exit 1 with tracebacks.
No malformed case achieved overall acceptance: missing extrema/refinements
still prevent a pass. Nevertheless, these gaps must be fixed before the auditor
can reliably classify arbitrary candidate evidence.

Reproduction: `python3 build/a057/probe.py`; then
`python3 tools/validate_contact_reference.py --candidate build/a057/failure_empty.json`.
The scratch directory retains all inputs, CLI stdout/stderr, results and hashes.
Next: validate finite positive controls, exact vector dimensions, finite
accelerations, nonnegative magnitude diagnostics and status before numerical
work; preserve explicit failures and report malformed input as structured failure.

# A070 — Validate relaunch evidence and legacy controls

## Repair

Legacy scalar components now require actual finite JSON numbers before conversion;
booleans, numeric strings and overflowing integers reject consistently with canonical
vectors. CSV numeric conversion remains supported. Nonzero run failure codes fail
even with a true or absent success flag, before optional numerical-backend work.

Backend-free `validate_action_evidence()` follows structural preflight. It checks
snapshot cardinality, status, frozen action time/velocity, exact velocity assignment,
unchanged positions/modal velocities/unrelated ledgers, and agreement between kinetic
work, declared work, launch-ledger change and energy change. Missing snapshot lists
or metadata remain explicit incompleteness; explicitly wrong counts, contradictory
statuses, malformed states or inconsistent actions fail.

The independent analytic and Radau oracles retain copies of the exact states they
already compute immediately before/after each action, including time zero. Snapshot
states and action work are checked against those independent states. Thus mutually
consistent fabricated candidate fields cannot substitute for the reference.
The existing event-work budget remains `1e-12 + 1e-10 * abs(work)` J; trajectory
budgets, solver equations and refinement criteria are unchanged.

With integrator authorization, corrected one existing test's intended valid empty
baseline to reset its stale `failure_code=5` to zero. Separate new tests reject that
contradiction. No solver, CMake, canonical-state or Git edits.

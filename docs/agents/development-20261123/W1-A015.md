# W1-A015 — Release-safe event-processor regression tests

**Date:** 2026-11-23  
**Scope:** HOST-001 bounded worker assignment; integration and canonical state remain with the root agent.

## Changes

Added `tests/cpp/event_processor_test.cpp`, promoting the independent
`build/w1a009/review.cpp` audit into seven named fixtures with exception-based
checks that remain active under `NDEBUG`. No production, CMake, state, or Git
changes were made by this worker.

- `scalar_partitions`: independent direct-call 130-frame reference versus
  130-, 64-, and one-frame partitions, exact output, all modal states, and cursor.
- `equal_offset_order`: reversed tie versus its independent scalar reference;
  producer sequence may restart at a later offset.
- `preflight_atomicity`: invalid final event rejects the entire block before
  preceding strike, sustain, or reset events mutate state; continuation agrees.
- `invalid_events`: 18 invalid key/value/type/offset cases and three invalid
  ordering cases, with complete silence and state preservation.
- `block_limits`: empty blocks; rejection of events in empty blocks, 257 events,
  and 4097 frames; successful execution of all 256 events and 4096 frames;
  output-span sentinel preservation.
- `sample_fault_reset`: injected failure at sample 17 preserves the prefix,
  silences the suffix, fences later processing, rejects queued reset recovery,
  preserves the latch after invalid prepare, and recovers through explicit
  reset or valid prepare. A later-block failure checks relative coordinates.
- `event_fault_reset`: injected `note_on` failure identifies the event and sample,
  preserves earlier work, stops subsequent events, fences processing, and recovers.

Every process result checks status, success flag, processed frames, both failure
indices, reset requirement, and the new `ProcessResult.subsystem` field.

## Actual validation

Local Linux compiler: `g++-14 (Debian 14.2.0-19) 14.2.0`.

```sh
python3 tools/project.py validate
python3 tools/project.py sync --check
python3 tools/project.py next --json
mkdir -p build/w1a015
g++-14 -std=c++20 -O2 -DNDEBUG -Wall -Wextra -Wpedantic -Wconversion -Wshadow -Werror -Iinclude tests/cpp/event_processor_test.cpp src/research_engine.cpp -o build/w1a015/event_processor_test
build/w1a015/event_processor_test all
build/w1a015/event_processor_test event_fault_reset
build/w1a015/event_processor_test unknown_fixture
```

State validation reported 14 valid tasks and two evidence records; generated
state was current. Compilation succeeded without warnings. The `all` run printed:

```text
PASS scalar_partitions
PASS equal_offset_order
PASS preflight_atomicity
PASS invalid_events
PASS block_limits
PASS sample_fault_reset
PASS event_fault_reset
```

Individual selection printed only `PASS event_fault_reset`. Unknown selection
returned exit 1 with `FAIL unknown_fixture: unknown event-processor fixture`,
confirming active failure checks in the Release-style executable.

## Limits and handoff

Root must register the seven names in CMake/CTest. CTest, sanitizer and other
platform runs were not performed here. Fault injection validates dispatch and
recovery semantics, not physical fidelity or real-time performance. Public-API
tests do not exhaust the 64-bit frame cursor. This work adds no measured data.

# A071 — SDK configuration gates and isolation

## Scope and method

Tested a frozen source snapshot with Linux x86-64, GCC 14.2 and CMake 4.4.5.
`BUILD_TESTING=OFF` excludes test targets. No module rebuild or network download.

Created disposable checkouts using `git clone --shared --quiet SOURCE DEST`
for the SDK root and each of `base`, `cmake`, `pluginterfaces`, and `public.sdk`.
Worktrees, indexes and refs are independent; local alternates supply objects.
All five revisions matched documented pins.

Fresh configurations:

```sh
cmake -S build/a071/source -B build/a071/configure-CASE \
  -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF \
  -DRHODES_BUILD_VST3=ON -DRHODES_VST3_SDK_ROOT=FIXTURE
```

The SDK-off case substituted `OFF` and a nonexistent SDK path. The snapshot
contains current CMake files, headers, sources, apps and plug-in files.
Procedure and results:
`build/a071/run.py` and `build/a071/manifest.json`.

## Observations

All **10/10 expected outcomes** occurred:

| Fixture | Exit | Observed result |
|---|---:|---|
| SDK off, nonexistent path | 0 | Configured without SDK |
| SDK on, nonexistent path | 1 | Complete pinned checkout required |
| SDK on, empty directory | 1 | Complete pinned checkout required |
| Rename disposable `base/.git` | 1 | Missing Git checkout identified |
| Root revision changed, same tree | 1 | Root revision mismatch identified |
| `public.sdk` revision changed, same tree | 1 | Submodule revision mismatch identified |
| Unstaged root README edit | 1 | Dirty root rejected |
| Unstaged pluginterfaces header edit | 1 | Dirty submodule rejected |
| Staged public.sdk source edit | 1 | Staged submodule edit rejected |
| Clean pins plus untracked build artifact | 0 | Configured successfully |

Wrong revisions came from disposable `git commit-tree`/`update-ref` operations.
Dirty fixtures appended a comment; the staged case used `git add`. Mutations
were reversed in disposable clones. `git status` confirmed the permitted marker
untracked; `git check-ignore` returned 1.

Every rejected case emitted its expected targeted diagnostic before creating the
`vst3-sdk` build directory. The original SDK's **1,005 tracked files**, five HEADs
and clean tracked status matched before/after records exactly.
No defect found.

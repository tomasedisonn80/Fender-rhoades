# W2-A026 — Full-call event runtime benchmark

Implemented `apps/runtime_benchmark.cpp`, a separate bounded-event benchmark.
The existing process-only executable and its schema remain unchanged. Root owns
build integration and evidence registration; this worker changed no shared state.

## Measurement and workloads

Each timestamp pair encloses exactly one `EventProcessor::process` call, including
whole-block validation, event dispatch, sustain updates and sample rendering.
Output/timing storage is allocated before execution. Schedule construction,
hashing, output inspection, block-end modal inspection, sorting and JSON occur
outside timestamps. No independently computed quantiles are subtracted.

Seven deterministic schedules cover silence, periodic held chords, 256-event
off/on storms, 256-event pedal storms and held/sustained/released tails. Storms
support identical offsets or distributed offsets. Tail/pedal initial conditions
use one excluded, explicitly counted one-frame event call after reset. Warmup
replays the selected schedule; measurement resets and reinstalls identical
initial conditions. Keys are evenly distributed across the fixed 73 slots.

Strict argument limits are 1–1,000,000 blocks, 1–4,096 frames, 32–192 kHz,
0–73 selected keys and 0–10,000 warmup blocks. Retrigger storms require a key.
Machine labels are bounded printable ASCII; malformed/unknown arguments fail.

Schema 2 retains every raw timing, nearest-rank p50/p95/p99, mean, maximum,
strict deadline exceedances, four chronological timing windows, actual status
counts, finite-output/checksum results, event totals, schedule fingerprint and
observed subnormal values. Source/build metadata have optional compile definitions;
unknown metadata are explicitly unrecorded. The fingerprint is noncryptographic.

## Actual checks

From the repository root, strict Release compilation passed:

```sh
g++ -std=c++20 -O3 -DNDEBUG -Wall -Wextra -Wpedantic -Wconversion \
  -Wshadow -Werror -I include apps/runtime_benchmark.cpp \
  src/research_engine.cpp -o /tmp/rhodes_runtime_benchmark_a026
```

A temporary Python subprocess audit passed 35 checks: all seven schedules with
both offset policies; 1- and 4,096-frame boundaries; 18 malformed/range cases;
and identical output checksums/schedule fingerprints after different warmup
lengths. Python independently recomputed quantiles, means, maxima and deadline
counts from raw JSON, and checked 256-event storm totals and zero silence output.
These were short smoke executions, not a performance acceptance campaign.

One five-block 48 kHz/128-frame released-tail smoke observation had p50 91.536 µs,
maximum 91.572 µs and zero deadline misses against 2,666.667 µs. Shared Linux
container scheduling was uncontrolled; those values establish no deadline bound.

## Integration and remaining limits

Add target `rhodes_runtime_benchmark`, link `rhodes_core`, apply project warnings,
and define `RHODES_BUILD_CONFIGURATION` as for the existing benchmark. Retained
CLI regression coverage can reproduce the temporary audit.

This executable does not time MIDI ownership, state recall, VST3 or a device.
It does not intercept allocations, prove lock freedom, inspect FTZ controls,
certify worst-case execution, or complete the RT-001 numerical/antialiasing gate.
Subnormal modal observations are only at block ends. Full reproducibility needs
an accompanying source/build/hardware record and representative repeated runs.

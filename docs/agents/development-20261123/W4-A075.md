# A075 — Optional numerical dependency isolation

## Observed behavior

On Linux x86-64, Python 3.12.14, a `python3 -S` probe confirmed that
`site` was unloaded and both `find_spec("numpy")` and `find_spec("scipy")`
returned `None`. No packages were installed or source changed.

Fifteen auditor invocations produced these outcomes:

| Case | Observed result |
|---|---|
| `--help`; `--list-fixtures` | Exit 0; documented options and all 26 fixtures |
| Valid empty trajectory | Structured `incomplete`, exit 2 |
| Seven malformed/explicit-failure inputs | Structured `fail`, exit 1, before backend access |
| Shape-valid analytic and Radau initial samples | Structured dependency failure, exit 1 |
| `--self-check`, ordinary and `--output` modes | Structured dependency failure, exit 1 |
| Analytic candidate with `--output` | Matching file/stdout failure status, exit 1 |

Malformed cases cover unknown fixture, NaN acceleration, overflowing/boolean legacy
components, contradictory failure status, empty required action evidence and explicit
failure without samples. No audited failure emitted a traceback or a false pass.
The diagnostic names NumPy and SciPy and states that reference CTests do not require
them. Production analytic oracles also use the shared numerical loader; their
mathematical closed form does not make this implementation package-independent.

## Retained checks

`ordered_races` uses real threads and barriers for five controlled orderings:
different and identical UI recalls arriving after audio consumption but before
publication; the same two cases before abort; and abort restoration without a
newer write. Every pending recall survives and is consumed exactly once.

`concurrent_stress` performs 100,000 UI writes, 100,000 single-attempt audio block
operations and 100,000 independent observer snapshots. Alternating publications
use distinct gain/pedal pairs, so a mixed snapshot fails. The audio owner mixes
publication with abort. A final barrier-controlled UI write arrives after the
last audio token: stale publication must fail, the recall must remain coherent,
and subsequent consumption must occur exactly once.

Checks remain active under `NDEBUG`. Barriers are test coordination, not callback
implementation. No mailbox operation has a retry loop. Thread-owned result
records are inspected only after joining.

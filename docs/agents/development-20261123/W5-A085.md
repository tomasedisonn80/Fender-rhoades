## Source review and remaining native gates

The state/control headers explicitly require IEEE binary32/binary64, eight-bit
bytes and always-lock-free 64-bit atomics; unsupported representations fail
compilation. Both concurrency targets link `Threads::Threads`; barriers belong
to test hosts, and threads are joined before observations. Test aligned allocation
pairs `_aligned_malloc/_aligned_free` on MSVC and size-rounded `aligned_alloc/free`
elsewhere. SDK macros export the factory and platform entry points despite hidden
project visibility. MSVC project code requests `/fp:precise`; the documented
macOS Makefiles path avoids the SDK's Xcode fast-math branch.

[Apple's support table](https://developer.apple.com/xcode/cpp/) places synchronization
library deployment at macOS 11, matching CI. However, [Xcode 26 release notes](https://developer.apple.com/documentation/Xcode-Release-Notes/xcode-26-release-notes)
identify nonexperimental `jthread` support: the guides' generic C++20 requirement
is insufficient for older bundled Apple libraries. Root was notified to document
`barrier`/`jthread` availability and Xcode 26+ for these test builds, or deliberately
use explicitly joined `std::thread` tests for older toolchains. No native failure
was invented; no AppleClang/MSVC/AArch64 compiler was available.

# W2-A021 — Separate offline contact reference implementation

**Date:** 2026-11-23. **Scope:** implementation under the integrator's PHY-002
lease. **Status:** implemented and locally compiled; **full acceptance incomplete**.
No specimen measurements, fidelity promotion, canonical-state changes, Git

## Delivered API and mechanics

Changed only `include/rhodes/contact_reference.hpp`,
`src/contact_reference.cpp`, and this report. The namespace is `rhodes::contact`.
`Reference::initialize`, `advance`, `relaunch_hammer`, and `set_damper_motion`
return typed `Result` objects. Immutable getters expose configuration, mechanics,
observation, integrated ledger, event brackets, interval residuals, and diagnostics.
`observe`, `sample_face`, and `fixed_damper_equilibrium` are guarded pure helpers.

The offline model has a finite-mass hammer, two diagonal modal degrees of freedom,
and one prescribed compliant damper. Zero frequency and zero decay support free
mass fixtures. All coordinates remain the unshifted SI coordinates in A005;
assembled fixed-damper equilibrium uses the closed-form p=1 compliance solution.
No shifted-energy preload term is silently omitted. The exact selected law is
`F=max(0,delta*(k+c*delta_dot))` for positive compression and zero force otherwise.
Exponent values other than exactly one are rejected.

The integrated trajectory has separate hammer/damper active and clipped losses,
background viscous loss, signed damper actuator work `-F_d*ell_dot`, and both
contact impulses. Clipped loss is `-k*delta*delta_dot`; stored contact potential
remains present during clipping. Endpoint energy is computed independently of
these integrals. The ledger records cumulative residual, its maximum magnitude,
and the sum of absolute interval residuals with compensated accumulation.
Instantaneous acceleration, force, storage, loss, actuator power, and analytic
power residual are available for independent checks.

Relaunch changes only hammer velocity, with signed exact kinetic work
`0.5*m_h*(v_new-v_old)*(v_new+v_old)`. Modal positions/velocities and hammer
position persist. A damper trajectory change must preserve its current face
position exactly; a finite velocity breakpoint is permitted and recorded.
Constant, linear, and sinusoidal trajectories produce position and velocity
analytically from one definition. An instantaneous displacement change is rejected.
There is no surrogate key-release reset; continuous prescribed damper motion is
how the reference represents release-related contact travel.

## Integration, events, and finite domain

Adaptive classical RK4 compares one full step with two half steps using the
`(fine-coarse)/15` error estimate. It accepts the two-half-step state without
Richardson extrapolation. Mechanical errors are mass weighted using a fixed
reference mass, preserving the declared diagonal coordinate rescaling.
Integrated quantities have separate positive absolute scales. Local tolerance is
an integration control, not a convergence certification or an energy-loss source.

Each accepted candidate is checked at endpoints, quarter points, and midpoint.
Geometric and raw-force-factor transitions are separate. Relative-velocity and
raw-factor derivative sign changes trigger interior-extremum replay and bisection;
an interior crossing can produce two events despite equal endpoint gap signs.
Roots are replayed from the accepted starting mechanics. A known-frequency cap
`h <= pi/(4*omega_max)` prevents a fast prescribed sinusoid from aliasing entirely
between zero-force RK stages. Ordinary root brackets satisfy both the requested
time width and the gap-resolution setting. These are numerical-trajectory
brackets, not a proof of the global error against the exact continuous solution.

At an external action, an impending natural event within the event-time resolution
can be ordered first only when extending its bracket to the action time also
meets the configured gap bound. Such a row explicitly has `action_time_tie=true`,
retains its actual bracket and gap uncertainty, and reports the external time
inside that bracket. No mechanical coordinate is projected onto the surface.
If the expanded uncertainty exceeds the gap bound, the action fails atomically
with `numerical_failure/unresolved_event`.

Concrete default public bounds follow A018: masses `[1e-6,1] kg`; frequency
`[0,20000] Hz`; beta `[0,1e5]/s`; stiffness/damping `[0,1e8]` in the header's
units; projections `[-100,100]`; position/clearance/face `[-1,1] m`; velocity
`[-1000,1000] m/s`; stored time `[0,1000] s`; increments `[1e-12,1] s`; finite
arithmetic and accumulators at most `1e24` in magnitude. The sinusoidal face
additionally has `omega <= 40000*pi rad/s`, `|phase| <= 1e6 rad`, and a globally
certified position/velocity envelope. Linear faces are checked over the whole
requested interval using both endpoints. All trajectory fields are guarded,
including unused fields.

Defaults retain `h_max=20e-6 s`, event width `1e-8 s`, and gap resolution
`5e-13 m`. The four frozen maximum steps and three event refinements remain
available without changing any A005 acceptance budget. Minimum progress is
`max(1e-14 s,4*ulp(t))`, with every RK stage separately required to advance in
representable time. Per-call limits are 100000 trials, 1200000 RHS evaluations,
64 consecutive rejections, 64 bisections per root, and depth 32. Persistent event
and optional interval history each have a 100000-row bound. Tests may reduce
caps to exercise exhaustion; the implementation cannot raise these hard maxima.

Every mutating call stages a complete copy including compensations, controller,
mechanics, configuration, events, and diagnostics. Success commits the entire
requested interval. Failure leaves the entire original object unchanged and
returns attempted-work counters separately. Allocation/history exhaustion is
also typed. This intentionally allocates and is not an audio-callback component.

## Checks actually run

Required context and A005/A007/A008/A018 plus the frozen acceptance and solver
contracts were read. `python3 tools/project.py validate`, `sync --check`, and
`next --json` passed before implementation: 14 tasks, two evidence records,
fidelity unvalidated, and no independently available task to claim.

Strict direct compilation passed:

```sh
c++ -std=c++20 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -Werror \
  -Iinclude -c src/contact_reference.cpp -o /tmp/contact_reference_a021.o
```

Standalone temporary probes compiled with the same warnings and `-O2` exercised
A005 dynamics using default settings. Observed examples:

| Probe | Actual observation |
|---|---|
| Conservative free impact to 0.002 s | Hammer velocity `0.6000000001009 m/s`; impulse `0.00319999999919 N s`; cumulative residual about `-8.1e-13 J` |
| Damped free impact | Hammer velocity `0.7178560627911 m/s`; loss `0.00066504747719 J` |
| Forced clamp | Exactly zero impulse; loss `0.00010000000000000003 J`; unchanged velocities |
| Supported impact to 0.020 s | Six natural contact transitions, successful full interval; residual about `-2.3e-11 J` |

| Moving sinusoidal damper | Eight transitions; signed work `8.7834114e-6 J`; residual about `2.2e-14 J` |
| Grazing miss, local 60 us interval | No events and exactly zero impulse |

| Tangent | Typed unresolved-grazing failure; entry mechanics/ledger/events retained |

These are probes, not independent convergence certificates. They are not claimed
as canonical frozen acceptance results.

The independently authored A022 C++ fixture suite was then compiled directly
against this source and actually run:

```sh
c++ -std=c++20 -O2 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -Werror \
  -Iinclude src/contact_reference.cpp tests/cpp/contact_reference_test.cpp \
  -o /tmp/contact_a021_independent_test
/tmp/contact_a021_independent_test
```

**Result: 13 of 14 named cases passed; aggregate exit status 1.** The failed case
was `grazing_tangent`, returning `numerical_failure/unresolved_grazing`.
Conservative impact at all four maximum steps, damped impact, forced clamp,
separated oscillator, preload, moving damper, relaunch, finest-step event order,
coordinate scaling, invalid-input rollback, five resource-cap exhaustion cases,
grazing miss, and positive grazing contact passed that run. The event-order test
uses maximum step `2.5e-6 s` and event width `2.5e-9 s`; it does not establish the
same result for every coarser integration setting.

A separate default-20-us action probe confirms the remaining coarse-setting
boundary: at the analytic separation time, accumulated phase error leaves
compression `6.615e-12 m`. This exceeds the `5e-13 m` gap bound, so relaunch
returns `numerical_failure/unresolved_event` and preserves the pre-action object.
Relaunch one microsecond before and after separation succeeds. The implementation
does not widen the bound or invent a zero compression to make the exact-time
fixture green.

## Explicit remaining gates and handoff

1. Resolve the exact tangent without numerical contact impulse and certify its
   distinct classification. Current interior-extremum uncertainty returns failure.
2. Resolve exact-separation action timing at coarser settings within both time and
   gap bounds, or characterize the narrower successfully tested action domain.
   A focused analytic free-branch specialization is a possible next implementation.
3. Complete A022's independent-method, common-physical-time waveform, physical
   loss/work, event refinement, local-tolerance refinement, and two-successive-step
   decreasing-difference gates. C++ fixture passes do not establish these gates.
4. Diagnostic force/compression maxima are explicitly sampled accepted-trajectory
   maxima with sample times. Continuous-time extrema have not been certified.
5. Quarter/interior/extremum checks are implemented, but no proof of complete root
   isolation for every allowed nonlinear/clamp-tangency configuration is claimed.
   Exponent 1.5, measured mechanics, arbitrary trajectory families, and runtime
   execution remain outside this scope. Nonlinear-solve refinement is inapplicable
   to this explicit solver, not a passed test.

# W1-A003 — Runtime and host-readiness audit

Agent: `/root/w1_a003`. Scope: read-only audit of RT-001, the benchmark, and the
boundary needed before a host adapter. Baseline commit:
`10cbde821e2912d2a41ebb5952ee639988bc9e14`. No source or canonical-state changes.

## Findings

The most useful independent runtime implementation is the already specified
bounded event adapter. `ResearchEngine` currently takes call-boundary controls
and arbitrary-length output spans; callers must split buffers themselves. Add a
fixed maximum of 4096 frames and 256 ordered events per call, validate the entire
event list before state mutation, preserve producer ordering for same-offset
events, and distinguish rejected input from a partial arithmetic fault. Keep the
physical core independent of a host SDK. The proposal is engineering work that
does not depend on specimen measurements.

The present `rhodes_benchmark` is a useful process-only baseline and should retain
that identity. Note-on, note-off, pedal and reset can recalculate many transitions
but are excluded from its timestamps. Add a separately named full-call workload
timing input validation, event application and rendering. Include 256-event
stress, all 73 keys, pedal/retrigger traffic, 192 kHz/64-frame stress and an
uninterrupted long decay. Do not silently reinterpret old JSON measurements.

Source inspection finds fixed storage and no explicit core allocation, locking
or I/O, but there is no allocation-trap test. Instrument callback/event execution
with a scoped allocation counter and reject allocations on both accepted and
invalid-input paths. Avoid claiming this proves all platform-library behavior.

RT-001 cannot be completed by timing alone. Its acceptance also requires a
numerical-reference error report and timestep/antialiasing convergence. Exact
linear propagation does not remove aliasing from the nonlinear pickup. Retain
this as an open numerical limit until independently measured against a suitable
high-rate, low-pass reference. A prospective SDK wrapper also needs explicit
MIDI range/channel/overlap policy, parameter/state serialization, float-output
scaling, host-buffer segmentation, reset/fault policy and actual host validation.
No VST SDK or plugin is currently present in the inspected build.

## High-value adapter tests

- Compare the specified 130-frame event fixture under `[130]`, `[64,64,2]` and
  single-frame partitions, including final modal states and same-time off/on
  order reversal.
- Reject late/out-of-order events, offset equal to block length, event overflow,
  bad key/value/type and events on an empty block before any state change; zero
  the rejected output.
- Test pedal lift with a held key and a released key; hard-reset after mixed
  pedal/key activity and compare subsequent behavior to a fresh engine.
- A diagnosed arithmetic fault must retain earlier output, zero the failing
  sample/remainder, and require explicit reset. Add a narrow test seam if needed
  rather than pretending invalid-input coverage exercises arithmetic recovery.

## Checks actually run

All commands ran in the repository root on Linux:

```sh
python3 tools/project.py validate
python3 tools/project.py sync --check
python3 tools/project.py next --json
cmake -S . -B build-agent003 -DCMAKE_BUILD_TYPE=Release
cmake --build build-agent003 --parallel 2

./build-agent003/rhodes_benchmark --blocks 1000 --block-size 64 --sample-rate 192000 --active-keys 73 --machine container-shared-unspecified-cpu
```

State validation succeeded (13 tasks, 2 evidence records, fidelity unvalidated).
The generated view was current; PHY-002 and RT-001 were available. CMake used
GCC 14.2.0, Release, and all 25 CTests passed. The private build directory is
temporary review output and is removed after this review.

The exploratory benchmark observed mean 49.781749 us, p50 45.008 us, p99
111.696 us, maximum 500.047 us, and 2 callbacks above its nominal 333.333333 us
deadline. It measured 1000 blocks after 32 warmup blocks. All 73 keys were
struck at block zero; the declared retrigger interval was 1500 blocks, so this
short recorded run did not contain a retrigger. Checksum was 58.392124788974051
and peak absolute synthetic volts 0.46334956319161308.

This is one process-only observation in a shared container without recorded CPU
model, affinity, priority, power or competing-load controls. It is not a complete
RT-001 performance record, an audio-device result, or a CPU-utilization claim.
The observed misses must not be omitted from any summary of this run.

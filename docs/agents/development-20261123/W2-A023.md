## Implementation delivered

- Separate public `rhodes::vst3::RhodesProcessor` and `RhodesController` classes,
  stable processor/controller FUIDs and an SDK factory in eight original source
  files. No SDK source was copied or vendored.
- One sixteen-channel event input, no audio input and one stereo output. Both
  channels receive the same synthetic mono signal. Float32 and float64 audio,
  32–192 kHz, zero advertised latency, and an asymptotically decaying tail are
  supported. Rejected setup leaves the working configuration unchanged.
- Monitoring gain parameter `0`, normalized default `0.5`, plain range `0..32`,
  and sustain parameter `1`. Sustain uses reversible `Off`/`On` strings, with
  normalized `0.5` selecting `On`. `IMidiMapping` exposes only CC64, on channels
  0–15 of event bus zero. There is no custom view.
- Full syntax/buffer/queue preflight precedes mailbox consumption. Ownership is
  then validated on a fixed-storage copy, empty only when a recall token was
  consumed. Ownership or combined-dispatch failure calls the shared
  `StateMailbox::abort_block` before any mechanical mutation.
- Gain points are quantized to binary32 and duplicate offsets retain the final
  point. Interpolation starts from the previous value at sample `-1`; offset
  zero applies directly. Sustain is a step. At equal offsets, parameter events
  precede physical notes, whose original host ordering is retained.
- At most 256 raw input note events and 256 translated note events are accepted.
  Each core invocation handles one sample and at most 256 combined note/pedal
  events. Dense host automation therefore does not exceed the core event array.
- Parameter-only zero-frame flushes accept offset-zero points and do not advance
  mechanics or the frame cursor. Note-bearing zero-frame calls reject atomically.
- Exact sixteen-byte state stream helpers share the core codec. Reads validate
  current position, seek/end/restore results and exactly sixteen remaining bytes.
  Reads and writes accept positive short transfers through at most sixteen calls,
  and reject errors, invalid transfer counts and zero progress.
- State callbacks publish/snapshot the lock-free mailbox only. Audio applies
  recalls after successful full preflight. Lifecycle resets clear mechanics,
  holders, interpolation history and arithmetic/conversion fault latches while
  preserving the selected configuration.
- Output conversion is checked in double and again after float32 conversion.
  Faults preserve prior successful output, leave the failed sample/remainder
  silent and require reset. Invalid input silences supplied output without
  changing live configuration, holders or mechanics.

Unsupported input event types reject the block; the output-only SDK legacy CC
event is not treated as incoming MIDI. Finite tuning metadata is ignored because
this prototype has a fixed synthetic temperament. An inactive audio bus may have
null sample buffers, as allowed by the SDK; its channel-pointer array is required.

## Integration decision: bounded 8192-frame host calls

The initial implementation followed the originally assigned 4096-frame host
limit. The integrator's actual SDK-validator run exposed that the pinned
`public.sdk/source/vst/testsuite/testbase.h` configures `maxBlockSize` and
`kMaxSamplesPerBlock` as **8192**. This worker inspected both definitions locally.
The integrator explicitly directed expansion of the adapter's host staging bound.

`plugin_ids.hpp` now defines `kMaximumHostFrames = 8192`. Setup, host frame count,
fixed parameter storage and each queue's raw-point cap use that constant. The
core's separate 4096-frame invocation bound remains unchanged; each adapter
invocation of the core processes one sample. The revised check also rejects an
8193-frame buffer atomically and clears all 8193 supplied samples. This change
does not relax the core numerical tests, note bounds or per-sample event limit.

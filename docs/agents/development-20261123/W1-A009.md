# W1-A009 — Event processor contract review

Scope: bounded, read-only implementation review for the integrator; no task-state or Git changes. Read required repository context, `include/rhodes/event_processor.hpp`, the engine implementation, and `docs/specs/RUNTIME_AND_ASSETS.md`.

Reviewed header SHA-256: `2d45ea128e7654b5aa1bbbbb74255a08371e053a1bd11ad42a409e977aaab87c`.

## Findings

1. **No demonstrated ordering or preflight-atomicity defect.** Validation scans the entire bounded event list before applying any control. Equal-offset sequences must increase strictly; events execute before that sample. Independently dispatched scalar controls produced bitwise-identical samples and all 219 final modal states for partitions `[130]`, `[64,64,2]`, and single frames. Reversing release/retrigger at 63 changed output, as required.
2. **Oversized rejection has caller-sized cost.** The rejection lambda fills the complete output span even when its size exceeds 4096. A 5000-frame fixture confirmed every element was zeroed. Therefore 4096 bounds accepted DSP work, not total work on malformed calls. Preserve the required zero-output behavior, but document an upstream bounded buffer/segmentation contract; do not claim globally bounded rejection cost without it.
3. **Diagnostic contract remains incomplete.** `ProcessResult` reports sample/event indices and reset requirement, but no subsystem field. The engine's Boolean result cannot currently identify mechanical versus pickup/network failure. Add a bounded subsystem value, or explicitly document an undifferentiated engine-fault scope until the core exposes that information.
4. **Recovery semantics need explicit documentation.** A queued reset event cannot clear a previous fault: the fence rejects it before event dispatch. Public `reset()` or successful `prepare()` recovers and resets the cursor; an ordinary in-block reset preserves the cursor. This is a reasonable policy, but hosts must distinguish these operations. Invalid `prepare(NaN)` preserves the fault fence.
5. **Scheduling scope remains narrower than the complete contract.** Relative-offset events cannot identify an event that became late before this call; no absolute timestamp/future queue exists. The surrounding host scheduler must own those checks. Cursor overflow arithmetic is present but has no practical public test seam.

## Exact follow-up tests

- Exercise event-application failure at sample 17/event index 1; assert both indices, no sample-17 processing, no later event dispatch, retained prefix, and reset requirement.
- Add a legitimate cursor-test seam: start at `UINT64_MAX-1`; accept one frame, accept empty input, reject the next frame before controls/state changes.
- Test accepted 4096 frames/256 events, sequence `UINT32_MAX` ties without wrap, descending offsets, NaN/Inf values, invalid enum values, and negative intensity.
- After both reset routes, compare strike/release with a fresh engine, including pedal activity; freeze empty-call behavior while faulted.

Only the report and ignored harness artifacts were written. These tests establish adapter behavior, not production arithmetic-fault induction, allocation/locking guarantees, host deadlines, or physical fidelity. Next: integrate the discriminating cases and clarify the four scope boundaries above.

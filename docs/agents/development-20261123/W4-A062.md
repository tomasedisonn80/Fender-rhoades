# A062 — Hide VST3 implementation symbols

## Change

Set explicit `CXX_VISIBILITY_PRESET hidden` and `VISIBILITY_INLINES_HIDDEN ON`
on the VST3 module and static core. The SDK's child-directory defaults do not
configure these parent targets. SDK export annotations preserve the factory and
platform entry points. The core setting is conditional on its actual
`STATIC_LIBRARY` type, preserving existing `BUILD_SHARED_LIBS=ON` behavior.
No DSP, state format, class identity, dependency, or test wiring changed.

## Observed result

On Linux x86-64, GCC 14.2, CMake 4.4.5, strict Release:

| Measure | Before | After |
|---|---:|---:|
| Defined dynamic exports | 137 | 14 |
| Rhodes implementation exports | 120 | 0 |
| ELF bytes | 331208 | 326792 |

`GetPluginFactory`, `ModuleEntry`, and `ModuleExit` remain exported. The eleven
other exports are standard-library weak/template or type-information symbols.
Generated compile flags contain both visibility options for core and module.

Configured `build/vst3` with `RHODES_BUILD_VST3=ON` and the documented external
SDK, then built `rhodes_vst3`, `rhodes_tests`, `rhodes_vst3_host_tests`, and
`rhodes_vst3_fp_tests`. `ctest --test-dir build/vst3 -R '^(core\.|vst3\.)'
--output-on-failure --no-tests=error` passed **29/29**, including **47/47 SDK
validator checks** and all sixteen retained host selectors.

SDK `moduleinfotool` creation and validation succeeded on a copied rebuilt bundle.
Regenerated metadata equals the bundled bytes and the pre-change metadata;
both processor/controller UIDs match `plugin_ids.hpp`. A separate Release build
with `BUILD_SHARED_LIBS=ON`, `BUILD_TESTING=OFF`, and `RHODES_BUILD_VST3=OFF`
built the shared core and renderer; renderer `--help` succeeded, with hidden
visibility absent from that core's flags.

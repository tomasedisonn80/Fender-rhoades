## Result

The existing renderer accepts `--audio-path direct|filtered`. Omitting the flag
selects the original `ResearchEngine`; `filtered` selects `AudioEngine`. One
dispatch outside the rendering loop instantiates a shared templated rendering
function. No per-sample variant dispatch was introduced.

Normal success output reports the selected path, the prepared engine's internal
sample rate and latency: 0 host frames for direct, 48 host frames for filtered.
Help states the direct default and explains that the causal filtered delay stays
inside the requested duration. The renderer emits exactly the existing rounded
host-frame count, with no initial trimming, extra tail or changed release time.
The synthetic-parameter/no-hardware-fidelity statement remains in success output.

The existing temporary-directory reservation, closed-file publication,
no-overwrite preflight and publication-time recheck, forced regular-file
replacement, symlink refusal, flush/close checks and finite-input/output checks
remain shared. The two engine-specific failure messages now say “audio engine”
instead of “research engine”; the failure exit status remains 2.

Example invocation for documentation integration:

```sh
./build/main/rhodes_render --audio-path filtered \
  --output build/main/filtered-note.wav --seconds 3 --sample-rate 48000
```

### Exported causal-phase check

A separate Python standard-library calculation rendered a direct 192-kHz WAV
with the same 0.01-second duration, note and monitoring gain, then parsed the
385 stored L=4 coefficients. It independently evaluated zero-padded direct
convolution at internal indices `4*n`, starting at `n=0`, and compared every
result with the 480-frame filtered 48-kHz WAV. No alignment, trimming, gain fit
or onset fit was applied. Symmetry and length imply `(385-1)/(2*4) = 48` host
frames of group delay for these coefficients.

Maximum absolute difference was **3.0634285594355326e-9 output units**. The
computed binary32 rounding bound was **6.144980928268781e-9**, obtained from
`sum(abs(coefficients)) * max(input half-ULP) + max(output half-ULP)`; the check
allowed an additional `1e-12` for arithmetic. This bounds the loss from using
the direct float WAV as the oracle input. It checks exported stream timing;
it does not independently validate the coefficient recipe. The export fixtures
remain under `build/main/w2-022-baseline-v37d1y4s`.

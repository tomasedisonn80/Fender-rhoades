# W1-008 — Separate filtered VST3 compatibility review

Reviewed 2026-11-23; bounded source review only. Read `AGENTS.md`, README,
roadmap, canonical state/dashboard, host contract, codec/mailbox, VST3
processor/controller/factory/streams, build wiring, and existing state fixtures.
No builds or executable tests run; no implementation or canonical-state changes.

## Recommendation

Approve the second-bundle strategy with the contracts below. It preserves
existing model-1 identity, bytes, sound and zero-latency behavior while making
the FIR signal path an explicit model-2 selection. `AudioEngine` does not yet
exist in the inspected tree, so its reset/prepare behavior remains unverified.

## Minimal contract and integration hazards

- Keep the existing processor/controller FUIDs, bundle name, controller display
  name, model-1 tag and original `EventProcessor` alias unchanged. Allocate two
  permanent new FUIDs, a distinct filtered controller display name, and a
  distinct macOS bundle identifier. `factory.cpp` currently hardcodes the
  controller name; changing only `kPluginName` misses it. The processor's
  `setControllerClass(kControllerUID)` must select its matching variant.
- Put the conditional `HostEventProcessor` alias in the adapter, including its
  diagnostic return type and member. Compile **every translation unit** of a
  filtered executable/module with the same private target definition. Never
  combine both processor variants into one executable/object library: their
  identical C++ class/symbol names would denote incompatible definitions.
  Existing hidden module/inlined-symbol visibility permits separate modules;
  preserve it on the new target. Do not put the variant definition on shared
  `rhodes_core`, the SDK, or global compiler flags.
- Make codec and stream model arguments ordinary explicit values with an
  unconditional model-1 default. Do not make inline codec bodies/defaults
  depend on `RHODES_FILTERED_VST3`. Preserve sixteen bytes and version 1;
  bytes 6–7 carry the little-endian model identifier. Restrict supported model
  arguments to 1/2, and reject unknown or mismatched identifiers. Pass the
  selected model explicitly at **all** processor/controller save/restore
  boundaries, including `setComponentState`; otherwise model-2 can accidentally
  serialize or accept model-1. `InstrumentState` and mailbox remain unchanged
  because each processor's model is immutable.
- Report constant latency through an adapter override derived from the engine
  contract: original 0, filtered 48 host samples at every supported rate and
  lifecycle stage. FIR group delay does not mean the first 48 samples must all
  be zero. Keep event offsets in host frames and monitoring automation at the
  existing output-stage timing.
- Recall, activation, processing transitions, successful reconfiguration and
  termination already funnel through `reset_audio_owner`/`install_recall`.
  `AudioEngine::reset` must clear FIR history, phase, mechanics and fault state;
  failed preparation must preserve everything. Zero-frame control flushes must
  not advance FIR phase. Pending recalls and whole-block rejection semantics
  remain those of the current mailbox.

## Focused verification

1. Leave original tests unchanged and run them. Add independent model-2 golden
   bytes, both cross-model rejection directions, unknown models, malformed/
   partial streams, and rejected recall preserving a prior pending recall and
   controller parameters. Exercise processor and both controller restore APIs.
2. Compare filtered adapter samples against an independently dispatched
   `AudioEngine` for both sample formats, sample-offset notes/pedal and gain
   automation. Check split-block equivalence, FIR reset/recall, zero-frame flush,
   sample-rate changes and rejected setup continuation.
3. Validate factory FUID pairing, distinct metadata, constant latency, and
   same-process coexistence of both loaded bundles. Run the official validator
   against **both** packages; add the filtered target to `rhodes_vst3_checks`.
   Assert allocation-free filtered callbacks.

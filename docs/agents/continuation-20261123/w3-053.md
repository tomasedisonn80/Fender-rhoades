# W3-053 — Checked diagnostic stdout publication

Actual worker 53, 23 November 2026. Owned changes are
`apps/audio_probe.cpp`, `apps/contact_reference.cpp`, and
`tests/cpp/diagnostic_stdout.cmake`. The integrator owns CMake registration,
Git publication, canonical state and campaign records. No subagent was spawned.

## Finding and repair

Both tools could return success although their final buffered stdout bytes had
not reached the destination. The probe checked stream state before flushing;
the contact exporter did not check output state. Copied pre-change binaries
returned **0 with empty stderr in all four `/dev/full` cases** below.

Each tool now explicitly flushes stdout and checks its state before a successful
return from either ordinary JSON or help output. A write failure uses the existing
exception path: probe exit **2** with `rhodes_audio_probe: Cannot write stdout`,
contact exit **1** with `Contact reference error: Cannot write stdout`.
Successful contact solver output retains its existing `result ? 0 : 2` return;
invalid input and solver status handling are unchanged. A failed stdout write
can leave partial output; this is error detection, not transactional rollback or
a filesystem durability guarantee. No equation, coefficient, schema or text
payload was changed.

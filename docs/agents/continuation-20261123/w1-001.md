The immediate mechanism is the interaction between two independent controls:
`ReferenceSolver::error_norm` in `src/contact_reference.cpp` imposes a fixed local
contact-gap defect scale of `0.002 * event_gap_tolerance_m` (default `1e-15 m`),
while `advance` treats `maximum_step_s` as a ceiling and adapts each accepted step
using that error. Halving the ceiling does not halve the steps already constrained
by the tighter local controller. The frozen 10/5/2.5 µs sequence therefore changes
an adaptive mesh rather than uniformly refining a single discretization.
`refinement_gates` nevertheless requires every final maximum observable difference
to decrease by 0.8 whenever it exceeds its 128-ulp threshold. Those exact gate
conditions cause the seven failures.

The damped example demonstrates why event splitting alone cannot resolve the
diagnosis: its 5/2.5 µs position-difference maxima occur at 120 µs (`q_m[0]`) and
100 µs (hammer position), before its approximately 956 µs separation. The
preceding 10/5 µs `q_m[0]` maximum is instead at 2 ms. Its normalized maximum
changes from `3.0005949543e-7` to `7.6864880335e-7`, despite the latter maximum's
absolute difference being only `8.3009855635e-15 m`. This is a pre-asymptotic
adaptive-refinement result, and the existing strict gate correctly retains it.

There is a separate event-reporting limit. `refine` stops when both bracket and
gap tolerances pass and publishes the bracket midpoint; `scan` records events,
and `commit_interval` commits the original trajectory without splitting at them.
For supported impact, the fourth event's 5/2.5 µs centers differ by
`1.192093e-12 s`, approximately one final bracket width. The event decrease test
uses machine ulps of fixture duration, not the root bracket's actual uncertainty.
Thus midpoint quantization can dominate the last observable difference even
when trajectory refinement improves. Source inspection and observed brackets
establish this mechanism; no modified-solver ablation was performed.

# W1-005 — FIR coefficient specification and measurement

Actual worker 5; 2026-11-23. Bounded numerical study for RT-001. Read required
repository context, W1-002, and `ResearchEngine::prepare/sample`; no runtime,
Git, claim, or canonical-state edits. Constants below are synthetic engineering
choices, not specimen measurements.

## Decision

**Prefer `N=96L+1`, delay 48 host samples**, Kaiser beta 9, cutoff
`0.47 * host_rate`. Freeze passband **0–0.446 host rate, ±0.05 dB**, and
stopband **0.5 host rate through internal Nyquist, at least 80 dB rejection**.
At 32 kHz this passes through 14,272 Hz, covering W1-002's highest linear carrier
14,266.280620 Hz. The transition is 14,272–16,000 Hz; cutoff is 15,040 Hz.
These edges scale with rate. Use the proposed L=4/2/1 rate partitions unchanged.
Latency is 1.5 ms at 32 kHz, 1 ms at 48 kHz, and 0.25 ms at 192 kHz.

If **32 host samples is mandatory**, freeze the weaker, explicit alternative:
`N=64L+1`, beta 5.5, same cutoff/edges, **±0.1 dB passband and 54 dB rejection**
across all factors (58 dB for L=2/4). Do not describe this as an 80 dB filter.
The scanned Kaiser recipes did not attain both 0.1 dB and 80 dB with this length;
this is not an optimality proof over all FIR designs.

At 32 kHz/L=4, the exact highest-linear-carrier gains for K=64/96/128 were
-0.081914/-0.031663/-0.000513 dB. K=128 buys additional flatness/rejection but
raises latency to 64 frames and symmetric FIR pair work from 193 to 257 at L=4.
K=96 is the pragmatic compromise. At L=1 the stopband is the single internal
Nyquist endpoint; it does not represent rejection beyond a sampled spectrum.

## Reproducible coefficient recipe

For K=96, L in {1,2,4}, define M=48L, m=n-M, n=0…96L:

`g[n] = (0.94/L)*sinc(0.94*m/L)*I0(9*sqrt(1-(m/M)^2))/I0(9)`

Use normalized `sinc(x)=sin(pi*x)/(pi*x)` and `h=g/sum(g)`. Equivalent:
`scipy.signal.firwin(96*L+1, .47, window=('kaiser',9), fs=L, scale=True)`.
Odd symmetric taps give exactly 48 host samples of linear phase delay [1].
Use substep-0 decimation as W1-002 specifies; history is continuous across blocks.

Frozen reference byte format: consecutive IEEE binary64, little-endian, no header.
SHA-256:

- L=1: `b4d90ee147b19dfed8c7ffbe8e09806574ace6f22c15c51c307233a873100728`
- L=2: `9e5816a101b3903d01c761225ee470c21f749206e086888805d4e45bee96578f`
- L=4: `b674ee4bbf6a06847aea3db69a2b1fc463887db9bc8766a853263745350a899f`

All measured arrays were exactly symmetric; DC-sum error was ≤2.23e-16.
Recipe regeneration on another math library need not be bit-identical. Freeze
serialized taps or compare with explicit numerical tolerances.

## Evidence and limits

Commands actually run: `python3 build/w1-005/measure.py` and
`python3 build/w1-005/dense.py`; both completed successfully. Temporary scripts,
search/dense JSON and coefficient binaries are under `build/w1-005/`.
Kaiser order equations are empirical and can miss nominal rejection [2]; the
chosen 80 dB gate has >8 dB measured margin. Dense grids are observations, not a
continuous-frequency proof. FIR rejection does not bound event transients,
preexisting internal-rate aliases, or complete-engine error. Next: integrate the
chosen latency explicitly, verify serialized taps independently and run event,
reference-error and callback-cost gates before enabling host quality selection.

[1] SciPy developers, [firwin](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.firwin.html): window method, linear phase, cutoff and DC normalization.
[2] SciPy developers, [kaiserord](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.kaiserord.html): empirical equations and first-stopband-lobe caveat. Both accessed 2026-11-23.

## Priority defect and recommended contract

`plugins/vst3/processor.cpp::silence_outputs` traverses every positive
host-declared output count, channel count and frame count, including immediately
after `validate_buffers` rejects those counts. Rejection work therefore scales
as declared buses × channels × frames, outside the accepted 1 × 2 × 8192
envelope. Existing `rejected_buffers` explicitly requires clearing 8193 frames,
three channels and a second output bus. This is a confirmed implementation
property, not a timing measurement or a claim about invalid pointer safety.

**Choose unsupported output dimensions untouched, rather than a cleared prefix.**
Make cleanup independently validate its output envelope before any traversal:

- Require supported sample format, `0 <= numSamples <= 8192`, exactly one
  output and a non-null output array before accessing its bus.
- For positive frames, require exactly two declared channels. Then examine at
  most the two channel pointers and clear supplied non-null sample buffers.
  A null channel-pointer array permits no sample access.
- For zero frames, accept zero or two declared channels, update their silence
  flags, and access no sample pointers. Zero outputs require no work.
- For an unsupported frame/bus/channel count or format, leave output samples
  and silence flags untouched and return failure. Do not clamp a count and
  imply that uncleared remaining storage is silent.

Other malformed input with a supported output envelope can still receive full
silence. A block larger than the configured maximum but no larger than 8192
can be cleared within this global bound. The bounded cleanup continues to trust
that non-null storage actually exists as declared; C++ cannot validate foreign
memory or prevent foreign event getters from blocking.

Update the host contract and guide to distinguish these cases; the current
unqualified “invalid input returns silence” must change. This is an intentional
rejection-policy revision, not a relaxation of note/state transactionality.

## Specific regression design

Update `tests/cpp/vst3_buffer_contract_test.cpp` expectations for unsupported
output shape and keep real, guarded storage. Cover float32/float64, 8192/8193
frames, one/two buses, two/three channels, bad format, negative dimensions,
null pointers and the zero-frame shapes. For giant integer counts, use null
channel arrays or otherwise legitimately accessible test storage; do not
allocate enormous buffers or rely on a flaky callback-duration threshold.
Check unchanged sentinel flags as well as samples on unsupported shapes.

Repeat each rejection with and without pending recall, compare complete
mechanics/ownership/configuration snapshots, then compare subsequent valid
audio with an untouched control processor. Retain full clearing for a malformed
queue/note with ordinary stereo output and for a configured-block-limit breach
inside the global limit. Run the allocation guard and SDK validator after the
change. Static review should establish no cleanup loop can use raw counts
beyond one bus, two channels and 8192 frames.

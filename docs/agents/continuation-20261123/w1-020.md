Actual worker 20, 2026-11-23. Read-only production audit against the frozen
`docs/specs/FILTERED_AUDIO_20261123.md`; only this report and temporary

production target was rebuilt. Project `validate`, `sync --check`, and
`next --json` succeeded; the active integrator retains task/state ownership.

## Result and concrete defect

**Both Linux modules coexist and instantiate successfully, but filtered resource
packaging is incomplete.** Under `build/main/VST3/Release/`, both
`RhodesResearch.vst3` and `RhodesResearchFiltered.vst3` contain their appropriately
named `Contents/x86_64-linux/*.so` and `Contents/Resources/moduleinfo.json`.
However, the filtered bundle lacks `LICENSE.txt` and `THIRD_PARTY_NOTICES.md`.

`cmake/Vst3.cmake::rhodes_add_plugin` invokes the pinned SDK's
`smtg_target_add_plugin_resources` twice with identical input paths. That SDK's
`SMTG_AddSMTGLibrary.cmake::smtg_target_add_plugin_resource` attaches resource
generation through `MAIN_DEPENDENCY` on the shared input source. The generated
`build/main/CMakeFiles/rhodes_vst3_filtered.dir/build.make` lines 72–80 and 193–194
actually copy/depend on **RhodesResearch.vst3** resources. This confirms a
generated-rule collision rather than an unperformed filtered build. Recommended
integrator fix: target-specific resource staging inputs, or explicit per-target
copy commands using each target's `SMTG_PLUGIN_PACKAGE_PATH`, then inspect both
fresh bundles. No production files were changed here.

## Actual verification

A temporary C++ loader uses pinned SDK `VST3::Hosting::Module::create`, existing
`libsdk_hosting.a`, `libsdk_common.a`, `libbase.a`, `libpluginterfaces.a`, and the
SDK's `module_linux.cpp`/`memorystream.cpp`. Compiled with `c++ -std=c++20 -O0
-DRELEASE=1`, SDK include root `/workspace/scratch/af088a9f3cc9/vst3sdk`, archive
link group and `-ldl -lpthread`. Invoked with both absolute bundle paths.
Exit **0**: both modules retained simultaneously; four unique class IDs;
distinct factory pointers; processor/controller creation and initialization;
16-byte processor states with model tags 1/2; reported latencies 0/48;
successful termination. No audio processing or DAW operation was exercised.

`nm -D --defined-only` found only three strong exports per module:
`GetPluginFactory`, `ModuleEntry`, `ModuleExit`, plus eleven standard-library
weak/RTTI symbols. No Rhodes implementation symbols escaped. Pinned Linux SDK
hosting uses `dlopen(RTLD_LAZY)`, calls mandatory `ModuleEntry(handle)` before
factory retrieval, and releases its factory before `ModuleExit`/`dlclose`.

`compile_commands.json` confirms all five filtered-module translation units
carry `RHODES_FILTERED_VST3=1`; all five direct units omit it. Core (1), SDK
(17), SDK-common (9), and SDK-hosting (9) units omit it and use hidden visibility.
Filtered benchmark (3) and test (4) units consistently carry their private
definition. This matches the CMake target scopes.

## Central technical distinction

SciPy's independent Radau reference still uses sign changes for ordinary event
detection, which can miss multiple roots inside a step. Its dense state is a
cubic collocation interpolant. The derivative of an interpolated position need
not equal its separately interpolated velocity between collocation points;
likewise interpolated velocity derivatives need not equal RHS acceleration.
Thus the design distinguishes physical-RHS stationary roots from extrema of the
dense interpolant and requires explicit reference refinement/coverage reporting.

Polynomial enumeration can supply even-root candidates for constant/linear face
motion. It does not justify treating a sinusoidal face as polynomial, nor does
bounding a dense polynomial alone bound the true ODE solution. Proposed phase 1
therefore keeps `coverage=uncertified_independent_search` and cannot close PHY-002.

## Independent algebra check actually executed

A Python scalar calculation used only the frozen free-mass constants and the
derived invariant, with `scipy.optimize.brentq` on the monotone scalar equation
`Phi(w)+(alpha/2)*w-Phi(w0)=0`. No candidate trajectory or peak code was called.

| Calculated quantity | Observed value |
|---|---:|
| Conservative peak compression | `0.000282842712474619 m` |
| Conservative peak force | `5.656854249492381 N` |
| Conservative peak time | `0.0004442882938158366 s` |
| Damped peak compression | `0.00018988288088523308 m` |
| Relative speed at damped force peak | `0.5467377817171872 m/s` |
| Damped peak force | `6.191807278604625 N` |
| Scalar stationarity residual | `1.1102230246251565e-16 m/s` |

The environment was Python 3.12.14, NumPy 2.3.5 and SciPy 1.17.0. This checks the
proposal's scalar arithmetic; it is not a new candidate validation or proof of
the complete numerical reference. No full contact sweep or audio test was run.

## Candidate mechanism and bounds

After a trial passes the existing local-error check and event scan, select the
smallest right-bracket endpoint among newly found natural branch-changing roots.
If it lies at least the existing progress floor from both ends of the current
trial, replay once from the unchanged starting state to that endpoint, check the
same local-error test, rescan the shortened interval, and commit its resulting
mechanics and ledger. The next outer step restarts from that unprojected state.
The rescan may refine the event's recorded bracket; it does not recursively
split again inside the same outer trial.

This uses the post-root bracket endpoint rather than repeatedly replaying toward
a root midpoint. It is generic over contact identity and branch kind; grazing
has no branch change and therefore does not trigger a split. A root at the start
or too close to either endpoint is left to the existing accepted-step behavior.
No coordinate, velocity, impulse or work projection is introduced. External
actions and their ordering code are untouched.

The extra trial and scan use the existing trial, RHS, root, subdivision, event,
interval and rejection limits. There is at most one extra replay per initially
accepted outer trial. A failed shortened trial uses the existing rejection path;
there is no uncounted retry loop or new budget. The committed step length and
next-step controller use the shortened interval. Reaching a budget may occur
sooner because the candidate performs additional charged work; that behavior
was not hidden by raising limits.

## Bounded sanity sample and limits

Eight additional fixtures ran once each at 1.25 µs, the same event/local/output
settings: conservative_impact, forced_clamp, event_before, event_at,
supported_impact, moving_damper, grazing_contact, and grazing_tangent. These
address free motion, clipped loss, action ordering, repeated recontact, moving
contact and short/tangent contacts without a full sweep.

All baseline and candidate commands exited 0, with identical sample times and
event contact/kind sequence. `forced_clamp`, `event_at` and `grazing_tangent`
outputs are identical in every field. The conservative outgoing velocity and
impulse have the same corrected values as event_after. Baseline-to-candidate
comparisons returned no budget errors in these eight cases; the largest fraction
was 0.000151119120060 for supported_impact. This is a change-size check, not an
independent correctness oracle for those nonlinear fixtures.

Only one implementation variant was compiled and run; there are no failed
variants to conceal. No midpoint-iteration variant, additional refinement depth,
relaxed tolerance, reduced divisor, fixture-specific correction or global step
cap was tried. The following limits remain explicit:

- No 338-run sweep, full CTest suite, independent Radau/expm audit or continuous
  extrema audit was run, and no claim about those gates is made.
- The clipped fixture starts on the clipped branch and separates. It does not
  exercise an interior active↔clipped factor-zero crossing. That generic path
  uses the same split rule but remains unverified by this sample.
- Simultaneous/overlapping natural root brackets, roots within a progress-floor
  distance of endpoints, and forced work-budget exhaustion need focused checks.
- The smooth RK4 error estimator is unchanged. The candidate reduces the
  straddling defect by restarting at a localized event; it is not a proof of
  error control at every nonsmooth transition or unresolved near-tangency.
- Repeated scans can change sampled extrema slightly. Existing diagnostic maxima
  remain sampled estimates and do not satisfy the independent-extrema gate.
- Root bracket output remains tolerance-bounded, not an exact event-state
  projection. The residual sub-bracket crossing is finite and must remain part
  of the reference-error analysis.

The next actionable step is integrator review of the unapplied patch alongside
workers 031/032, followed by focused budget/simultaneous/clamp tests and the
unchanged uniform matrix plus independent/extrema requirements if integrated.

# W1-009 — Continuous contact-extrema implementation design

Date: 2026-11-23. Assigned read-only review; only this report changes. No
implementation, numerical experiment, Git operation, or canonical-state mutation.

## Current boundary

`src/contact_reference.cpp::scan` checks five points per accepted interval.
`scan_segment` searches gap/clamp roots and some derivative turning points for
event discovery. Those refined points are not passed to `sampled_peaks`;
`commit_interval` updates maxima only from the five scan points. Public
`Diagnostics` and CLI `diagnostics.sampled_maxima` correctly disclaim continuous
extrema. The auditor unconditionally retains the missing-extrema gate.

There is an evaluation-consistency issue to resolve before extending root work:
`replay(start,t)` takes two RK4 half-steps from the interval anchor, whereas scan
quarter/midpoint values use different RK4 compositions. Re-evaluate both bracket
endpoints through the same replay evaluator; otherwise a bracket combines
different approximate trajectories. Replay is still numerical approximation,
not a validated dense extension.

## Implementable candidate diagnostics

Add a shared relative-acceleration helper using `Observation`:

- Hammer: `a = hammer_acceleration - sum(hammer_projection[j]*modal_acceleration[j])`.
- Damper: `a = sum(damper_projection[j]*modal_acceleration[j]) - face.acceleration`.

For each enabled contact, write `delta=gap_m`, `w=gap_rate_m_per_s`,
`z=k+c*w`. Compression candidates include roots of `w` where `delta>0`.
Positive-force stationary candidates solve `w*z+c*delta*a=0`, strictly within
`delta>0 && z>0`. Do not confuse existing `clamp_rate=c*a` with force rate.
For `c=0`, positive-force stationary points coincide with compression points.

Add `RootFunction::force_rate` and a separate extrema collector; do not emit
stationary points as contact events. Partition searches at geometric/clamp
brackets and external actions. Include initial/final states, accepted interval
endpoints, boundary brackets, and explicit before/after observations for relaunch
and damper-velocity changes. Preserve both sides even when their times match.
Separated/clipped force plateaus contribute zero without recursive zero-root
enumeration. Compression remains relevant on clipped branches.

Use deterministic bounded subdivision and bracketed refinement, counting all
replays against existing RHS/trial/root limits. Add a bounded candidate-row
limit. Preserve transactional rollback on exhaustion. Refine root time and
peak-value stability separately; event-time tolerance alone supplies no
force-error bound. Retain unresolved intervals rather than silently declaring
them root-free. Sign-change searches miss multiple/even roots; finite sampling
cannot certify completeness.

Keep existing sampled fields unchanged. Export additive extrema records with
contact, quantity, value, time bracket, endpoint/action-side classification,
evaluation method, and unresolved-search count. Initially label these
`located_candidates`, with coverage `uncertified`, not continuous maxima.

## Independent Radau integration

Extend the auditor's `Oracle` to retain dense segments, solver mesh boundaries,
and both action sides. Independently compute acceleration from its own `rhs`
and use the equations above, without candidate times as oracle seeds. Search
each smooth contact branch; current `solve_ivp` event lists alone do not establish
complete partitioning. Use bounded root isolation with explicit unresolved
outcomes, including tangencies. Compare extrema values under frozen compression/
force budgets and independently refine Radau tolerances, step caps, and root
brackets. Evaluate the candidate at oracle peaks and independently locate
candidate peaks; either direction alone can miss an extra peak.

Closure requires justified root coverage and candidate continuous-evaluation
error. Polynomial dense-output root isolation can establish interpolation-root
coverage only; ODE/interpolation error still needs validation, and sinusoidal
faces need corresponding interval bounds or an unresolved result.

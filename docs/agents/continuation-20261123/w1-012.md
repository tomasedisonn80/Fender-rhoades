Date: 2026-11-23. Bounded review; no production implementation, Git, canonical-state
changes, or full sweep. Read AGENTS, README, PROJECT_STATE, ROADMAP, canonical

## Reproduced defects

Command: `python3 build/w1-012/reproduce.py` (exit 0). Reproducer and results
are in `build/w1-012`. It uses structurally valid synthetic samples and the actual
preflight/selector, with only `compare_runs` mocked; no numerical acceptance is
claimed.

The smallest reproduced step-axis counterexample contains five runs: four frozen
step levels with event tolerance 2.5 ns and baseline local tolerances, plus a
conflicting duplicate at 5 us. Its sample position differs while its complete
settings tuple is identical. A mock comparison reports that discrepancy whenever
selected. Original order returns **incomplete**; reversal returns **fail**.
The existing sort chooses the first tied run, so duplicate conflict is never
identified independently of order. The full auditor also audits each run; this
is a selector counterexample, not a demonstrated overall false acceptance.

A second five-run case replaces that duplicate with a 2.5-us run at local scale
0.1. Reversal alone adds “independent step axis with fixed local/event
tolerances” to missing evidence. W1-006's concern is therefore reproducible
without a solver run.

Additional observed selection behavior:

- Replacing local scales 0.1/0.01 with 0.8/0.6 leaves no fixture-local missing
  evidence; the selector accepts any three distinct relative/absolute pairs.
- Removing a required local run reports incomplete; NaN metadata fails before
  comparison. A one-fixture subset records all 25 absent fixtures.
- Event selection ignores local settings, local selection silently drops tied
  settings, and coordinate comparisons minimize only step/event settings.
- CSV grouping uses only fixture/step/event and can merge distinct local settings;
  extend its grouping key or reject insufficient axis metadata.
- Output grid and velocity/energy/impulse tolerances are not part of selection.
  Sweep generation checks only position/relative tolerances plus step/event/grid;
  it should also verify the three other emitted absolute tolerances.

## Minimal implementation design

1. Add the W1-006 bounded `extra_step_levels=0,1,2` policy to plan and auditor.
   Keep all eight original runs per fixture. Append N step runs plus four
   new-finest event/local runs when N>0: totals 208, 338, 364. Retain policy in
   aggregate input and its hash; `read_runs` currently discards envelope metadata,
   so validate envelopes before flattening. Explicit flags and policies must agree.
2. Build one deterministic required-slot map from constants, never observed
   minima/counts. Key each slot by fixture, step, event tolerance, output grid,
   relative tolerance, and all four absolute tolerances. Map finite settings to
   exactly one declared slot using a tight fixed comparison; reject ambiguous or
   undeclared extension settings. Missing required metadata/slots is incomplete;
   present invalid metadata is fail.
3. Hash canonical scientific run content, excluding only separately recorded
   provenance. Identical same-slot copies may deduplicate with all sources
   retained. Different same-slot content fails before comparison, regardless of
   order. Compare event/local/scaling pairs at explicit matching slots only.
4. Require all 26 fixtures for acceptance even when generation selected a subset.
   Preserve frozen results; append declared extension results and unchanged-budget
   final-pair/decrease checks. Missing extrema still prevents full acceptance.

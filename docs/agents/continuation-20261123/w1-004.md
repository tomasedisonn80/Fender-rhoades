## Changes

- `plugins/vst3/processor.cpp`: `silence_outputs` independently requires a
  supported sample format, 0..8192 frames, exactly one output and a non-null
  output array before accessing a bus. Positive-frame cleanup requires exactly
  two channels and clears each supplied non-null channel buffer. Its only
  channel loops have the constant limit two; each fill has at most 8192 samples.
  Unsupported frame, output, channel or format declarations leave all samples
  and silence flags untouched. Configured-block-limit failures within the
  global envelope still clear fully. A zero-frame empty bus gets flags 0, a
  stereo bus gets flags 3, and no sample pointer is inspected. Zero outputs
  require no work; unsupported zero-frame shapes preserve flags.
- `tests/cpp/vst3_buffer_contract_test.cpp`: revised the prior oversized-output
  clearing expectations and expanded rejection coverage to 38 scenarios.
  Added the 8192-frame clearing boundary, INT_MAX frame/input/output/channel
  counts, malformed queue/note rejection, and explicit zero-frame flag rules.
  Integer-extreme fixtures use fixed real sentinel storage and null channel
  arrays where applicable; no enormous allocation or fabricated pointer is
  used. Every rejection runs in float32/float64, realtime/offline setup, and
  with/without a pending recall. Existing full mechanics, ownership,
  configuration and cursor snapshots plus subsequent independent-control audio
  comparisons remain in each rejection. The accepted flush matrix now checks
  flags for absent outputs and unused buses explicitly.

No event, state mailbox, rendering arithmetic, acceptance criterion or unrelated
implementation behavior was changed.

## Remaining limits and integration handoff

These are local functional checks, not callback-duration measurements or a
native DAW/platform validation. Non-null caller storage must actually exist
within the supported declared envelope. C++ cannot validate arbitrary foreign
pointers, and foreign parameter/event getters may still block. The fixed
cleanup bound does not establish a realtime deadline guarantee.

The allocation guard, complete host suite, rebuilt plug-in SDK validator,
sanitizers and native hosts were not run by this worker. The integrator should
run the relevant host suite and allocation/validator checks against the new
source, update current host documentation, and retain historical frozen
acceptance reports unchanged before recording a new source-bound review.

## Code review: event semantics and bounds

- At most one extra trial and scan occurs per initially accepted outer trial.
  Trial/RHS/root/subdivision/event/history work uses existing counters and caps.
  Rejection retains the existing rejection cap and minimum-progress checks.
- The split uses the minimum eligible right bracket endpoint. The time is a
  tentative landing target, not a projected state or an exact surface hit.
  The fresh trial starts from unchanged mechanics; its error is checked again.
- `found.clear()` removes original event rows; `scan` overwrites all five points.
  Commit therefore uses new mechanics, ledger, event brackets and sampled points.
  Events outside the shortened interval are reconsidered on subsequent steps.
- A second scan may change brackets or remove an earlier apparent crossing.
  There is no recursive convergence to the new bracket. Thus this is bounded
  event landing, not proof every root is the final interval endpoint exactly.
- Duplicate detection is contact-specific, and commit sorts by time, contact,
  then kind. Exact simultaneous hammer/damper roots survived the tested case.
- Roots less than the progress floor from an endpoint do not request a split.
  The existing scan can still reject unresolved near-floor behavior explicitly.
- Whole-call `Reference::advance` operates on a copy and assigns it only after
  success. New budget failures cannot publish partly committed mechanics.
- `trial_power_residual_` retains samples from the initial longer trial before
  replay. If its maximum is intended strictly for the committed interval, reset
  it before the shortened trial; this is a diagnostic interpretation issue,
  not evidence of stale mechanical/event state. Legacy maxima are sampled.

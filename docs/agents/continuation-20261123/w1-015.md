# W1-015 — Explicit instrument-model state codec and streams

Implemented and locally tested 2026-11-23 by the assigned worker. This is a
bounded HOST-001 engineering change under the frozen
[filtered audio contract](../../specs/FILTERED_AUDIO_20261123.md) and
[W1-008 compatibility review](w1-008.md). No measured-instrument fidelity,
audibility, native-host, release, or task-completion claim follows from it.

## Scope and result

Changed only these implementation/test paths and this report:

- `include/rhodes/instrument_state.hpp`
- `plugins/vst3/state_stream.hpp`
- `plugins/vst3/state_stream.cpp`
- `tests/cpp/instrument_model_state_test.cpp`

The encoder, decoder, stream reader, and stream writer now take a trailing
`std::uint16_t model = 1` argument. The default is an unconditional literal 1;
no core or stream definition depends on a variant preprocessor definition.
Exactly models 1 and 2 are supported. `InstrumentState`, `StateMailbox`, their
fields, and their behavior were not edited.

The format remains sixteen bytes with `RHST` magic and wire version 1. Bytes
6–7 encode the selected model in little-endian order. Gain/pedal representations
and signed-zero handling are unchanged. Both literal packets for gain 0.5 and
pressed sustain are independently tested:

```text
model 1: 52 48 53 54 01 00 01 00 00 00 00 3f 00 00 80 3f
model 2: 52 48 53 54 01 00 02 00 00 00 00 3f 00 00 80 3f
```

A caller must supply its immutable expected model when decoding or reading.
Cross-model packets are rejected in both directions. Unknown models are rejected
even when the packet and expected argument contain the same unknown value.
Encoding validates before creating an accepted packet; stream writing validates
before its first write. An invalid read model is also rejected before any
`tell`, `seek`, or `read` call. Existing bounded positive short transfers,
seekable exact-length input, and host-owned output sizing are preserved.

Processor/controller calls and CMake registration belong to the integrator and
were not edited by this worker. No Git commands, state-tool commands, claims,
canonical-state mutations, or child-agent spawns were performed.

## New independent test coverage

The new test file is a standalone executable with always-active checks, including
in `NDEBUG` builds. The core build requires only the existing public headers.
Its fixtures use literal golden packets and separate base-256 byte construction,
not production serialization helpers.

| Selector | Scope | Passing checks |
| --- | --- | ---: |
| `model1_golden` | Original literal bytes, default and explicit model-1 API | 7 |
| `model2_roundtrip` | Independent model-2 golden, gain endpoints/subnormals, pedal and signed zeros | 136 |
| `cross_model_rejection` | Both directions, default decoder expectation, caller-byte preservation | 83 |
| `invalid_model` | All 65,534 unsupported 16-bit arguments and wire tags, including nonzero high bytes | 393,204 |
| `malformed_models` | All single-byte header mutations, truncated/extended inputs, invalid binary32 gain/pedal payloads, both models | 8,248 |

Defining the test-only `RHODES_TEST_STATE_STREAM=1` enables additional fixtures
using a direct fixed-storage `IBStream` mock. They do not include processor or
controller types and do not need compiled SDK libraries.

| Additional selector | Scope | Passing checks |
| --- | --- | ---: |
| `stream_roundtrip` | Default model-1 stream APIs, explicit models 1/2, all positive chunk limits 1–16, prefix/guard preservation, exact bytes and transfer counts | 2,212 |
| `stream_invalid_model` | All unsupported model arguments leave bytes, cursor, extent, and read/write/tell/seek counts unchanged | 196,602 |
| `stream_rejection` | Cross-model/unknown/malformed packets, null streams, every shorter input length and one trailing byte, invalid gain rejected before writes | 65 |
| `stream_transfers` | Error, zero progress, negative count and excessive count on first/second transfers, both models; exact completed-write prefix retained | 1,056 |

These stream checks do not claim output rollback after an actual I/O failure:
completed write prefixes remain visible under the existing stream contract.
Invalid state/model arguments make no write at all. Packet rejection does not
restore a reader's cursor after bytes have already been read; state installation
remains the caller's responsibility.

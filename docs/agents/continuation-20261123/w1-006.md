## Proposed CLI and data contract

Add `--extra-step-levels N` to both sweep and auditor, integer choices `0,1,2`,
default `0`; corresponding APIs are `plan(names, extra_step_levels=0)` and
`refinement_gates(runs, *, extra_step_levels=0)`. Keep `STEP_LEVELS` immutable.
The effective sequence appends the first N entries of `(1.25e-6, 0.625e-6)`.
No automatic retry-until-pass, per-fixture depth, or selection of a favorable pair.

Default behavior, original eight runs per fixture, and existing report fields
remain unchanged. In extension mode, retain every original run and append the
extra maximum-step runs plus event/local axes at the declared finest step.
Thus N=1 requires 338 runs; N=2 requires 364, across all 26 fixtures. Subsets
remain useful experiments but cannot establish full acceptance.

Keep candidate run schema version 1. Add optional envelope/manifest
`refinement_policy` containing `version:1`, `extra_step_levels`,
`step_levels_s`, `axis_step_s`, `event_levels_s`, `local_tolerance_scales`,
`output_step_s`, and sorted `required_fixtures`. Include it in the input hash.
Extension auditing requires the explicit flag and an agreeing policy; verify
every listed value against derived constants. Legacy envelopes remain valid
under N=0. Reject inconsistent policies, undeclared finer inputs, nonfinite
settings, and conflicting duplicate setting tuples; deduplicate identical runs
only with recorded provenance. Do not infer the policy from whichever runs exist.

## Gate behavior

Select runs by the complete settings tuple, never input order. The current
auditor's sorting by event tolerance alone leaves tied local tolerances dependent
on input order. For the step axis require event tolerance `2.5e-9 s`, relative
tolerance `1e-8`, absolute tolerance `1e-12`, and output grid `20e-6 s` at every
level. Require matching remaining solver controls and fixture identity.

At N=1 the final comparisons are **5→2.5** and **2.5→1.25 microseconds**;
at N=2 they are **2.5→1.25** and **1.25→0.625 microseconds**. Both differences
must satisfy unchanged observable budgets; the final must be at most 0.8 of
the preceding when resolvable under the existing 128-ulp calculation. Retain all
intermediate differences and event-classification outcomes. Independently audit
each declared finest candidate.

At the new finest step run event tolerances `10,5,2.5 ns` with local scale 1;
run local scales `1,0.1,0.01` with event tolerance `2.5 ns`. Each adjacent
comparison must satisfy the unchanged one-tenth budgets. Compare coordinate
pairs at identical declared settings. Keep original event/local runs and their
results. Nonlinear-solve refinement remains inapplicable to explicit RK4.

Report `frozen_refinement` and `extended_refinement` separately. Preserve the
original failed decision verbatim; an extended decision may supersede its final
pair for the explicitly permitted further-refinement procedure, without deleting
historical failures. Missing required runs means incomplete; generation failure,
invalid evidence, or failed numerical gates means fail. Missing extrema still
prevents full acceptance. Use fresh output directories and retain stdout, stderr,
exit codes, timeouts, hashes, policy, and failed audit reports; never overwrite
archived attempts or exclude failed fixtures.

## Independent continuous extrema

Partition each independent oracle trajectory at geometric/clamp roots, external
actions, and prescribed-motion breakpoints. Within smooth branches locate
compression stationary points from relative speed `w=0`; locate positive-force
stationary points from `dF/dt=w(k+c*w)+c*delta*a_relative=0`. Include endpoints
and both sides of jumps; evaluate hammer and damper separately, including
zero-force plateaus. Damper relative acceleration includes surface acceleration.
Root isolation must handle multiple/even roots and unresolved brackets explicitly;
a sign-change scan alone cannot certify completeness. Independently refine
trajectory, root brackets, and extrema values with the frozen budgets.

Candidate-side continuous evaluation or accepted-step dense polynomials with
validated interpolation error are also needed. Independently search their extrema
and compare to the oracle; candidate diagnostics and 20-us samples cannot bound
missed peaks. Oracle peak discovery alone cannot establish candidate peak accuracy.
This design is not an implemented extrema audit or a mathematical enclosure proof.

## Changes

Added only `observation_node_count = 6`, the opaque fixed-storage
`FractionalObservationPlan`, and the agreed `ResearchEngine` methods:

- `prepare_observation_plan(array<double,6>, plan) const noexcept`
- `observe(plan, node) const noexcept`, returning optional loaded-harp volts.

The plan defaults invalid and binds to an exact host sample rate. Preparation
validates six finite, strictly increasing fractions inside `(0,1)`, calculates
all 73-key/three-mode matrices for both existing loss regimes, then publishes
atomically. Positive IEEE binary64 ordering makes fraction-domain decisions
independent of DAZ/FTZ. It rejects invalid endpoints, nonfinite/negative values,
duplicates and descending fractions while retaining an existing valid plan.

Observation uses node-major prepared matrices, the engine's actual held/pedal
regime, and its existing pickup and complete harp network. It combines modal
motion before the nonlinear pickup. No observation changes modal state or uses
transcendental functions, heap allocation, locks or I/O. All old processing,
oscillator, note/pedal/reset functions remain textually unchanged.

The plan occupies **84,104 bytes** on the tested Linux compiler. Preparation
uses a local candidate of that size; audio observation uses a fixed 73-double
source array. This report makes no measured callback-performance claim.

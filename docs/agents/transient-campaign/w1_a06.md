## Result

Fixed Gauss–Legendre quadrature within each host-frame cell is a viable separate
audio model. It avoids sampling the right limit of an impulse-induced voltage
jump because every note/pedal event lies at a cell boundary and the nodes lie
strictly inside the cell. Existing model-1/model-2 audio and state identities
should remain unchanged. These five exploratory cases do not establish a full
matrix, C++ implementation, real-time cost or physical fidelity result.

The experiment used the unchanged independent `KeyTrajectory` and
`continuous_reference` from `tools/validate_filtered_audio.py`. Candidate Q2,
Q4, Q6 and Q8 rules were built with `scipy.special.roots_legendre`, mapped onto
each unit host cell; their taps were `weight * kernel(cell + delta)` and
normalized by their complete tap sum. Candidate output was compared directly
with the existing Q64 output, including all 4096 frames, every scripted event,
zero prehistory and reset epochs. No gain, delay or onset fitting was performed.

## Causal implementation and delay

Let node `delta[j]` and weight `w[j]` refer to the lag-cell quadrature. For
output frame `n`, compute

```text
y[n] = sum(j=0..Q-1, k=0..95)
       w[j] * K(k+delta[j]) * x(n-k-delta[j]) / N_Q
```

The newest source cell is `[n-1,n)`. At frame `n`, apply ordered events first
(a reset clears all history), form output from previously completed cells,
then evaluate the current interval `[n,n+1)` for subsequent output. For each
phase, retain the source at forward position `1-delta[j]` in a 96-cell ring.
The current cell must not be used in `y[n]`, and the ring index must not add a
second one-frame delay. Symmetric nodes and the kernel centered at 48 preserve
the intended 48-frame linear-phase timing. A strike at `n` affects the current
cell; the integral's isolated endpoint contributes zero measure. Mechanical
diagnostics still end at `n+1`, as with the existing engines.

Advance each mode analytically using matrices prepared outside processing for
both existing damping regimes and every fixed node interval. No callback
trigonometry, adaptive quadrature, dynamic storage or new event queue is needed.
Same-offset event order, release, sustain and retrigger must preserve q/v.
Do not publish the cached output if a later observation or advance within that
host call faults; use the existing zero-suffix/reset-required convention.

## Safe API and cost implications

Do not pretend that the nonuniform nodes constitute a sample rate accepted by
the existing 32–192 kHz API. Keep host-rate validation unchanged and introduce
an explicitly named fractional-trajectory operation with prepared transition
data. Two implementation approaches are possible:

- A dedicated trajectory engine stores the same synthetic constants/state and
  precomputes `Q+1` forward transition intervals. Compare its boundary q/v
  against the legacy engine independently across events and long runs.
- A new wrapper retains the existing engine at host rate, uses read-only
  boundary q/v plus the active damping regime to project to Q nodes, and
  advances the old engine once per host frame. This requires a narrow
  non-mutating accessor for the damping regime; it must not duplicate note
  ownership or infer damping from output samples. It preserves the original
  boundary transition arithmetic, at the cost of another full observation.

Avoid expanding the old oscillator's per-instance cache solely for this new
path. Separate prepared storage keeps model-1/model-2 object cost stable.
Independent Q6 projections require 2 regimes * 219 modes * 6 nodes * 4 doubles,
or 84,096 bytes of matrices, plus 4,608 bytes of phase history. Sequential
Q6-node transitions need seven intervals, or 98,112 matrix bytes if all are
stored per mode/regime. Q8 increases these costs. Matrices need initialization
only at preparation, with fixed regime selection during note/pedal events.

Each frame requires Q complete nonlinear pickup/network observations and
96Q FIR multiply-accumulates (576 at Q6). Modal work is roughly Q projections
plus one boundary advance, versus the old 4/2/1 advances per host sample.
This is an operation-count comparison, not a CPU benchmark: the Q6 cost can
matter particularly above 96 kHz, where the old path used only one advance.
Prototype and measure complete callbacks before preferring Q6 over the
event-correction approach or claiming a real-time improvement.

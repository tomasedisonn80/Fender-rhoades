## Findings

**No actionable callback defect found in the reviewed source.** The review read
the operating contract, current README/state/roadmap, frozen quadrature contract,
wrapper/FIR, fractional observation and oscillator implementation, host adapter,
event processor, mailbox, and retained allocation/fault fixtures.

- Each successful audio frame performs a fixed six-by-96 FIR sum, six
  observations of 73 keys with three modes, and one original-core boundary
  advance. Histories, plans, source arrays and host scratch have fixed storage.
  The host bounds blocks at 4096 frames, notes at 256, and parameter queues at
  two with at most 4096 points each; merged per-frame dispatch is preflighted
  against its 256-entry capacity. The standalone wrapper's span length is
  caller-controlled; the host/event processor supplies its bounded envelope.
- Fractional preparation and oscillator cache misses call transcendental
  functions during setup. `ResearchEngine::prepare` populates both damping
  regimes, so the audio owner's note/pedal/reset operations only select cached
  transitions. `observe` uses arithmetic and finite checks without mutating
  mechanics. Reset and state recall clear fixed history and reuse the plan;
  neither calls preparation. The sizeable candidate engine/plan objects belong
  to preparation, outside `process`, and still require platform stack testing.
- Reviewed project-owned callback paths contain no allocation, stream/file I/O,
  mutex, or retry loop. Instance creation and SDK bus initialization allocate
  outside processing. `StateMailbox` statically requires always-lock-free
  64-bit atomics; each begin/end/abort operation makes a bounded single attempt.
  A competing publication is deferred, rather than retried on the audio thread.
- FIR input validation precedes all ring writes. Output remains provisional
  until observations, core advance and cell retention succeed. Arithmetic
  failure preserves prior published samples and silences the failed sample
  and suffix. Partial mechanical advance is deliberately not rolled back:
  `BasicEventProcessor` latches the fault, and host rejection preserves that
  fence until explicit lifecycle reset or accepted recall. Invalid preparation
  publishes no candidate state; host syntax/ownership preflight precedes recall
  installation and live-state changes.

## Conclusion

`BasicEventProcessor` already dispatches every boundary event in producer order
before a one-frame engine call. It can wrap the proposed quadrature engine
without changing dispatcher semantics. The new engine must preserve the
distinction between source observation in the current cell and output from
previously completed cells. Existing direct/filtered timing remains intact.

## Focused implementation checks

| Case | Required observation |
| --- | --- |
| Strike at frame `n` after silence | `y[n]` remains zero; the current-cell observations contain the strike and contribute from `n+1`. Do not shift the reference or add a second delay. |
| Moving-state retrigger, release, sustain, all-notes-off | Boundary `y[n]` equals an unchanged-history continuation because these events preserve histories. Current-cell observations/future output and mechanics reflect the event. |
| Reset then strike at the same offset | All prior history is gone, `y[n]=0`, and the newly struck motion contributes from the next output. |
| Strike then reset at the same offset | `y[n]=0` too, but future output and modal state remain silent. A test comparing only the reset frame would miss reversed ordering. |
| Queued reset vs external reset | Queued reset clears engine histories/mechanics without rewinding the processor's global cursor. External `processor.reset()` clears cursor and fault latch. |
| Healthy empty block | No events: success with zero processed frames and no history/cursor/state change. Any event, including reset at offset zero, is invalid because no frame exists. |
| Empty block while faulted | No events: existing `reset_required` result is retained. An event is still rejected by preflight before the fault fence. |
| Invalid final event after a valid reset/strike prefix | Entire block rejects before any event executes; histories, prepared plan, q/v, cursor and fault latch remain unchanged; the caller output is zeroed. |
| Six-node observation or boundary-advance failure | Discard even the already-computed past-cell value for the failed frame. Preserve earlier successful output, zero failed frame/suffix, stop work and latch the fault. |
| Fault recovery | A queued reset must not bypass the fence. Invalid preparation must not clear it. Explicit reset or successful preparation permits continuation with cleared histories. |
| Partition changes | Exact output and boundary mechanics must agree for one-frame, irregular and zero-length partitions, including splits at events, ring wrap and support-tail endpoints. |

Use a nonzero-history warmup for rejection/reset tests; comparing only silent
state cannot detect lost history. For observational atomicity, compare a copied
control instance's future output for at least the full 96-frame history as well
as current modal state. Heap-own large Q6 fixtures/copies outside allocation
probes, as identified in A11.

## Host recall and parameter flush

`RhodesProcessor::process` validates host syntax before `begin_block`, then
checks candidate note ownership before `install_recall`. Ownership rejection
calls `abort_block`, preserving a pending valid recall. Extend this existing
test pattern to model 3: queue a valid recall, reject both malformed syntax and
an ownership conflict, then accept a block and compare with a control that
installs that recall exactly once. Histories must not be cleared on rejection.

Also reject model-1/model-2 state while a valid model-3 recall is pending and
compare a subsequent accepted block plus its 96-frame tail. A successful recall
intentionally resets history; it must reuse the prepared observation plan.

A zero-frame VST3 parameter flush is broader than an empty core block: gain and
sustain can update without advancing mechanics/history, and an accepted pending
recall can reset them. Preserve that existing host policy. Monitoring gain is
applied after the delayed source output, so frame-n gain automation can change
`y[n]`; do not confuse this with the source-event invariance described above.

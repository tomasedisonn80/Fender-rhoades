## Decision

**No design blocker found.** The stated algorithm, compatibility boundary and
numerical gates are coherent. Implementation and full-matrix evidence remain
required; the focused Python experiments do not establish C++ correctness,
callback cost, general error bounds or physical fidelity.

## Reviewed relationships

- At output boundary `n`, cell age `k` stores `x(n-1-k+a[j])`. Therefore its
  kernel lag is `k+1-a[j]`, exactly the stated coefficient argument. Emitting
  before inserting the current cell prevents both future-state leakage and an
  accidental extra frame. No point at the event boundary receives finite weight.
- Complementary forward nodes and `c[j][k]=c[5-j][95-k]` make paired lags sum
  to 96, centering the response at 48 frames. Test phase using fractional-node
  sinusoidal sources; an arbitrary single-branch impulse is not by itself a
  proof of the combined fractional-observation delay.
- Normalizing the complete six-branch finite-kernel sum gives unit DC for a
  constant source after history fills. It does not make Q6 identical to the
  continuous kernel integral. The independent Q6 and Q64 comparisons correctly
  distinguish implementation error from quadrature approximation error.
- Source events other than hard reset cannot alter already completed cells.
  Hard reset intentionally discards those cells. Host monitoring gain is applied
  after convolution and can change the current delayed output; sustain changes
  the current source cell and future output. These are different timing paths.
- An output calculated at frame start must remain provisional until all six
  observations and the boundary advance succeed. A later fault must zero that
  frame as well as its suffix, then obey the existing reset fence.
- Keeping boundary state in the original engine avoids duplicating held/pedal
  state. Plan validity/rate checks must occur without changing that state.
  Configuration recall and syntax/cross-model rejection retain the existing
  mailbox transaction boundary, including any pending valid recall.

## Highest-value implementation checks

1. Compare a wrapped ring with an ordinary six-branch convolution across startup,
   95/96/97-frame boundaries and several wraps; verify constant-source DC and
   fractional-source phase with the exact proposed coefficient convention.
2. Check reset-then-strike and strike-then-reset through future samples and q/v,
   since both have zero output on the reset frame. Include rejected blocks with
   warm history and empty calls in healthy versus faulted states.
3. Inject failure at every observation node and at the final boundary advance;
   verify provisional output is discarded and recovery requires explicit reset.
4. Build the Q6 oracle from independent analytic trajectories and SciPy nodes/
   weights, without importing production taps or the generator. Keep the full
   2,097-case plan and both reference refinements; retain all failed cases.
5. Verify all six cross-model rejection directions while a valid recall is
   pending, then verify it applies once; reproduce retained model-1/model-2 WAV
   fingerprints and separately measure model-3 callback allocations/timing.

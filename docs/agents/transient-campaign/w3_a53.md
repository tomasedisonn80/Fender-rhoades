# Wave 3 assignment 53 — analytic peak input contract

## Boundary and fixture identity

Inspected the [native emitter](../../../apps/contact_reference.cpp), both existing
[sweep](../../../tools/run_contact_sweep.py) and
[auditor](../../../tools/validate_contact_reference.py) readers, the
[peak diagnostic specification](../../specs/CONTACT_PEAK_DIAGNOSTICS_20261123.md),
[extrema proposal](../../specs/CONTACT_EXTREMA_AUDIT_DESIGN_20261123.md), and
[A50 findings](w3_a50.md). The four actual fixture names are
`conservative_impact`, `damped_impact`, `forced_clamp`, and `preload_equilibrium`.

**No physical configuration is serialized.** A fixture name cannot attest its
parameters. Bind only these names to independent frozen parameter definitions;
retain their definition hash, producer source/binary identities, complete
settings, duration and initial-state checks. These records still cannot prove
which executable produced arbitrary supplied bytes. Never infer oracle masses,
stiffness or damping from candidate observations. Expected initial zeros should
match exactly; the proposed 64-ULP allowance for other initial components handles
independent floating-point assembly without borrowing a physical error budget.

## Required native fields

Require exactly `schema_version: 1`, `model: "synthetic-contact-p1"`, and `runs`
containing one run. Its exact fields are `fixture`, `success`, `failure_code`,
`samples`, `relaunch_snapshots`, `events`, `diagnostics`, and all eight settings:

```text
maximum_step_s, event_tolerance_s, output_step_s, relative_tolerance,
absolute_tolerance, velocity_absolute_tolerance,
energy_absolute_tolerance, impulse_absolute_tolerance
```

Settings must be positive finite numbers, excluding booleans; preserve the full
tuple. Passing comparison requires literal true success and integer failure code
zero. Retain producer failures separately. The current sweep checks requested
agreement for only five settings; the general reader permits missing optional
settings and aliases, so neither reader alone provides this stricter contract.

Samples require the emitter's exact 26 fields:

```text
time_s, q_m, v_m_per_s, hammer_position_m, hammer_velocity_m_per_s,
hammer_force_n, damper_force_n, hammer_gap_m, damper_gap_m,
hammer_relative_velocity_m_per_s, damper_relative_velocity_m_per_s,
hammer_impulse_ns, damper_impulse_ns, modal_loss_j, hammer_loss_j,
damper_loss_j, hammer_clipped_loss_j, damper_clipped_loss_j,
actuator_work_j, launch_work_j, energy_j, modal_acceleration_m_per_s2,
hammer_acceleration_m_per_s2, instantaneous_power_residual_w,
actuator_power_w, pickup_voltage_v
```

The three modal arrays have exactly two finite components; remaining fields are
finite scalars. Require strictly increasing sample times from zero through the
named fixture's complete duration. Events require `contact`, `kind`, `time_s`,
`bracket_lo_s`, `bracket_hi_s`, `gap_uncertainty_m`, `work_j`; validate contact and
event enums (`hammer|damper`; `onset|separation|clamp_on|clamp_off|grazing`), finite
bounded brackets and nonnegative uncertainty. These fixtures
have no actions: snapshots are empty, and relaunch/motion-change events and
action peak origins are invalid.

Require all 14 native diagnostic fields:

```text
max_abs_cumulative_residual_j, sum_abs_interval_residual_j,
maximum_power_residual_w, initial_energy_j, minimum_accepted_step_s,
maximum_accepted_step_s, accepted_steps, rejected_steps, rhs_evaluations,
analytic_free_evaluations, event_subdivisions, root_iterations,
grazing_candidates, sampled_maxima
```

Preserve `sampled_maxima` separately from continuous candidates; validate its
literal native `scope` and eight contact/quantity value/time fields.
Counters are nonnegative integers excluding booleans;
check scalar finiteness and accepted-step ordering. Optional
`located_peak_candidates` has exactly `coverage`, `evaluation_method`, and four
records: `hammer_compression`, `hammer_force`, `damper_compression`, `damper_force`.
Require the literal metadata:

```text
uncertified_sign_change_search
fixed_interval_anchor_replay_two_rk4_half_steps_or_certified_free_motion
```

Each record has exactly its unit key (`value_m` or `value_n`), `time_s`,
`bracket_lo_s`, `bracket_hi_s`, `origin`. Require nonnegative finite value and
`0 <= lo <= time <= hi <= duration`. A `stationary_candidate` bracket width is at
most `event_tolerance_s * (1 + 1e-9)`; sample/disabled brackets are degenerate.
Do not require an independent root inside a candidate replay bracket: trajectory
error and localization width are different quantities.

## Zero semantics, limits and API

All four hammers are enabled. Only the first three dampers are disabled; their
`disabled` records require exact zero value/time/brackets. Enabled zero maxima
must remain enabled: forced-clamp hammer force has a zero plateau. Preload's
positive damper maximum must not be declared an exact plateau from rounded
equilibrium state alone; A54 supplies its residual/time qualification.

Propose `parse_candidate(raw: bytes) -> ParsedCandidate`, returning immutable
normalized records, raw SHA-256 and explicit availability, without running an
oracle. Absent optional candidates mean `not_available`; present null, partial,
wrong-unit or unknown records are malformed. Unsupported fixtures remain
unsupported. Reject duplicate keys, unknown fields, booleans as numbers,
nonfinite/overflowed values and unbounded integers. Existing JSON readers do not
reject duplicate keys.

Agreed with A52: 32 MiB/file, 128 MiB aggregate, 64 files, 1–30,000 samples and
at most 100,000 events per run. Check byte caps before decoding; convert decoding,
JSON, overflow and recursion errors into bounded malformed outcomes.

# Wave 2 assignment 35 — quadrature study runner regression tests

## Scope and result

Added `tests/python/test_quadrature_audio_validation.py`. The runner, production
code, existing filtered-reference tests, CMake, CI, canonical state and Git were
not changed. This assignment exercised the study protocol, not the full or pilot
waveform matrix. No production defect was observed.

The 16 retained tests cover:

| Area | Tests | Retained behavior |
| --- | ---: | --- |
| Plan and provenance | 5 | Exact 2,097-case / 2,534,400-frame matrix; frozen legacy plan and case-document hashes; 36-case pilot subset; unchanged gates and legacy plan after calls; exact adjacent binary64 rates; help/plans without site packages; CLI conflicts; source additions, byte changes and portable provenance keys |
| Probe interpretation | 4 | Exact model/scheme/rate/nodes/latency; integer metadata without coercion; complete finite sample arrays and signed zero; duplicate keys; malformed/non-object/oversized JSON; NaN/infinity/overflow; forbidden uniform-rate fields |
| Study publication | 4 | Complete artifacts and hashes; refusal to overwrite; exit codes for numerical failure versus unresolved reference; retention of completed rows after interruption/runtime failure; changed source or binary invalidates an otherwise complete run |
| Numerical reporting and arrays | 3 | Independent A/B/refinement statuses; RMS refinement rejection even when peak passes; Q6 reference labels and five-array hash map; input/legacy-plan preservation; exact float64 NPZ retention for unresolved data; malformed/failed probe streams retained before interpretation |

The parser tests isolate only its final array conversion. The short two-case
study tests use explicitly marked protocol stubs for numerical execution and
normalizers; they do not create numerical accuracy evidence. Actual assessment
and NPZ tests use installed NumPy/SciPy and explicitly skip if unavailable.
This keeps 13 protocol tests runnable with only the standard library.

## Commands actually run

```sh
python3 tools/project.py validate
python3 tools/project.py sync --check
python3 tools/project.py next --json
python3 -m unittest discover -s tests/python -p test_quadrature_audio_validation.py -v
python3 -S -m unittest discover -s tests/python -p test_quadrature_audio_validation.py -v
```

The state commands passed: 14 tasks, 16 evidence records, current generated
state, fidelity `unvalidated`; ready work remained claimed by the integrator.

Final normal-environment run: **16 tests passed, zero skips**, 1.351 seconds.
Final `-S` run: **13 tests passed, three explicitly skipped numerical tests**,
1.263 seconds. Both exited zero. The help and both plan CLI subprocesses also
run with `-S` inside the suite.

An initial fixture compared a deserialized JSON plan directly with Python tuple
values and failed in its two plan subcases. The fixture was corrected to compare
canonical document hashes, since JSON represents those tuples as arrays. This
was a test assertion error; the runner's serialized documents were consistent.
The final commands above then passed.

Environment: Linux x86_64, kernel 6.18.57, glibc 2.41, Python 3.12.14,
NumPy 2.3.5, SciPy 1.17.0. Native Windows/macOS execution is not claimed.

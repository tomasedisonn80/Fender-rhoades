# Wave 2 assignment 39 — Quadrature build and CI target review

## Result and scope

Read-only review found no functional gap in the reviewed target or archive
wiring. The working tree was inspected after the integrator registered the
assignment-36 CLI and Linux stdout checks. Only this report was written; no
production, CMake, workflow, project-state or Git mutation was performed.

## Findings

- All three modules retain separate package names, processor/controller FUIDs,
  versions and macOS bundle identifiers. Function-local version settings keep
  quadrature at 0.3.0 without changing direct 0.1.0 or filtered 0.2.0 metadata.
  The conflicting-macro compile guard is present. Generated compiler flags show
  the filtered/quadrature definitions only on their own targets; neither appears
  on `rhodes_core` or SDK targets. Visibility remains hidden for implementation
  symbols and the static core.
- `rhodes_vst3_checks` has 32 direct target dependencies in the generated Linux
  build graph. These include all three modules and benchmarks, the dedicated
  quadrature host fixture, and both loader fixtures. Each module depends on the
  SDK validator. All shared host suites have quadrature targets and registrations.
- The generated Release configuration contains **285 CTests**, including
  **135 `vst3.*` tests**. All 13 selected registrations from assignments 31, 32,
  33 and 36, including the new stdout check, are present with correct commands.
  The five engine selectors and CLI checks run in Foundation CI; the four host
  selectors and two triple-module selectors run in VST3 CI. Triple-module loading
  is explicitly Linux-only. The stdout fixture explicitly selects the quadrature
  executable/model identity and is guarded by Linux `/dev/full` availability.
- Validator commands use `$<TARGET_FILE:validator>` and each SDK package-path
  property, with 180-second limits. CI consistently configures/builds/tests
  Release; the pinned SDK's platform packaging code supports those paths for
  Visual Studio and the selected Unix Makefiles generators. macOS uses distinct
  identifiers and a non-Xcode generator; this is a configuration review, not a
  native macOS result.
- The archive step names all three complete bundle directories. It requires
  native modules, module metadata, SDK license and notices before archiving.
  The tar comparison checks complete entry sets, modes, symlink targets and file
  hashes before upload. Platform-specific suffixes are `.so`, `.vst3` and the
  suffix-free macOS executable. No loose-module upload path is used.
- The state-stream comment now includes model 3 and preserves the documented
  model-1 defaults and rejection policy. User-facing README/build documentation
  still describes two variants; the planned documentation integration should
  add the third variant and its different observation scheme.

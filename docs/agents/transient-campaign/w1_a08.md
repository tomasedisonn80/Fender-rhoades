## Recommendation

Keep `ResearchEngine` as the sole owner of mechanical state, held keys, sustain,
excitation and damping selection. Prepare it at the host rate. Add a separate,
fixed-storage **fractional observation plan** owned by the new quadrature wrapper,
with narrow factory/observation methods implemented in `research_engine.cpp`.
This translation unit already owns the synthetic frequency, decay, observation
and strike constants; do not duplicate those numbers in a second engine.

An illustrative API is `prepare_observation_plan(offsets, plan)` and
`observe(plan, node) const`. The plan holds exactly six offsets in `(0,1)`, its
host-rate identity and the precomputed matrices. It is opaque or privately
constructible so callers cannot inject arbitrary matrices. Default-invalid plans,
rate mismatches and invalid node indices return failure without touching state.
Preparation validates everything into a candidate before publishing the plan.
The quadrature wrapper publishes a prepared core and plan together, keeping
rejected preparation atomic.

Six nodes, two damping regimes, 73 keys, three modes and four matrix elements
require 10,512 doubles, approximately 84 KB, plus small metadata. This storage
belongs only to the new wrapper, not every legacy oscillator. Account for it in
Windows test-stack usage and avoid unnecessary full-engine temporary copies in
the callback.

## Exact node recurrence

For node fraction `delta`, let `tau = delta / host_rate`,
`omega = 2*pi*frequency`, `wd = sqrt((omega-beta)*(omega+beta))`,
`e = exp(-beta*tau)`, `c = cos(wd*tau)`, and
`s = tau*sinc(wd*tau)` with the existing small-angle treatment.
Precompute, separately for free and damped loss:

```text
q_delta = e*(c + beta*s)*q + e*s*v
v_delta = -e*omega*omega*s*q + e*(c - beta*s)*v
```

This is the same analytic transition used by `ModalOscillator`; all transcendental
work occurs during preparation. Evaluate every node directly from the current
boundary state, avoiding chained fractional rounding or inverse transitions.
Select the loss regime from the core's actual `key.held || sustain_` state.
For each key, sum observed modal displacement and velocity before calling the
existing pickup. Feed all 73 resulting voltages through the existing harp,
including electrically silent branches. Do not duplicate held/pedal state in
the wrapper or omit inactive pickup loads.

## Processing order and compatibility

At host boundary `n`, all events for `n` have already been applied in producer
order. The wrapper first computes `y[n]` from histories of completed cells. It
then observes the six nodes strictly inside `[n,n+1]`, stages those values for
future convolution, and advances the core once to `n+1`.

The smallest safe initial implementation can call the unchanged
`ResearchEngine::process()` for one sample and discard that endpoint voltage.
This incurs one redundant pickup/network evaluation but reuses the exact current
state advance, arithmetic-fault behavior and diagnostics. A later dedicated
advance-only operation can be considered if measured cost justifies it.

The fractional observations never mutate core state. Legacy `process`,
`ModalOscillator::advance`, `note_on`, `note_off`, pedal and reset behavior need
no arithmetic changes. The original direct and filtered paths can therefore
retain their output semantics. The plan needs no expanded sample-rate domain:
the host stays inside 32–192 kHz, and the existing highest synthetic mode is
within the 0.45-rate configuration bound even at 32 kHz.

Reset clears the core and all six phase histories. Release/retrigger/pedal
preserve those histories. Any failed observation or core advance zeros the
failed output and remaining buffer and requires the established explicit reset;
do not publish a partially valid phase cell or continue silently.

## Required implementation checks

Verify node q/v against an independent closed form at all supported rate
boundaries and both damping regimes; verify boundary mechanics match a direct
host-rate core under the same event sequence. Retain legacy output regression
checks, rejected-prepare tests, reset/history flushing and allocation checks.
Compare the new voltage record to the existing independently converged Q64
reference without altering latency or fitting onset. These checks are proposed,
not executed by this design assignment.

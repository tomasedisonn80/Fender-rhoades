## Implemented behavior

Only `include/rhodes/quadrature_fir.hpp` and
`include/rhodes/quadrature_engine.hpp` were added as production files.

`QuadratureFir` owns six fixed 96-cell histories. A complete incoming cell is
checked for finite values before any branch or ring cursor changes. Its output
is an ordinary six-branch sum using the generated Q6 coefficients. Startup and
reset have zero prehistory; no allocation, lock, I/O or runtime coefficient
construction is involved.

`BasicQuadratureEngine<Engine>` owns the original mechanical engine, the A21
rate-bound observation plan and the FIR. Preparation validates a candidate core
and plan before publication. Rejected preparation preserves mechanics, metadata
and histories. Reset retains the prepared plan and clears mechanics/history.
Events are forwarded without rebuilding the plan or changing past cells.

Each output frame first calculates the completed-cell convolution, then obtains
all six current-cell observations, advances the original core by one host
frame, and pushes the completed cell. The output remains provisional until all
these operations succeed. A failed node, boundary advance or filter operation
zeros the failed output and suffix; the existing `BasicEventProcessor` supplies
the reset-required fence. Earlier successful samples remain intact.

Public metadata is `sample_rate_hz()`, `node_count()` (six) and
`latency_frames()` (48). The class deliberately has no uniform-oversampling
factor or internal-rate alias. Modal-state and mechanical-energy diagnostics
refer to the authoritative host-boundary core. Legacy source and build files
were not edited by this worker.

The successful run checked:

- 320 frames of ring output against an independent long-double ordinary
  convolution, with absolute tolerance `2e-14`, including several wraps.
- Infinite input in each of six cell positions rejects atomically, followed by
  97-sample continuation comparisons; constant-input DC differs by less than
  `5e-15` after history fills.
- Failure at each of six observation nodes and at boundary advance discards
  the already-nonzero provisional output, preserves the valid prefix and
  zeros the failed sample and suffix.
- Rejected observation-plan preparation preserves a warmed 100-sample future
  trajectory and sample-rate identity. Explicit reset clears histories.
- The event-processor fault fence rejects a queued reset until external reset.
- At 32, 48, 96 and 192 kHz, 193-frame scripts with repeated strikes, release
  and sustain preserve exact direct-core modal boundary states; reset returns
  100 zero samples, and rejected NaN preparation preserves future output.
- A calibrated ordinary/array C++ allocation counter observed zero allocations
  in those audio calls. This is limited smoke coverage, not every allocator or
  a complete VST3 callback measurement.

The first harness compile hit GCC's mismatched-new/delete heuristic in the
scratch custom allocation interceptor. Making its deallocator non-inlined,
following the repository's existing test pattern, resolved that harness issue.
Production warning policy and code were not relaxed.

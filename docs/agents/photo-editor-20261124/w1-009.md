# W1-009 — Native photo geometry foundation

Implemented only `plugins/vst3/photo_geometry.hpp` inside the repository. No Git operations, editor/controller/processor changes, CMake changes, source-image edits, or canonical state changes were performed.

## Result and API

Header-only C++20 namespace `rhodes::vst3::photo`, independent of the VST3 SDK and GUI:

- `Point {x,y}`, `Rect {left,top,right,bottom}`, `Polygon {std::array<Point,6> points; std::size_t size}`. Rectangles and polygons provide `contains(Point)`; polygons provide `bounds()`.
- `kSourceWidth=1536`, `kSourceHeight=1152`, `kFirstMidiNote=28`, `kLastMidiNote=100`, `kKeyCount=73`.
- `key_polygon(index)` returns immutable geometry for key index 0–72; invalid indices return an empty polygon. `hit_key(x,y)` returns that index or -1; MIDI is index + 28. `is_black_key(index)` classifies the valid range.
- Forty-three six-vertex white polygons include sloping top surfaces and front faces. Thirty four-vertex black polygons follow perspective. Exact anchor arrays from W1-003 are retained; rear interpolation and widths are explicitly approximate visual estimates. Black hits always override white hits; shared same-color boundaries select the lower index.
- `kControls`, `control_for_parameter(id)`, `hit_control(x,y)`: IDs 0 volume, 1 pedal, 3 bass, 4 treble, 5 intensity, 6 speed, 7 vibrato/tremolo. Highest numeric priority wins; switch > sliders > padded knobs/pedal.
- `AspectFit::fit(width,height)` returns `{scale,offset_x,offset_y}` with `valid()`, `view_bounds()`, `contains_view(Point)`, `source_to_view(Point)`, `view_to_source(Point)`. One centered aspect-preserving transform serves painting and input. Inverse coordinates are not clamped; letterbox points remain outside. Invalid dimensions/transforms/nonfinite inputs reject safely.

The geometry source is the original 1536×1152 WebP inspected in W1-003, SHA-256 `782b4c83a2bf827ed0d363bc567cdc2211485da6e650db4ae99448e78b7da24b`. Viewed the original directly; no derivative image was created.

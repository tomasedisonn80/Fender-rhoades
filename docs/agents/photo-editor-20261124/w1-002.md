## Observed contracts

`plugins/vst3/plugin_ids.hpp` fixes gain/sustain/expression IDs at 0/1/2, commands at 0x1000–0x100f, immutable models 1/2/3 and latencies 0/48/48. There are 19 parameters. All three variants use the same controller and processor implementation.

`include/rhodes/instrument_state.hpp` stores normalized binary32 Monitoring Gain (default 0.5), Sustain (false), Expression (1). Wire RHST v1 is exactly 16 bytes; v2 is exactly 20, with Expression appended at byte 16. At unity Expression the writer emits exact legacy v1. Decoders reject wrong lengths, models, unsupported versions, invalid numbers and malformed pedal values. Stream helpers are bounded and seekable-stream-only.

The mailbox packs all configuration into one lock-free uint64_t: gain bits 0–31, sustain bit 32, pending recall bit 33, expression bits 34–63. Its begin/end/abort protocol protects newer UI recalls and preflight rejection. It cannot fit five extra independent binary32 controls.

`processor.cpp` validates every parameter/event before changing live state. Continuous gain/expression curves anchor at offset -1 in the audio owner's state; duplicate offsets retain the last point. Zero-frame flushes update final configuration without advancing audio. Accepted recalls reset mechanics/ownership. Rendering first computes `(32.0 * gain) * volts`, checks it, then conditionally multiplies Expression; exact unity skips that multiplication. Stereo duplicates the same scalar as mono. Mechanics continue while expression is zero or output is inactive.

## Recommended parameter and DSP contract

Bind the pictured **Volume** control to existing `kGainId` (0), preserving its normalized range, default 0.5 and digital 0–32x mapping. Retain the generic host label Monitoring Gain; a GUI caption may say Volume. Bind the pedal to `kSustainId` (1). Keep Expression (2) and its global CC11 mapping independent.

Proposed new IDs, to freeze once before implementation:

| ID | Symbol | Normalized default | Proposed synthetic mapping |
| --- | --- | --- | --- |
| 3 | kBassId | 0.5 | -12 to +12 dB |
| 4 | kTrebleId | 0.5 | -12 to +12 dB |
| 5 | kIntensityId | 0 | amplitude depth 0–1 |
| 6 | kSpeedId | 0.5 | 0.5–10 Hz, linear |
| 7 | kVibratoId | 0 | Off/On, threshold 0.5 |

These ranges are proposed synthetic design constants, not measurements of the photographed instrument. Document that the switch enables amplitude tremolo. Preserve scalar mono/stereo behavior; stereo auto-pan would require a separate output-contract decision. Retain all six class UIDs, models, latency and old MIDI mappings.

Add dependency-free `include/rhodes/panel_effects.hpp` with `PanelState`, `PanelValues`, and an instance-owned `PanelEffects` exposing `prepare(sample_rate)`, `reset()` and `process(monitored, values) noexcept`. A transparent, readily testable first version is two first-order shelving blends with fixed synthetic corner frequencies, plus sinusoidal attenuation `1-depth*(0.5-0.5*cos(phase))`. The exact frequencies and smoothing policy must be frozen in the implementation contract. Keep filter/LFO history persistent across blocks; advance the LFO only for accepted audio frames, including inactive output, and reset on the existing lifecycle/recall reset path. Zero-frame flushes do not advance it.

Insert the panel between the existing checked monitored signal and final Expression multiplication. Keep the old monitored operation and fault check unchanged. At neutral EQ and disabled/zero-depth modulation, return the original scalar directly, without identity-filter or unity-multiplication arithmetic. With Expression zero, continue the panel and mechanics but produce zero. Retain finite checks before controls could hide a failure. A filter may keep warm history while its audible branch is bypassed, but this behavior must be specified and benchmarked.

Use fixed storage and explicit parameter indexing: add `kPersistentParameterCount = 8`, total count 24, and map commands to `8 + channel`. Current `collect_parameters` hardcodes `3 + channel`, assumes IDs are array indices and routes all non-gain/non-expression queues to Sustain; all three assumptions must change together. Extend preflight, final flush updates, independent sample curves, controller text validation and host state recall together. The existing 8192-point-per-control and 256-command/event limits should remain explicit.

## Canonical compatibility and mailbox recommendation

Keep `InstrumentState`, existing v1/v2 encoders, `StateMailbox`, and old stream entry points intact as legacy APIs. Add `include/rhodes/plugin_state.hpp` containing `PluginState { InstrumentState instrument; PanelState panel; }` and explicit v3 encode/decode APIs. Add `read_plugin_state_stream` / `write_plugin_state_stream` in the existing stream files and use them in the adapter.

Proposed RHST v3 is exactly **40 bytes**: existing v2 fields retain offsets; normalized binary32 Bass/Treble/Intensity/Speed occupy bytes 20/24/28/32; Vibrato is canonical 0.0/1.0 at byte 36. Keep model bytes 6–7 unchanged. Loading v1/v2 always installs default panel values, even after a previous nondefault session. Saving emits v1 or v2 whenever *all five stored panel values equal their defaults*, using the current Expression rule; otherwise emit v3. Do not discard changed Speed/Intensity just because Vibrato is off. Old builds reject v3 rather than receiving a mislabeled legacy chunk.

Use one **coherent extended configuration transaction**, not separate independent core/effects recalls. Do not widen `std::atomic<InstrumentState>` or use atomic128 without a proven lock-free platform guarantee. Recommended new `PluginStateMailbox` API: `request_recall`, `try_snapshot`, `begin_block`, `end_block`, `abort_block`, with the same newer-recall precedence and preflight restoration semantics. A viable bounded implementation direction is a fixed pool of immutable state slots, atomic reader pins/write ownership and a generation-tagged atomic publication token. Readers pin before copying and revalidate the token; writers never reuse pinned slots. No audio-side wait/retry loop, mutex, allocation or stream call. Exhaustion/contention must have an explicit bounded failure result; a getState failure must occur before writing bytes. Retain existing core mailbox tests unchanged and independently review/test this new protocol before integration. This is a design recommendation, not a concurrency proof or validated implementation.

- `docs/VST3.md` and a new panel/editor implementation contract: synthetic scope, mappings, format and old-build rollback boundary.

Meaningful regressions:

1. Exact neutral/default audio against unchanged baseline for all three models, float/double, mono/stereo, gain/expression automation, old v1/v2 recalls, inactive output and partitioned blocks. Retain old WAV/legacy-capture oracles rather than deriving expected output from new code.
2. Golden v1/v2 byte identity; hand-authored v3 packets; exact lengths; cross-model rejection; all nonfinite/out-of-range/negative-subnormal inputs; signed-zero canonicalization; short transfer and stale-trailing-byte rejection; malformed recall must leave both controller and processor untouched.
3. Deterministic whole-state concurrency interleavings, newer recall wins, abort restoration, no mixed generation, pinned-reader/writer contention and bounded failure, no stream calls or allocations on audio thread.
4. Independent analytic shelf magnitude/DC/high-frequency checks, tremolo rate/depth/phase checks, deterministic reset, no extra latency, sustained histories under bypass/inactive output, finite extreme settings across 32–192 kHz.
5. Every new queue at capacity, duplicate offsets/queues, late invalid final points, zero-frame behavior, output omission, and unchanged note/CC123 budgets. Existing expression, mono, command, stream, fault and allocation tests remain regression gates.
6. GUI binding tests should verify beginEdit/performEdit/endEdit, host-driven repaint and close/reopen recall. Keys must enter the bounded note/ownership path with explicit GUI ownership; never call engine methods from the UI thread. A GUI key release must not release a simultaneously held external MIDI owner.

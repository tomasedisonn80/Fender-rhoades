# W2-001 — Native Linux photo-editor interaction harness

## Scope and ownership

Assigned by the HOST-004 integrator: create `tools/verify_native_photo_editor.py`,
exercise the actual direct VST3 bundle, and retain native images, callback logs,
quantitative outcomes and source identities. No canonical state, Git, production
editor, shared CMake, shared SDK or original host-build files were changed.

The integrator subsequently authorized a separate diagnostic host under
`/home/agent/rhodes-7a7c13ab7da3/w2-001`. It is an isolated copy of the pinned
SDK's `editorhost.cpp` with only three callback method bodies changed. This is
an editor integration fixture, not a DAW or an audio-processing host.

## Outcome

The actual native child attaches at **1024 × 768**, resizes to **1536 × 1152**,
and reproduces the supplied PNG's decoded RGB pixels **exactly** at full size.
Both the unmodified SDK host and the accepting diagnostic host establish this.
All successful observed editor parameter gestures are paired in the diagnostic
log, including teardown while a Volume drag remains held.

The native-focus integration result remains incomplete. Both hosts exhibit a
native focus-forwarding gap: real FocusOut events reach the editor child and its
host top-level window, but a held photographed key remains highlighted and the
accepting host does not receive endEdit before the pointer is released. A
separately labeled **direct XEMBED_WINDOW_DEACTIVATE probe passes**: the editor
ends the held Volume gesture before release and clears the held-key visual to
the exact reference. These results demonstrate the editor's response to explicit
deactivation and preserve the separate native-host focus-delivery gap. They do
not establish two independent plug-in defects, and the direct protocol probe
does not close the native-host/DAW focus gate.

No audio processing, acoustic output, processor note-release timing, hardware
deadline or DAW operation was exercised or claimed.

delivery in both the tool and the JSON.

### Original SDK host boundary

The pinned SDK's ComponentHandler returns `kNotImplemented` from beginEdit,
performEdit and endEdit. The plug-in correctly declines edits when beginEdit is
rejected. The original Release host also compiles out SMTG_DBPRT callback logs.
Its empty `editorhost.log` is therefore retained as **no callback observation**;
it is not interpreted as successful parameter editing. Its successful native
attachment, resize, pixel comparison and closure remain independently useful.

# W1-006 — Extended state mailbox design audit

## Scope and inspection

Read the repository operating contract, README/current project state/roadmap and canonical task context, then inspected `include/rhodes/instrument_state.hpp`, the processor state and transaction paths, and the existing state/expression/concurrency fixtures. This is a design review only. No implementation or canonical project-state edits, build, or tests were performed. The only written path is this worklog.

## Recommended independent type

Keep `InstrumentState`, its codecs, `StateMailbox`, and their exact packed-token tests unchanged. Add an aggregate `PluginState { InstrumentState instrument; FrontPanelState panel; }` and a separate `PluginStateMailbox`.

Store a fixed atomic integer payload, for example one `atomic<uint64_t>` containing the existing packed instrument triple and five `atomic<uint32_t>` containing the normalized panel values. Alternatively eight explicit 32-bit words are equally valid. Do not store shared ordinary floats and rely on a seqlock to excuse concurrent access: that is a C++ data race. Assert that every employed atomic word type is always lock-free.

Use a 64-bit atomic guard: bit 0 is temporary writer ownership, bit 1 is pending recall, and the upper 62 bits are a monotonically increasing revision. Every successfully completed writer operation, including a successful begin operation and identical-value recalls, advances the revision. Compare the complete guard, never the state value or pending flag alone.

For the first implementation, make guard and payload atomic operations sequentially consistent. This gives a direct total-order coherence proof for snapshots. Relaxing individual payload operations requires a separately reviewed C++ memory-model proof; release/acquire labels alone are insufficient justification.

## Bounded audio transactions

`begin_block()` loads a stable guard, rejects immediately if busy or revision-exhausted, and makes exactly one strong CAS to set busy. On failure return a default token with `may_publish=false`; do not retry. On success copy the fixed payload, release a fresh stable revision preserving the pending flag, and return that revision with the decoded coherent state, `apply_recall=pending`, and `may_publish=true`. The busy interval contains only the fixed payload loads and guard publication. It ends before ownership preflight, DSP, engine reset, host calls, or any other extensible work.

**Defer consuming pending until successful end.** Begin selects a recall but leaves its pending flag set. This makes `abort_block()` a no-op: a rejected transaction never consumed anything, so there is nothing to restore. The existing processor preflight sequence still applies: all syntax validation precedes begin; ownership preflight precedes installing recalled mechanics; rejection returns without modifying audio state.

`end_block(token, state)` first checks token validity and all state values. It makes exactly one strong CAS from the exact returned stable revision to its busy form. On failure return false with no writes. On success store all fixed payload words, then publish the next stable revision with pending cleared. No retry loop, allocation, mutex, yield, sleep, or callback belongs on either audio path. No writer ownership survives a method return. Invalid end input must leave the token usable for a subsequent valid end.

If end cannot publish, the only concurrent writer is a newer recall transaction. Its payload remains pending; a later block selects it. An identical new recall still advances revision and cannot be overwritten by an old end token. A failed begin does not prevent processing with the audio owner's previous live configuration, but its token forbids publication.

## Non-audio operations and coherence

`request_recall(state)` validates/canonicalizes the complete aggregate before acquiring ownership. All seven normalized float fields use the existing integer-bit validity rules, preserve positive subnormal encodings, and canonicalize either zero sign to positive zero. It may retry the guard CAS off the audio thread; the CAS serializes multiple concurrent callers. Once acquired, it writes the complete fixed payload and publishes a new revision with pending set. This is last-committed-writer-wins, including identical values. Invalid requests change nothing.

`snapshot()`/getState may retry off the audio thread: load stable guard, copy every atomic word, load guard again, and accept only when both guard values are identical and nonbusy. With sequential consistency and no guard reuse, an accepted payload cannot straddle a writer. Snapshot does not consume recall and returns the newest committed complete configuration, pending or applied. Never call this retrying API from the processing callback.

A descheduled writer may postpone non-audio readers/writers; audio immediately skips its one attempt and never waits. This is bounded callback work, not a guarantee that a contended non-audio operation completes in bounded time.

## Revision exhaustion and API compatibility

Never wrap the 62-bit revision. Check exhaustion before every attempt to acquire writer ownership and fail closed while retaining the last complete snapshot. Reserve/reset only through an externally synchronized lifecycle with no outstanding readers or tokens; do not silently reset during normal use. An explicit no-wrap policy prevents theoretical ABA even for indefinitely retained tokens.

One audio owner and at most one active block token remain the contract. The new token layout need not equal `StateMailbox`'s literal packed values. Preserve processor-facing legacy accessors by returning `.instrument` from `current_state()` and `published_state()`; new full-state accessors may be added separately. Keep snapshot out of real-time internals. State-format migration belongs in a separate codec, not in mailbox ownership.

## Focused implementation checks

Add tests for complete aggregate snapshots under concurrent writers, identical-value and A→B→A recalls between begin/end, pending preservation after reject, busy-guard one-attempt deferral, invalid panel values with an existing pending recall, a stale end racing a newer recall, multiple non-audio producers, canonical negative zero/subnormal preservation, and near-exhaustion no-wrap behavior using a narrow test seam. Retain all existing InstrumentState/StateMailbox tests verbatim. Deterministic barriers belong only in test harnesses. Source inspection should verify fixed loop bounds and absence of retrying snapshot calls in audio code; stress tests alone do not prove boundedness or memory ordering.

## Findings

No new concrete regression identified.

- Ordinary mouse-down cancels only the local interaction. Shared-key release/close clears that owner's slot and emits one ordered up only after the last holder leaves; distinct and idle siblings remain unaffected.
- Allocation, attribute, and send failures clear controller ownership and retain emergency cleanup until a successful send. Recovery calls reject their attempted fresh down. The existing fixture exercises these failures, signed zero, subnormal velocity, stale tokens, 32-owner capacity, uint64 exhaustion, and termination/reinitialization.
- Full registration returns zero without changing holders. Tokens never recycle; wrap permanently disables registration. A view created without a token remains unavailable for its lifetime.
- Removal and close cancel interaction before view destruction; destructor unregisters idempotently. The SDK editor retains its controller through an `IPtr`, and PhotoEditor closes its frame before base destruction. No normal teardown dangling-reference path found.
- Processor release consults MIDI ownership at block entry; MIDI releases are suppressed while UI holds the key. Shared sustain is untouched. Queue operations are SPSC, bounded, allocation-free, with at most 256 copied commands and 73 emergency releases; controller scans remain UI-side.

## Limits

The previously documented emergency epoch can cancel a later down in the same captured batch; there is no processor acknowledgement. If every final-view teardown retry fails, pending cleanup has no remaining view idle callback and awaits another service/reopen/termination opportunity. Source inspection does not establish native-host execution, callback serialization, externally retained detached-view lifetimes, or audio deadlines. Existing tests were inspected, not executed.

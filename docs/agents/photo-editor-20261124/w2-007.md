## Changes

- `plugins/vst3/photo_editor.cpp`, PhotoEditor sizing methods only: content-scale
  changes now call the available **IPlugFrame**, including before native CFrame
  attachment. `rect` remains old until synchronous host `onSize`; no-IPlugFrame
  changes commit through `onSize` directly. Refused, malformed, or missing changed-size
  notifications restore the old scale, zoom, and public rectangle. A same-size
  successful request may omit `onSize`, as permitted by the SDK. Nested scale
  negotiations are refused while the current change is in progress.
- Native CFrame zoom changes occur inside `onSize`. The new `beforeSizeChange`
  guard accepts that already-authorized native update without calling the host
  again. The SDK pending-size check runs before native mutation.
- `tests/cpp/vst3_photo_editor_test.cpp`: SDK-only recording IPlugFrame fixture,
  bound and detached with stack lifetime. The real-module test now exercises
  accepted/refused scale changes, old/new `getSize` ordering inside `resizeView`,
  invalid/missing `onSize`, refusal after an accepted notification, unchanged-size
  acceptance without a notification, invalid scale filtering, nondefault user
  zoom rollback/retry, and absence of resize echoes for unattached host resizes.
  The existing six live controllers, three bundle identities, sibling-view
  independence checks, and no-native-window boundary remain in place.

## SDK basis

Pinned root: `/home/agent/rhodes-7a7c13ab7da3/vst3sdk`.
`pluginterfaces/gui/iplugviewcontentscalesupport.h` requires `resizeView` once an
IPlugFrame exists; its direct-size exception applies before that frame is set.
`pluginterfaces/gui/iplugview.h` specifies synchronous `onSize`, old `getSize`
before that callback, and platform resizing only inside `onSize`.

The source path for the redundant native request is concrete:
PhotoEditor `onSize` → CFrame `setZoom` → CFrame `setSize` → VST3Editor
`beforeSizeChange` → IPlugFrame `resizeView`. The previous PhotoEditor called
VST3Editor `onSize` only afterward, so its SDK `sizeRequest` guard was not yet
active. The new guard cuts that request path while applying `onSize`.

## State and lifecycle

Replaced the legacy mailbox with `PluginStateMailbox` while retaining separate
audio-owned `live_state_` and `live_panel_` fields. Every existing successful or
accepted-fault publication now passes the complete `{instrument, panel}` value
through one mailbox transaction. The callback only uses bounded `begin_block`,
`end_block`, and `abort_block`; its path never invokes the retrying snapshot API.
The non-audio `getState` and `published_state` paths may still snapshot.

`current_state()` and `published_state()` still return InstrumentState, as before.
`current_panel_state()` supplies suspended/audio-owner diagnostics for the new
configuration. `getState`/`setState` now use worker012's complete-state stream
helpers with the original immutable `kStateModel`.

`install_recall(PluginState)` resets the synthesis engine, note tracker, effect
histories, smoothing state, phase and fault latch, and applies the complete recalled
configuration. Lifecycle reset uses the bounded mailbox token's pending recall
when available, otherwise the current audio-owned complete configuration. Effect
preparation is performed on a small local copy before engine preparation commits,
preserving setup rejection behavior. Panel-effect faults participate in
`requires_reset()`.

Zero-frame calls update and publish all eight persistent parameters using the
existing preflight and fault policy. They do not advance effect time or clear
effect histories; changed targets enter the effect's smoothing path on the next
rendered sample.

## Automation and bounded storage

Bass, Treble, Intensity, Speed, and Vibrato use public IDs 3, 4, 5, 6, and 7. Queue
uniqueness slots 0..2 and 3..18 retain the legacy instrument and channel-command
mapping. The panel controls use slots `19 + (id - 3)`, with a total limit of 24
queues. Each new raw queue is rejected above 8,192 points before point traversal.

All input is copied and validated before a mailbox recall is consumed or any
live configuration, ownership, mechanics, or effects are changed. The four
continuous controls use the same previous-sample anchor and endpoint interpolation
convention as the legacy continuous controls, with canonical binary32 values.
Vibrato uses Sustain's discrete `>= 0.5` switch convention. Duplicate offsets
replace the entire prior endpoint, so the last supplied point wins before any
interpolation is performed.

One constructor allocation owns the five fixed point arrays and their counts
through `unique_ptr<PanelParameterScratch>`. The additional approximately 320 KiB
of point storage does not enlarge stack-resident processor instances. There are
no process-time allocations introduced by the implementation.

## Audio behavior

The existing monitored signal remains `(32.0 * gain) * volts`, with its original
finite/failure checks. FrontPanelEffects runs immediately afterward and before
Expression. Both effect channels must be finite before attenuation is allowed.

Stereo output retains the two effect channels. Mono returns the left sample
unchanged when both channel encodings match, preserving signed zero and neutral
sample bits; otherwise it uses `0.5 * left + 0.5 * right` to avoid overflow from
adding the full-scale finite channels first. The negotiated layout also governs
conversion when an inactive output is omitted.

Expression retains the exact unity bypass and legacy multiplication order for
neutral output. Both channel conversions are checked before either channel is
written for the current frame. Existing accepted-fault publication, retained
valid output prefix, and explicit-reset policy are preserved. Effects introduce
no additional reported latency. This is the existing documented synthetic effect,
not an identified physical tone/modulation circuit.

## Exact SDK finding

There is no generic desktop VST3 `editFromUI` or host note-injection method in the inspected interfaces.

| Interface/API | Actual purpose | Keyboard suitability |
| --- | --- | --- |
| `IComponentHandler::beginEdit`, `performEdit`, `endEdit` | UI-thread parameter editing through host | Correct for knobs/pedal; possible gate fallback below |
| `IEditControllerHostEditing::beginEditFromHost/endEditFromHost` | Host-to-controller notification around external helper-parameter edits | Not a UI-note sender |
| `IMidiMapping::getMidiControllerAssignment` | Incoming MIDI CC to parameter mapping | Preserve current CC11/64/123 mappings; not note injection |
| `IMidiLearn::onLiveMIDIControllerInput` | Incoming live CC notification for learning mappings | Not note injection or note highlighting |
| `IEventList::addEvent` | Add to a process-call event list | Does not expose host input events to a controller; never retain/process host lists from UI |
| `IInterAppAudioHost::scheduleEventFromUI(Event&)` | Optional Inter-App Audio wrapper scheduling | iOS wrapper-specific; not a desktop-host fallback |
| `IConnectionPoint::notify(IMessage*)` | UI-thread communication between separate components, possibly through a host proxy | Recommended desktop private-note transport |

## Recommended implementation

1. In the controller UI thread, use inherited `ComponentBase::allocateMessage()`, `IMessage::setMessageID()`, typed `IAttributeList::setInt/setFloat`, and `ComponentBase::sendMessage()`. Release the message using the SDK ownership helper. A versioned message carries key index `0..72`, down/up action, finite normalized velocity, editor-session identity, and monotonically ordered sequence. Transfer values only; no process addresses or custom-interface casts. The SDK explicitly warns that the peer may be a proxy. This supports separated controller/processor processes without shared memory.
2. Override processor `notify(IMessage*)` on its UI thread. Validate message ID/version, all attribute results and ranges, then copy a small POD command to an instance-owned, fixed-capacity SPSC queue. Do not touch `notes_`, `engine_`, `live_state_`, or other audio-owned state from `notify`. IMessage allocation/attribute work stays off the audio thread.
3. Audio `process()` stages a bounded queue snapshot only after host syntax validation. Preflight host and UI ownership and resulting dispatch bounds before committing either. Consume only commands included in the accepted transaction; a rejected host block must not silently lose queued note-offs. Assign live UI notes offset zero of the next accepted positive-frame callback, and document a deterministic tie order. Existing host-note order remains unchanged. This is block-quantized live audition, not host-timestamped MIDI recording.
4. Use lock-free atomic indices, release/acquire publication, fixed storage, and static assertions for required atomic lock freedom. Drain at most the fixed queue capacity; no retry loop, allocations, mutexes, SDK messages, logging, or UI callbacks from audio.
5. Treat overflow as a specified ownership event. Never accept a down that cannot be enqueued. A failed release must set an out-of-band bounded cleanup request/epoch; audio clears only that UI session's owners and discards older queued downs. Merely dropping an off or clearing the queue can leave stuck keys. Freeze the epoch/queue ordering design before coding and test its races.

Neither the private messages nor parameter gates guarantee that the DAW records mouse notes as MIDI. That is a separate host capability, and the UI should not promise it. Audio also requires the host to process the instrument; `restartComponent()` is not a generic audio-start command.

## Preserve external MIDI ownership

Do not reserve an arbitrary VST note ID or MIDI channel for the editor. Current `NoteTracker` accepts all 16 channels and every int32 note ID except the special anonymous `-1`; a purported reserved ID can collide with host events.

The lowest-impact implementation keeps the existing host `NoteTracker` unchanged and adds fixed UI ownership per physical key/session. Apply physical note-ons for every accepted strike. Emit a physical note-off only when the aggregate host/UI holder count becomes zero. Suppress host/CC123 physical release while a UI owner remains; suppress UI release while a host owner remains. Preserve sustain and ringing mechanics. Alternatively extend the tracker identity with an explicit source domain; matching and source-scoped cleanup must both include that domain.

Release UI owners on mouse-up, drag-to-other-key before the new down, pointer cancellation/lost capture, editor removal, and disconnect. State recall/lifecycle reset clears UI ownership and invalidates older queued downs. Never implement editor-close cleanup as engine panic or MIDI CC123, because either can disturb external notes. Black-key zones must win hit testing before white-key polygons; map photo zones directly to MIDI `28 + key_index` (E1–E7).

## Requested fallback: 73 hidden parameter gates

If message allocation/connection or a versioned handshake fails, a real playable fallback can use 73 stable gate ParamIDs delivered by the host's mandatory parameter route. Select one transport for a session; never send the same strike through both. Switch only after releasing old UI ownership.

- Register one zero-default parameter per key. `stepCount=1` gives a simple gate with a fixed audition velocity. Use `ParameterInfo::kIsHidden`, omit `kCanAutomate`; note that the SDK defines hidden as also read-only to outside callers. Internal plug-in UI changes are the intended source. Actual host delivery of these edits still needs verification.
- Down: `beginEdit(id)`, controller `setParamNormalized(id,1)`, then `performEdit(id,1)`. Up/cancel: `setParamNormalized(id,0)`, `performEdit(id,0)`, then `endEdit(id)`. Pair every successful begin with end; handle return failures visibly and perform ownership cleanup.
- Decode `ProcessData::inputParameterChanges` into preallocated gate changes. Gate values are stepped ownership levels, not interpolated amplitudes. Rising edge strikes, falling edge releases under the aggregate ownership rule above. Keep gates transient and excluded from the saved instrument chunk; reset on recall/lifecycle. A zero-frame flush may release ownership but should defer new strikes until positive-frame processing under an explicitly revised contract.
- Update the current 19-queue acceptance ceiling, ID validation, scratch sizing, and dispatch preflight deliberately. Bound aggregate gate points, not 73 times 8192. Preserve existing gain/expression/sustain and CC123 semantics. Saturated host input plus UI traffic needs a defined defer/reject policy that cannot discard offs.

This fallback is useful, but is not event-equivalent: parameter queues represent curves, and hosts may coalesce quick down/up or repeated equal values. A complete tap between process calls can disappear. Per-key gates also expand the public parameter inventory even when hidden. Therefore the robust primary transport remains IMessage with a queue; use gates as a tested host compatibility fallback rather than a promise of exact retrigger preservation. The pinned `ivstparameterchanges.h` explicitly defines curve/implicit-point semantics.

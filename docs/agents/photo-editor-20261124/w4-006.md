## Runner and dependency decisions

The runner adapts the retained task-local `with-xvfb.py` design: it allocates an
ephemeral TCP display, creates a private temporary directory and 0600 authority
file, starts Xvfb with cookie authentication, and verifies readiness with
`xdpyinfo`. TCP supports the current sandbox, which does not permit Unix X
sockets. There are no hardcoded task paths in the committed runner.

The cookie is delivered to `xauth` on stdin, never in its argument list. Xauth
output is suppressed. The temporary Xvfb log is printed only on startup errors,
with the cookie redacted, and removed with the temporary authority directory.
The child receives its own `DISPLAY` and `XAUTHORITY` environment.

Startup, including authentication, is bounded to 10 seconds; the test has a
30-second limit; CTest has a 60-second outer limit. Child and Xvfb processes run
in their own process groups. Finalization sends TERM, waits at most 2 seconds,
then sends KILL to remaining members and reaps the owned processes. SIGINT and
SIGTERM unwind through this cleanup. Ordinary child exit codes are retained;
signal deaths map to shell-style `128 + signal`; timeout returns 124; startup
errors return 1. No missing-tool condition is a skip or successful test.

Linux editor test configurations require these tools at CMake configure time:

| Executable | Cache override | Debian/Ubuntu package explicitly installed in CI |
| --- | --- | --- |
| Xvfb | `RHODES_XVFB_EXECUTABLE` | `xvfb` |
| xauth | `RHODES_XAUTH_EXECUTABLE` | `xauth` |
| xdpyinfo | `RHODES_XDPYINFO_EXECUTABLE` | `x11-utils` |

Missing discovery causes an actionable fatal error describing the packages,
the three overrides, and `BUILD_TESTING=OFF` for builds that intentionally omit
tests. The workflow now triggers on `tools/run_xvfb_test.py`. These exact
decisions were sent to the root integrator for the separate dependency-doc worker.

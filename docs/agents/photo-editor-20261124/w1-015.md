## Public API and ownership

`rhodes::EditorAuditionCommand` contains `int key`, `bool down`, and
`float velocity`. Keys are physical indices 0..72, and velocity is validated
in the inclusive normalized range using the existing integer-bit control
validator. Both signed zeros and positive subnormal values are accepted and
preserved; out-of-range values, infinities, and both quiet/signaling NaNs are
rejected without floating-point exceptions or queue mutation.

`rhodes::EditorAuditionQueue` has capacity 256 and provides:

```cpp
bool enqueue(EditorAuditionCommand) noexcept;
void request_release_all() noexcept;
Snapshot peek() const noexcept;
bool commit(const Snapshot&) noexcept;
void discard() noexcept;
```

`Snapshot` exposes `commands` (a 256-entry array), `count`, `read_begin`,
`read_end`, and `release_epoch`. Production cursors and epochs are `uint64_t`.
Private provenance/boundary fields reject foreign, stale, default, or altered
snapshot commits. The snapshot owns its copied commands, so later ring reuse
cannot change a previously captured batch.

Exactly one serialized UI/SDK-notify producer calls enqueue/release. Exactly one
audio consumer calls peek/commit/discard. A lifecycle thread may take consumer
ownership only with audio stopped. Multiple producers or concurrent reset/audio
consumers are unsupported; the integration must maintain this SPSC contract.

The producer writes only unowned free ring slots. A release-store of the write
cursor publishes them to the consumer's acquire-load. The consumer's
release-store of the read cursor relinquishes slots after copying/processing;
the producer acquire-loads that cursor before reuse. Slot payloads are ordinary
objects with exclusive access, not concurrently read/written non-atomic data.
Atomics are required to be always lock-free. There are no allocation, lock, wait,
spin, compare-exchange, or retry operations. The only transport loop copies at
most 256 commands.

## Transaction and emergency-release contract

1. Audio calls `peek()` before host-block preflight. `peek()` samples the release
   epoch **before** the published write cursor. Acquiring an epoch therefore
   includes every command published before that release in the captured prefix.
2. Preflight and process the copied commands against UI-owned note state. Then
   release all UI-owned notes if the snapshot epoch differs from the audio
   consumer's own applied epoch. Release wins over the entire captured batch,
   including a racing down that happens to enter the same snapshot.
3. On success, commit that snapshot and record its epoch as applied. Abort does
   neither, so both commands and release remain pending for retry.

A full queue rejects the attempted command and publishes an emergency-release
epoch. This gives a dropped final key-up a bounded, out-of-band way to release
all audition holders. No shared Boolean is cleared, so a release arriving
between peek and commit remains pending. A successful prefix commit does not
consume any later producer commands. `discard()` discards only its sampled
prefix for reset and never clears the release epoch.

The transport does not own MIDI or sustain. The processor integration must
release only UI-owned holders and preserve external MIDI holders and sustain.
That integration was not implemented or tested in this assignment.

Cursors never wrap. At cursor exhaustion, enqueue rejects and requests release.
The release epoch saturates; at its maximum no further enqueue is accepted.
Because no down can follow the terminal epoch, the ordinary audio-side epoch
inequality remains sufficient. An exhausted transport must be reconstructed
while both owners are stopped; discard does not reset sequence IDs. Tests use
the same implementation specialized to a 16-bit counter to execute these
otherwise impractical exhaustion paths without adding a mutation/test hook to
the public API.

   later writes retained, reset discard, and independent instance state.

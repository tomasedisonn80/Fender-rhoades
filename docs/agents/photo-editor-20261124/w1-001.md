# W1-001 — VSTGUI integration audit

Date: 2026-11-24. Scope: bounded read-only review of the controller, CMake integration, required project state/docs, dependency provenance, CI and bundle checks. No implementation, canonical state, or Git changes. This report is the only written artifact.

## Findings

- `plugins/vst3/controller.hpp` derives directly from `EditController` and `IMidiMapping`; it has no `createView` override. `controller.cpp` exposes 19 parameters: Monitoring Gain (`0`), Sustain (`1`), Expression (`2`), and 16 transient channel commands (`0x1000..0x100f`). The three configuration parameters already participate in state recall and notifications; custom visuals should bind to those parameter objects.
- `cmake/Vst3.cmake` forces `SMTG_ENABLE_VSTGUI_SUPPORT=OFF`, compiles the same controller directly into production modules and numerous headless tests, and packages distinct per-target resource staging copies to avoid SDK copy-command collisions. Preserve this staging pattern for image, UIDescription and notices.
- Current SDK is `v3.8.1_build_84`, root `3cdf9ca5d1f5b1b21e0a86832aa4abe55607bd96`. Its VSTGUI gitlink is `5db272256172557818b6158cf0bb2c4410bddb25`. Existing CMake verifies root and four submodules, but not VSTGUI. Existing notices explicitly exclude GUI dependencies.

## Recommended implementation

1. Add an explicit optional editor build switch inside the optional VST3 integration. Verify a clean VSTGUI checkout at the existing SDK gitlink before enabling SDK GUI support. Keep default dependency-free core and an explicit headless VST3 build available. Do not upgrade the SDK merely to add the editor.
2. Add `createView` returning the photo editor only for `ViewType::kEditor`; unknown/null names return null. Keep VSTGUI implementation in a separate translation unit, with a narrow per-target definition selecting the GUI branch. Existing headless controller tests should not gain native-window dependencies. Compile the editor source into all three GUI module targets and dedicated GUI tests.
3. Link the SDK-created `vstgui_support` target rather than assembling its sources manually. It includes VST3 parameter bindings, Windows bundle support, and Linux runloop support. Use `VSTGUI::VST3Editor` with UIDescription; the pin also contains `AspectRatioVST3Editor`, suitable for preserving the photo proportions.
4. Use the supplied original photo as the reference bitmap and preserve its framing, perspective, colors, labels and aspect ratio. Align hit regions and carefully masked moving controls to its coordinates. A themed approximation or unrelated redraw cannot satisfy an exact-photo requirement. This worker did not inspect or modify the image.
5. Bind controls through ordinary VST3 parameter tags and begin/edit/end gestures so host automation, touch/write, generic controls and state recall stay synchronized. Do not call audio processing from the UI. Photographed controls without a real corresponding parameter/DSP path need a separately specified implementation and versioned state extension; relabeling Expression or Monitoring Gain as an unrelated tone/vibrato function is insufficient. Preserve existing IDs, model IDs and legacy state decoding.

## Pinned dependency details

Upstream files were inspected through the GitHub read-only connector. VSTGUI has its own BSD-style three-clause notice, distinct from the SDK MIT notice; retain its complete `LICENSE` and inventory linked embedded dependencies before packaging. `VSTGUI_UISCRIPTING` defaults ON: explicitly disable it unless Tiny-JS scripting is required. SDK examples stay disabled.

At this exact pin, Linux CMake requires **Wayland client/server/protocols even with Wayland UI support disabled**, plus X11, FreeType, pkg-config, xcb, xcb-util, xcb-cursor, xcb-keysyms, xcb-xkb, xkbcommon, xkbcommon-x11, glib-2.0, cairo, pangocairo, pangoft2 and fontconfig. Keep `SMTG_ENABLE_WAYLAND_SUPPORT=OFF` for the initial scope: enabling it also FetchContents `cclsoftware/wayland-server-delegate` at another pin. UIDescription uses system Expat when found, otherwise embedded Expat. macOS links Cocoa, QuartzCore, Accelerate and conditionally UniformTypeIdentifiers/OpenGL through upstream. Actual platform builds remain required.

## Verification and handoff

Executed successfully: `python3 tools/project.py validate` (16 tasks, 33 evidence records); `python3 tools/project.py sync --check` (current); `python3 tools/project.py next --json` (revision 45). No compile, native editor, DAW, or image-fidelity test was run in this audit.

Implementation gates: build headless and GUI configurations; run the existing `rhodes_vst3_checks`/`vst3.*` suite and all three SDK/module validators on each claimed platform. Add focused tests for view-name rejection, view creation/destruction, parameter gesture delivery, external automation/state-to-control refresh, independent simultaneous editors, and packaged resource bytes/notices. A real host/editor harness must exercise attach/remove/reopen, resize/DPI, Linux event-loop behavior, pointer/keyboard controls and loss of focus. Capture screenshots at native and scaled sizes against the supplied image. Demonstrate an audible and automated response for every musical control. Existing audio tests and headless SDK validation cannot certify GUI operation.

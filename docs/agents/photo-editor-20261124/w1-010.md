## Implemented behavior

`create_photo_editor(RhodesController*)` returns a native `Steinberg::IPlugView`
implemented by a `VSTGUI::AspectRatioVST3Editor` subclass with its own
`VST3EditorDelegate` and custom `CView`. The editor requires the packaged
`rhodes-suitcase.png` to decode at exactly 1536×1152 before opening.

The `.uidesc` template starts at 1024×768 logical pixels, with 768×576 minimum
and 1536×1152 maximum. Size hooks enforce uniform 4:3 scaling, account for host
content scaling before or after attachment, reject invalid/nonfinite scaling,
and bound native integer geometry. Native dimensions use four-pixel width
increments so height is exactly three quarters of width. The pinned SDK's
unbounded maximum zoom and initial-size cache are bypassed through explicit
size/content-scale hooks; the view still derives from `AspectRatioVST3Editor`.

The custom view draws the complete original bitmap using W1-009's `AspectFit`.
Painting, pointer lookup, keyboard polygons, and host `IParameterFinder` lookup
use the same source coordinate system. The idle view paints no replacement
controls, persistent value panel, focus border, image filter, or crop. The SDK's
persistent focus drawing is disabled. Transient control/key outlines and value
readouts expire after 1.7 seconds; a held audition note remains highlighted only
while its note-on transport has succeeded. Values shown during interaction are
read directly from the controller, including automation/state-recall changes.

### Parameter editing

| Photograph control | Parameter ID | Input |
| --- | --- | --- |
| Volume | 0 | Vertical relative drag, wheel, arrows |
| Pedal / Sustain | 1 | Click, wheel, Space/Enter, arrows |
| Bass | 3 | Horizontal relative drag, wheel, arrows |
| Treble | 4 | Horizontal relative drag, wheel, arrows |
| Intensity | 5 | Vertical relative drag, wheel, arrows |
| Speed | 6 | Vertical relative drag, wheel, arrows |
| Vibrato | 7 | Click, wheel, Space/Enter, arrows |

All controls support double-click reset to the controller's declared default.
Tab/Shift-Tab traverses the photographed controls. Shift provides fine drag,
wheel, and arrow increments. Home/End select minimum/maximum. Escape cancels the
interaction and transient feedback. Ctrl/Alt/Super keyboard combinations remain
available to the surrounding host.

Editing requires a successful `beginEdit`; each accepted gesture has one
`endEdit`, including mouse-up, cancellation, focus loss, window deactivation,
frame-driven removal, and editor close. Values pass through
`setParamNormalized`; the canonical controller value is sent to `performEdit`.
Rejected `performEdit` restores the previous controller value. Rejected host
operations get explicit transient feedback. No GUI method mutates audio state.

### Keyboard audition

Mouse key-down and glissando use the perspective-aware `hit_key` lookup, whose
black-key priority belongs to W1-009. Audition calls
`RhodesController::auditionNote(key, down, velocity)` with zero-based keys 0–72
and a fixed synthetic audition velocity of 0.75. It releases the previous note
before entering another key, on pointer-up, on leaving the keyboard, on lost
capture, and on view/editor teardown. `releaseAuditionNotes()` is called for
focus/deactivation/cancellation cleanup.

The supported transport is the controller's UI-thread SDK message path; the
controller/processor implementation is owned by the integrator. A failed note-on
shows **Connect host to audition** and produces no pressed-key highlight. This
worker does not claim that host connection or audio delivery was exercised.

All mutable interaction state belongs to one view/editor instance; there is no
global active note, parameter gesture, controller pointer, or mutable photo state.

## Behavior covered

The executable accepts exactly three bundle paths in direct, filtered,
quadrature order. All instrument behavior is obtained through SDK module
factories and `IEditController`, `IPlugView`, and
`IPlugViewContentScaleSupport`. It includes no production header, no VSTGUI
implementation header, and no production-linked object/library.

The test loads all three native bundles together and initializes two controllers
per module using SDK `HostApplication`. Each controller owns two simultaneous
views. Frozen controller class IDs prevent a repeated or misordered bundle from
silently replacing a variant. Assertions cover:

- Editor rejection before initialize and after terminate; rejection of null,
  empty, differently cased, and unknown view names after initialize.
- Nonnull `ViewType::kEditor` creation on GUI builds and default
  `(0, 0, 1024, 768)` geometry.
- The current native platform type, rejection of unknown/empty platform types,
  advertised host resize support, null rectangle rejection, and safe unattached
  focus transitions.
- Independent fixed resize examples for minimum `768 × 576`, maximum
  `1536 × 1152`, default dimensions, off-aspect requests, and nonzero origins.
  Property checks require exact integer 4:3, preserved origins, bounded sizes,
  stable repeated constraint queries, and no current-size mutation before
  `onSize`. Off-grid widths must stay within two pixels of the requested width.
- Accepted host resizes reflected by `getSize`; rejected unconstrained resizes
  preserve both caller rectangles and current view geometry. Extreme signed
  input-coordinate differences clamp safely, while unrepresentable constrained
  endpoints reject without mutation.
- DPI factors `0.75`, `1.25`, `1.5`, `2`, `3`, and `1` before attachment or a host
  frame exists, with fixed expected dimensions and scaled minimum/maximum
  limits. DPI must preserve user zoom through nondefault-size round trips.
- Rejection of zero, negative zero, a negative value, NaN, both infinities,
  finite overflow, minimum positive normal and minimum positive subnormal
  factors. Rejection is checked from nondefault DPI and must preserve both
  current geometry and scale-dependent bounds.
- Distinct controller and view objects, independent controller gain values,
  independent per-view size and DPI for siblings and other modules, and view
  release/recreation preserving the surviving sibling and controller state.
- Releasing all views before controller termination, live peers surviving
  another controller's termination, fresh controller defaults after prior
  instances terminate, and host-side module ownership released before unload.

The observed native runtime created 9 initialized real controllers and 24 views,
rejected 54 malformed scale requests, and passed 3,855 checks on Linux.

# W1-019 — actual Linux native editor attachment diagnosis

## Result

The actual direct-model native GUI bundle opens successfully in the pinned official Steinberg `editorhost` on the task-local Xvfb server after preparing the XEmbed atom expected by that host. The 1024 × 768 native view rendered the complete supplied photograph. I inspected the captured native-window image: the black case, silver control strip, full keyboard, cabinet, legs and pedal are present, with no permanent synthetic dashboard or idle overlays.

No production source, SDK source, shared build configuration, canonical project state, or Git history was changed by this worker.

## Concrete failure and diagnosis

Original invocation terminated with SIGSEGV after `_XEMBED_INFO does not exist`. A task-local GDB was downloaded from the already configured signed Debian snapshot `20261117T190000Z`, but debugging a live inferior is denied by this environment: `ptrace: Operation not permitted`. Package versions/hashes are retained in `w1-019-gdb-provenance.json`.

I then compiled a diagnostic-only signal-handler shared library (`w1-019-crash-trace.c`) and launched the unchanged host/plugin with `LD_PRELOAD` plus unbuffered stdout. This captured the native failure stack in `w1-019-crash-trace-unbuffered.log`. The host reports **Could not create window**, and its resolved stack contains:

- `Steinberg::Vst::EditorHost::App::createViewAndShow`
- `Steinberg::Vst::EditorHost::Platform::kill`
- `Steinberg::Vst::EditorHost::App::~App` / `App::terminate`
- `VST3::Hosting::(anonymous namespace)::LinuxModule::_M_dispose`
- three addresses inside the stripped plugin module during teardown

The local pinned SDK source at `public.sdk/samples/vst-hosting/editorhost/source/platform/linux/window.cpp` explains the initial failure exactly: `X11Window::Impl::init` calls `XInternAtom(xDisplay, "_XEMBED_INFO", true)` and immediately returns false if the atom does not already exist. A new bare Xvfb server has no such atom. The failure therefore occurs **before plugin attachment**. The later teardown fault is a distinct path; the stripped module stack does not establish its precise internal cause, so no unsupported production diagnosis is claimed.

## Limits and integration handoff

This establishes actual native attachment and visible idle rendering for the direct model on this Linux/Xvfb setup. It does not establish normal close lifecycle, gestures, audio routing, multiple native windows, resizing, macOS, Windows, or DAW behavior. The parent's capture script terminates the host process after capture; normal view removal was not exercised.

Add atom seeding to the durable Linux native-host harness before starting `editorhost`; do not patch SDK/plugin sources merely to satisfy this bare-server host precondition. Keep the failed-window teardown limitation distinct from successful attachment. GDB and signal-preload files are diagnostic-only and must not be packaged into the plugin.

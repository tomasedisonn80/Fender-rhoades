`vst3.yml` uses Visual Studio x64, `--config Release`, whole bundle packaging and
all three SDK validators. `tests/cpp/contact_peak_cli.cmake` invokes the native

actual multi-module coexistence tests to Linux. Root reported the Windows VST3

retrieve that run and makes no new Windows execution claim.

## Focused gaps for the next implementation

1. **Keep the frozen benchmark Linux-only.** `run_vst3_matrix.py::main` explicitly
   rejects other platforms before affinity, Ninja or `/proc` access. Its pure
   verifier tests use synthetic Linux records and are portable; they do not
   establish Windows benchmark coverage. Add a focused Windows/platform-mocked
   test using a new output directory: expect exit 3 and a retained operational
   manifest, without invoking Linux-only APIs. The existing directory-refusal
   test returns before this branch and does not cover it.
2. **Exercise the new Python diagnostic as a real subprocess.** Current contact
   sweep tests predominantly mock native execution. Their real child fixture
   deliberately prefixes a Python script with `sys.executable`, avoiding a
   platform-dependent executable script. Reuse that pattern for the new CLI,
   with spaces and non-ASCII characters in candidate/output paths. Preserve raw
   bytes through binary reads/writes, including CRLF input, and compare hashes
   against those exact bytes. This does not extend the C++ CLI's documented
   narrow-argument/Unicode limitation.
3. **Make the optional timing cap portable.** If damped timing uses a worker
   process, an importable top-level target, guarded entry point and explicit
   spawn-compatible communication are needed. Test the spawn context on Linux
   as well as Windows, including timeout cleanup and backend absence. Python
   3.11 documents spawn as the Windows default and requires safely importable
   process entry points in its [multiprocessing documentation](https://docs.python.org/3.11/library/multiprocessing.html).
   A POSIX-only signal alarm would leave the promised Windows wall cap uncovered.
4. **Retain platform-specific skips honestly.** Existing symlink tests skip
   when creation is unavailable. New exclusive-retention tests should always
   cover ordinary file/directory collisions and partial failures; a skipped
   symlink case must remain explicitly unverified. Do not infer successful
   reparse-point behavior from Linux tests.

Python's [subprocess documentation](https://docs.python.org/3.11/library/subprocess.html)
also notes that process creation itself may delay timeout handling. Record this
boundary if a subprocess enforces the diagnostic's wall budget. These are
targeted coverage recommendations, not observed Windows numerical defects.

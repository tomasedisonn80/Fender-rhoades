## Independent oracles and ownership discipline

The wire oracle independently constructs RHST bytes, literal model IDs 1/2/3,
version, exact 16/20-byte length, gain/pedal words and expression payload. It
does not call the production encoder, decoder, packer or canonicalizer.
Snapshots must equal an entire permitted triple and its corresponding packet;
individual-field membership is insufficient. Output streams start with sentinel
bytes, and the oracle also checks transfer progress and untouched bytes beyond
the exact saved extent. Each state call owns its own raw stream.

There is one **serialized audio/lifecycle owner** per processor/mailbox. The
host-preflight fixture migrates that ownership to a temporary audio thread and
returns it only after joining. No other thread reads live state, mechanics,
ownership, cursors, queues, events or audio buffers while `process()` runs.
Concurrent callers use only `setState`, `getState`, or the atomic published-state
interface. Per-thread outcomes have one writer and are combined after joins.
No completed token is replayed, and no second consumer is introduced.

| Fixed selector | Covered behavior |
| --- | --- |
| `mailbox_ordered` | Twenty two-thread schedules per variant: replacement before/after token acquisition; successful versus aborted completion; identical, expression-only, complete-triple and A→B→A replacement; no newer request; invalid expression rejection. Checks the complete clear-token word, stale publication refusal, stale abort preserving the newer request, restored abort/retry, and exactly one pending consume. The UI writer never consumes a token. |
| `host_preflight` | Thirty-six actual-processor scenarios per variant, both sample formats. Warm mechanics/filter history and ownership, queue an initial nonunity recall, then gate the host getter and replace it with identical, expression-only or whole-triple state. Accepted blocks match an independently configured processor exactly. Late invalid expression and ownership rejection preserve live state, every key's holder count, modal state, fault state, cursor and 129 future pre-gain engine samples. Retry also covers a newer expression-only request after rejection, an identical request after acceptance, reset and two following blocks proving no repeated recall. |
| `adaptive_snapshots` | Eight ordered actual `getState`/`IBStream` cases per variant, using double-format processing. Pause the save after its first byte; concurrently replace the recall and run an accepted or ownership-rejected block. Cover v1→v2, v2→v1, v2 expression-only and identical-state transitions. The first save must finish as its original exact 16/20-byte snapshot with one-byte progress, while separate saves see the newer complete triple. |
| `live_anchors` | Forty-eight bounded concurrent blocks per sample format and variant. Unique, unautomated gain tags identify which recall was selected; the frame cursor identifies continuation when none was selected. An independent copied/reset raw engine and exact dyadic barycentric expression curve check every output sample. The expected anchor comes from the selected recall or prior audio-owner live state, never the mailbox snapshot. Includes pre-gain modal/energy comparisons and a nonzero-output witness. |
| `callback_stress` | One audio owner, one recall writer and one save observer. Per format: 256 accepted/rejected blocks, 4,096 recall attempts and 4,096 observer saves, plus writer-side saves. Correlated triples include zero, unity and minimum positive subnormal expression, consecutive expression-only recalls, full three-control automation and negative-subnormal expression rejection. Quiesce all workloads before the final exact recall, then verify reset and once-only consumption over two following blocks. |

The host getter gates deliberately precede token acquisition. They deterministically
prove replacement during syntax preflight, including later ownership failure and
abort, but cannot force a store between the processor's private load and CAS.
Post-consume publication/abort ordering is forced with the direct mailbox API.
The two stress selectors use bounded work and deterministic oracles; their exact
mid-render interleavings are scheduler dependent. The reported after-join
published/live differences are observations, not proof that every difference
existed at the instant the renderer read its anchor.

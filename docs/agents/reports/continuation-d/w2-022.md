## Implemented behavior

- Added `kExpressionId = 2` and changed `kControllerParameterCount` to
  `3 + kMidiChannelCount` (19). The six FUIDs, model numbers, names, versions,
  latencies, gain/sustain IDs and sixteen CC123 IDs are unchanged.
- Registered Expression after sustain and before commands, with title
  `Expression`, unit `x`, plain range 0..1, default 1, explicit continuous
  step count 0 and `kCanAutomate` flag. The existing RangeParameter implementation
  supplies the 0..1 identity range conversion.
- Added global CC11 mapping for event bus 0 and channels 0..15. Existing CC64
  and channel-specific CC123 mapping remains unchanged. Invalid buses/channels
  and unsupported controllers, including CC43, still reject without writing
  the caller's output tag.
- Recognized Expression in normalization and conversion entry points. Setting,
  parsing and formatting use the same integer `control::quantize` and
  `control::widen` helpers as Monitoring Gain. This canonicalizes signed zero
  and preserves binary32 subnormals through normal binary64 representations.
- Separated optional factor-suffix permission from the parser's binary64
  maximum. Gain retains maximum 32; Expression permits lowercase `x` and
  requires 0..1; commands retain maximum 1 without any suffix. The shared
  strict ASCII decimal grammar, bounded UTF-16 input and staged output remain.
  Domain checking occurs before binary32 canonicalization. Expression display
  remains numeric, with the unit supplied by metadata. CC123 setting and text
  retain their full binary64 precision and existing signed-zero handling.
- State recall checks the entire decoded packet, all three parameter objects,
  and both widened continuous values before changing any control. It applies
  gain, sustain and Expression and leaves transient CC123 controls alone.
  The updated decoder's v1 default therefore resets Expression to unity.
  State save validates both continuous values before constructing
  `InstrumentState{gain, sustain, expression}` and passing it to the common
  writer. `setState` continues to delegate to `setComponentState`.
- Updated the controller header's MIDI-mapping comment to include CC11; no
  header interface change was necessary.

The atomicity claim here is preflight-before-mutation at the controller API
boundary, matching the existing gain/sustain contract. No controller-thread
concurrency or new locking protocol is introduced.

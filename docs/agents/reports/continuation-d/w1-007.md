## Decision

The proposed mapping is supported by the inspected interfaces. Keep the draft's
explicit distinction between standardized controller numbering and the project's
chosen global digital response. No source reviewed establishes the proposed
linear amplitude law, unity default, or shared-channel behavior as a General MIDI
requirement.

## Public primary evidence

1. The [MIDI Association control-change table](https://midi.org/midi-1-0-control-change-messages)
   identifies CC11 as Expression, with a 0–127 MSB value, and CC43 as its LSB
   partner. The page explicitly describes itself as an incomplete overview.
   Its numbering table does not specify the proposed amplitude transfer curve.
2. The [MIDI Association message summary](https://midi.org/summary-of-midi-1-0-messages)
   places Control Change among channel voice messages: the channel field has
   values 0–15, corresponding to user-facing channels 1–16. CC11 is therefore
   channel-addressed at the MIDI transport level; describing it as inherently
   global would be misleading.
3. Steinberg's [IMidiMapping reference](https://steinbergmedia.github.io/vst3_doc/vstinterfaces/classSteinberg_1_1Vst_1_1IMidiMapping.html)
   defines the mapping query by input event-bus index, channel, and controller
   number. The returned parameter ID tells the host which regular parameter
   change to deliver; the processor does not receive the raw controller through
   this interface. Steinberg's [MIDI overview](https://steinbergmedia.github.io/vst3_dev_portal/pages/Technical%2BDocumentation/About%2BMIDI/Index.html)
   also distinguishes controller parameters from per-note expression.
4. Steinberg's [parameter documentation](https://steinbergmedia.github.io/vst3_dev_portal/pages/Technical%2BDocumentation/Parameters%2BAutomation/Index.html)
   specifies normalized double values in 0–1, continuous controls with
   `stepCount == 0`, and one queue per parameter ID. The
   [queue interface](https://steinbergmedia.github.io/vst3_doc/vstinterfaces/classSteinberg_1_1Vst_1_1IParamValueQueue.html)
   exposes parameter ID and time/value points, with no source MIDI-channel
   field. Consequently, mapping all channels to ID 2 intentionally merges their
   expression control before processing; separate channel levels cannot be
   recovered from that queue.

## Exact mapping recommendation

Apply these choices to every instrument variant:

| Query or metadata | Recommended result |
| --- | --- |
| Event input bus 0, channels 0–15, `kCtrlExpression` | `kResultTrue`, parameter ID 2 |
| Event input bus 0, channels 0–15, CC64 | Preserve shared sustain ID 1 |
| Event input bus 0, channels 0–15, CC123 | Preserve `0x1000 + channel` |
| Unsupported bus/channel/controller, including CC7 and CC43 | Preserve rejection; leave output ID unchanged |
| Expression metadata | Title `Expression`, unit `x`, plain/normalized range 0–1, default 1, `stepCount = 0`, `kCanAutomate` |

Keep Monitoring Gain at ID 0 and add one persistent control, for nineteen
exported parameters. Consume host-delivered normalized values directly; do not
divide `ParamValue` by 127 or quantize it to 128 MIDI steps. The draft's binary32
anchor/state canonicalization is a separate project rule.

Do not map CC43 independently to Expression: an LSB value is not a replacement
for a complete expression value. The plug-in need not reconstruct raw 14-bit
messages. This does not imply that normalized values derived by a host from
higher-resolution input are rejected.

## Documentation caveats to retain or add

Suggested user-facing text:

> Expression is a shared digital output multiplier, initially 1. CC11 received
> on any of the sixteen input channels maps to this same control. It affects
> the complete instrument output, including notes started on other channels.
> The host supplies normalized parameter changes. The plug-in performs no raw
> CC11/CC43 pairing and provides no independent per-channel expression level.

The factor response is an engineering choice. Do not call it a mandatory MIDI
amplitude law, General MIDI compliance, a historical Rhodes volume taper, or
per-note expression support. Keep the draft's zero-expression state-evolution
and fault-reporting requirements.

For simultaneous messages on different channels, promise only the delivered
parameter-queue behavior: the project's final-point rule handles equal offsets.
Do not invent a channel-priority rule or promise that a named DAW will order or
merge incoming MIDI and recorded automation identically. That remains a host
verification question.

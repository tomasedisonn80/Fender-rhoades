## Findings: implemented behavior and concrete omissions

`plugins/vst3/controller.cpp::initialize` creates exactly 18 controls: Monitoring
Gain, shared Sustain, and sixteen channel All Notes Off commands.
`getMidiControllerAssignment` handles only CC64 and CC123. There is no CC11
expression mapping, independent expression parameter, program-list interface,
pitch-bend mapping or host-recognized bypass parameter. The processor accepts
only the corresponding 18 parameter identities; its final conversion is
`(32.0 * gain) * volts`. These are deliberate scope omissions, not newly proven
violations of the existing contract.

The sustain/CC123 behavior is coherent: `NoteTracker::release_channel` releases
only a channel's holders, ordinary key releases retain mechanics, and shared
sustain can retain ringing. All three variants already have explicit state
recall, lifecycle resets, reported latency (0/48/48 frames), and an infinite
asymptotic tail. No missing tail estimate or recall failure was established.

The processor resets on every `setActive`/`setProcessing` call and does not track
the active/processing state. That is a malformed-call-order hardening opportunity,
already identified in continuation C worker 001, not evidence here of a failure
under conforming host calls. Current tests intentionally assert those resets.

## Recommendation: one global digital Expression control

Add **Global Expression**, normalized multiplier `0..1`, default `1`, mapped to
CC11 on bus 0, channels 0–15. The pinned SDK declares `kCtrlExpression = 11` in
`pluginterfaces/vst/ivstmidicontrollers.h`. This would give performance-volume
control independent of the existing monitoring trim, without claiming any
measured pedal, passive Stage circuit or calibrated tonal response.

Freeze the global scope explicitly: this is one shared physical instrument;
the last delivered expression value controls its whole output. It is not
per-channel expression or MPE. At zero, continue rendering mechanics, note
ownership, sustain and filter history; only the digital output multiplier is
zero. Reopening expression must reveal the correctly advanced tail. Do not
alias CC11 to Monitoring Gain, which would overwrite the user's trim and use
the unrelated 0–32x range.

Use the existing gain automation convention for expression: binary32 canonical
endpoints, linear interpolation from the prior accepted block's value at offset
`-1`, last duplicate offset wins, and final offset-zero value in a zero-frame
flush. Each scalar is interpolated independently, then expression multiplies
the existing converted signal. Preserve the existing arithmetic path exactly
when expression is unity. Keep latency and model identities unchanged.

This has clearer immediate musical value than program names over the current
two configuration controls. Pitch bend first needs a policy for shared-key,
multi-channel ownership and state-preserving modal retuning; physical half-pedal
needs a separate mechanics contract. Bypass is useful but does not provide
continuous performance dynamics. Those features should stay separate.

## File interfaces and bounded implementation

| Interface | Proposed change |
| --- | --- |
| `plugins/vst3/plugin_ids.hpp` | Reserve parameter ID `2`, retain IDs `0`, `1`, `0x1000..0x100f`; increase controller count to 19. |
| `controller.hpp/.cpp` | Register Global Expression with multiplier text, canonical setters and strict existing decimal conversion; map CC11; load/save all persistent controls atomically. |
| `processor.hpp/.cpp` | Add one fixed 8192-point expression array; preflight the new queue, update queue-index mapping so ID 2 cannot collide with CC123 channel 0, and apply expression after the existing gain conversion. |
| `include/rhodes/instrument_state.hpp` | Append default-unity expression to `InstrumentState`; validate and canonically pack it with gain/sustain. Preserve lock-free publication. |
| `plugins/vst3/state_stream.hpp/.cpp` | Read exact legacy v1/16-byte states with expression defaulting to unity and explicit v2/20-byte states appending expression at byte 16. Write byte-identical v1 at canonical unity, v2 otherwise. Reject unsupported lengths/versions/models atomically. |
| `tests/cpp`, `cmake/Vst3.cmake`, documentation | Independent scalar oracle, migration/concurrency and loaded-module checks for all three variants; explain global behavior and updated bounds. |

The mailbox need not require 128-bit atomics: canonical positive binary32 values
in `[0,1]` have raw encodings at most `0x3f800000`, which fit in 30 bits. Two
30-bit payloads plus sustain and pending bits fit in the existing 64-bit atomic.
This packing must be independently checked, including subnormals and signed-zero
canonicalization. Do not overwrite or reinterpret version-1 wire bytes; older
plug-in binaries need not accept v2, but all existing own-model v1 sessions must
remain readable. Cross-model rejection remains unchanged.

Adaptive serialization is feasible and recommended: retain the existing
`EncodedInstrumentState` v1 type/helper for legacy callers, add an explicit v2
encoder and 20-byte type, and choose the wire version in `write_state_stream`.
The v1 encoder must reject non-unity expression rather than silently lose it.
The shared decoder accepts both exact formats; a valid v2 packet containing unity
may canonically save back as byte-identical v1. This preserves all existing golden
save bytes when the new control is unused. Actual v2 persistence and migration
still need tests; this audit has not implemented them.

## Independent acceptance checks

1. **Musical behavior:** an external scalar oracle computes the product of two
   independently interpolated controls against identical unmodified-engine
   voltages. Cover endpoints, interior offsets, duplicate offsets, block splits,
   zero-frame flushes and both output formats. At expression zero, independently
   compare modal state, frame cursor, holders and later resumed output with a
   continuously running unity-expression instance.
2. **Compatibility:** replay retained direct/filtered/quadrature fixtures at
   default/unity expression and require exact previous outputs, unchanged
   identities and 0/48/48 latency. Hand-authored v1 golden bytes must recall unity;
   separately authored v2 packets must round-trip gain, sustain and expression.
   Saving unity expression must produce the original exact 16 bytes; non-unity
   must produce 20-byte v2; restoring expression to unity must restore v1 output.
3. **Transactional bounds:** late malformed expression points, NaNs, infinities,
   out-of-range values, duplicate queues and 8193-point inputs must reject
   without consuming pending recall or changing live controls/mechanics. Test
   all 19 legal queues together and command-index separation.
4. **Publication:** run coordinated recall/render/save interleavings with
   differing gain/expression pairs; saved tuples must always be coherent, and a
   newer pending recall must survive rejected blocks and stale publication.
5. **Host delivery:** loaded modules must expose the new ID and CC11 mapping on
   all channels while preserving invalid-bus/channel rejection and existing
   mappings. Native SDK/module validation and one named-DAW CC11 delivery check
   establish only the environments actually observed.

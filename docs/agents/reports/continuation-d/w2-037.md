## Authored scope

Changed only [the manual DAW protocol](../../../DAW_VALIDATION.md) and this new
report. The protocol now:

- Describes 19-control discovery, Expression ID `2`, defaults/flags where a host
  exposes them, the old two-/eighteen-control cache diagnostic, coherent
  `Stereo Out`/2 and `Mono Out`/1 metadata, and the separate factory category
  `Instrument|Synth`.
- Adds eleven proposed Expression/layout cases: metadata, steady direct-UI
  Expression, global CC11 across channels, direct-UI/MIDI delivered-value
  equivalence, independent ramps, equal offsets/block partitions, ordinary
  release at zero, sustained/channel release at zero, legacy unity stereo,
  mono versus each stereo channel, and observable omitted inactive outputs.
- Adds six proposed text/state/rollback cases and three coexistence cases for
  models 1/2/3, mixed unity/non-unity saves and available mono/stereo layouts.
  Existing basic-play rows also now carry explicit `Not run` results.
- Retains the existing CC123, pressure, sustain and ordinary-release procedures,
  updating only the current discovery and adaptive-state expectations. MIDI
  continuation comparisons explicitly keep Expression at unity. Earlier dated
  references and their source limits remain historical.
- Requires processor-delivery evidence for exact claims; upstream MIDI, UI
  displays and automation drawings do not establish parameter delivery. Raw
  CC11 byte 64, including a `64/127` mapping, is not exact 0.5. Unavailable
  routing, queue traces or callback boundaries leave the affected attempted
  claim inconclusive; never-attempted cases stay `Not run`.
- Separates Expression zero from host mute/bypass/suspension, requires an
  observable continuing reference tail and unchanged lifecycle for release
  comparisons, and limits inactive-output omission to actual observable
  positive-frame callbacks with inactive bus status. Pointer/fault guarantees
  remain dedicated harness claims.

The [frozen contract](../../../specs/HOST_EXPRESSION_MONO_20261124.md) takes
precedence over the earlier [W1-016 plan](w1-016.md): interpolation starts at
offset `-1` from the audio owner's canonical live value after the selected
recall. It does not start from the plan's older “previous published value”
wording or a mailbox snapshot that can already contain a newer pending recall.
Independent curves, canonical binary32 anchors and binary64 interpolation are
stated explicitly.

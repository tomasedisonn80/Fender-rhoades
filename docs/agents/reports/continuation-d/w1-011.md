# Worker 011 — loaded-module acceptance design

Date: 2026-11-24. Scope: read-only review of the expression/mono draft and actual
SDK-loaded test design; this report is the only changed file. No implementation,
build, test execution, Git operation, task-state change or child delegation was
performed. The conclusions below are proposed acceptance checks, not passing
results.

## Recommendation

Add one independent `tests/cpp/vst3_loaded_expression_mono_test.cpp`, linked only
to `rhodes_vst3_loader_support`, with selectors for controls/state, audio/layout
and coexistence. Follow the dependency and SDK-only linkage pattern at
`cmake/Vst3.cmake:388–417`, including the macOS universal-binary/signing setup.
Keep production headers, state codecs and processor fixtures out of this host.
Freeze public IDs, model numbers, latency and RHST bytes independently. Retain
the old loaded-MIDI and triple-module tests, making only their necessary
compatibility updates described below.

The existing loaded-MIDI harness has useful lifetime ownership and exact
continuation comparisons. Copy its small loader/RAII pattern; do not turn its
CC123/pressure oracle into a generalized framework. The new harness needs
variable-length state snapshots and layout-aware audio buffers, which would
otherwise complicate that established regression test substantially.

## Actual loaded-binary acceptance matrix

Run each applicable row for direct/filtered/quadrature and float/double host
buffers. Use 48 kHz and 192 kHz for audio/layout/coexistence, matching the existing
triple-module coverage; report executed combinations explicitly.

| Area | Stimulus and independent observation |
| --- | --- |
| Public controls | Create component/controller from the actual module factory. Check the six frozen class IDs, models 1/2/3, latencies 0/48/48 and infinite tails. Enumerate 19 parameters: gain ID 0, sustain ID 1, expression ID 2, then unchanged command IDs 0x1000–0x100f. Expression is named Expression, continuous, automatable, normalized/plain range 0..1, default 1 and unit x. Gain/sustain defaults remain .5/0. |
| CC11 | Query `IMidiMapping` on the actual controller. For all channels 0..15, bus 0/CC11 returns ID 2. Deliver the returned ID through `IParameterChanges` and verify audio/state response. Invalid bus/channel and CC43/CC120 must fail without overwriting a sentinel output ID; retain CC64/CC123 checks. Do not substitute raw MIDI events for host parameter delivery. |
| Scalar output | For identical note/release/sustain timelines and gain curves, run a unity-expression double-format peer. Independently evaluate expression's binary32 anchors and double interpolation; expected output is `monitored` at unity, otherwise `monitored * expression`, finally converted to the target sample type. Compare sample bits, including mono against the stereo left signal. Require audible oracle windows so equality is nonvacuous. |
| Curves/zero | Cover default/unity, constant zero/.25/1, first point after offset zero, duplicate offsets retaining the final value, held final value, and independent gain/expression curves. During a zero-expression interval deliver notes, releases and sustain changes; restoring unity must match a continuously advanced unity peer exactly. Partition comparisons must use equivalent curves and representable boundary anchors; dyadic ramps avoid accidental binary32 boundary drift. |
| Preflight | Use raw queues for duplicate ID 2, decreasing offsets, NaN/out-of-range values, a late malformed point, invalid count, and 8192 versus 8193 points. Admit all 19 distinct queues including expression plus every CC123 channel to detect command-index overlap. With a pending recall, reject a malformed block, then compare saved state and exact subsequent audio/release behavior with a peer that received no rejected callback. |
| Flush | Zero frames with no bus, zero-channel bus or negotiated-width bus must accept offset-zero expression without accessing sample pointers. Check pending recall followed by final gain/expression/sustain and releases, no time advancement, canonical saved expression, and rejection of nonzero offsets. A null buffer list is sufficient for the valid zero-frame cases. |
| RHST migration | Construct literal little-endian v1 and v2 packets outside production code. Default/unity saves are exactly 16-byte v1; nonunity saves are exactly 20-byte v2, with expression at bytes 16..19. Test component `setState`, controller `setComponentState` and controller `setState`. V1 recall over nonunity restores expression 1; v2 nonunity affects a fresh strike; v2 unity resaves as v1. Include signed-zero canonicalization, minimum subnormal, representative interior value and unity-adjacent value. |
| State rejection | Reject each wrong version/length combination, truncation/extension, wrong model and invalid expression bits while preserving the previous whole state and a queued valid recall. Exercise all six ordered foreign-model pairs with both v1 and v2. A host-owned short-transfer `IBStream` tests 1-byte transfers through 20-byte v2, failed/no-progress transfers, exact remaining length and bounded calls. |
| Bus metadata | Initially require stereo arrangement, two-channel main output and coherent name. Suspend, negotiate mono, then require standard `kMono`, one channel and coherent mono name from `getBusInfo`; repeat mono→stereo. Unsupported arrangement, inputs, bus count and null arrangement pointer must preserve the previous arrangement/name/count. Save before/after layout changes and confirm unchanged instrument configuration, latency and tail. |
| Mono buffers | After fresh lifecycle setup/recall, compare mono bits with a simultaneously advanced stereo peer and require stereo L/R equality. Mono silence mask is 1; stereo is 3; audible mask is 0. Use an actual one-element channel-pointer array, with guard-page or appropriately instrumented loaded-module coverage to detect a second-pointer read. Include sample-buffer canaries and null active/inactive sample entries. |
| Rejection cleanup | Mismatched declared width 1/2 must reject without state/time changes but clear only supplied nonnull channels within frame bounds. Unsupported widths, multiple buses or excessive frames remain untouched. Repeat with both negotiated layouts and formats, and zero-frame cases that never dereference pointers. Preserve the existing inactive-output synthesis/advancement policy. |

Do not compute float expectations by multiplying already-rounded float peer
output: expression is applied in double before the final float cast. The
existing processor's separation between double monitoring and output conversion
is visible at `plugins/vst3/processor.cpp:487–515`.

## Same-process three-variant coverage

Load all three actual modules simultaneously, verify distinct factory handles
and six distinct IDs, then maintain live instances with different layouts and
expression states (for example mono/.25, stereo/.5, mono/1). Interleave callbacks
and compare each instance with its independently advanced same-model reference.
Change or recall one instance while processing all peers; peer state, layout,
audio and silence flags must remain unchanged by that action. Rotate which
variant receives each layout/expression assignment. Include all six module load
orders, explicit release before unload and the existing duplicate-bundle guard.
The existing `vst3_triple_module_test.cpp` already supplies the load-order,
factory-identity, unload and foreign-model patterns; retain its legacy stereo
lane rather than silently replacing it with the new feature lane.

## Fixture compatibility updates required

- `vst3_loaded_midi_test.cpp:31–37,69–81,138–139,188–201`: count 18→19,
  persistent-prefix length 2→3, expression default 1, command metadata checks
  start at index 3. ID 2 must leave the unknown-ID parser list at lines 246–249;
  replace it with ID 3 to retain that negative case.
- Its controller seeding loop currently gives every non-sustain parameter .25
  before taking a fixed 16-byte snapshot (lines 220–227). Preserve expression at
  unity in this legacy lane, or deliberately introduce a variable-size snapshot;
  merely increasing the count will make the fixed snapshot fail. The command
  parsing loop also begins at index 2 and must move to 3. If the malformed parser
  corpus otherwise remains identical with four unknown IDs, `rejected_texts`
  increases from 1002 to 1056; derive and document this count rather than loosening
  the check. Existing flush/rejected-block counts need not change.
- `vst3_triple_module_test.cpp:161–164`: assert 19 controls and expression default
  1. Its fixed 16-byte snapshots and half-gain strike oracle remain valid because
  that lane never leaves expression unity. The same applies to the dual-module
  test's v1 snapshots; do not mechanically replace valid legacy goldens.
- The SDK fixtures are not adversarial queues: `ParameterValueQueue::addPoint`
  sorts offsets and replaces equal-offset values, while
  `ParameterChanges::addParameterData` merges duplicate IDs
  (`public.sdk/source/vst/hosting/parameterchanges.cpp:68–95,154–181`). The new
  harness needs tiny SDK-interface adapters that preserve the supplied raw
  queue/point sequence; otherwise duplicate/decreasing-offset tests are vacuous.
- Adjacent direct fixtures also require intentional updates: the mono-rejection
  assertion in `vst3_host_test.cpp:635–639`, parameter-count checks, command
  metadata index `2 + channel`, and the 18-queue dense allocation case at
  lines 1108–1138. Existing 16-byte short-transfer assertions remain correct for
  unity v1 states; add v2 cases rather than indiscriminately changing them to 20.

## Legacy audio binding and limits

`/tmp/rhodes-d-baseline-modules/manifest.json` records source
`6c91dab00855b67a559e92edb79ae49e567be469` and all three saved Linux `.so` hashes.
Use a neutral SDK-only recorder that accepts both old and new modules, exercises
only legacy controls/stereo, and compares complete sample bytes and state bytes.
Run baseline and candidate in separate processes, or fully unload between runs,
to avoid reusing identical class identities in one loader session. Default unity
and explicit candidate expression-unity should both reproduce the legacy output;
baseline cannot be required to expose ID 2. Preserve module hashes, source/build
binding, rates, formats, callback timeline and exact comparison outcome.

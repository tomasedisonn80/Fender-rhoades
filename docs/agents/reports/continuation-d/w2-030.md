### Independent numerical and state oracles

The six binary64 midpoint centers are `3690000000000000`, `36a8000000000000`,
`380fffffe0000000`, `3fe0000010000000`, `3fe0000030000000`, and
`3feffffff0000000`. Their predecessor/center/successor expected binary32 values
are derived from binary spacing and even-significand tie selection, following
the reviewed W1-008/W1-012 design. A separate Python `struct` probe confirmed the
literal pairs and widened decimal display fixtures before execution. No
production quantizer, widener, codec or decimal helper generated expected data.

State bytes are constructed from literal `RHST`, version/model fields and
little-endian integer words. The independently written v2 golden is:

```text
52 48 53 54 02 00 MM 00 00 00 00 3f 00 00 80 3f 01 00 00 00
```

`MM` is the compile-time test literal 01/02/03, independent of the production
constant. It means gain 0.5, sustain true, and least-positive binary32 Expression.
The test's separate expected widening is `36a0000000000000`.

   Corrected the fixture: `1e-400`, `-1e-400`, `1e-324`, and `-1e-324` reject;
   actual zero mantissas `0e-400` and `-0e-400 x` accept; representable positive
   binary64 subnormal `5e-324` still accepts and canonicalizes to binary32 zero.
   This was a fixture error, not a production bug. All nine required reruns passed.

## CMake handoff and platform skips

The existing fifth argument to `rhodes_add_vst3_test` selects controller-only
sources. Integrator-owned registration can use:

```cmake
rhodes_add_vst3_test(rhodes_vst3_expression_control_tests
    tests/cpp/vst3_expression_control_test.cpp FALSE FALSE TRUE)
rhodes_add_vst3_test(rhodes_vst3_filtered_expression_control_tests
    tests/cpp/vst3_expression_control_test.cpp TRUE FALSE TRUE)
rhodes_add_vst3_test(rhodes_vst3_quadrature_expression_control_tests
    tests/cpp/vst3_expression_control_test.cpp FALSE TRUE TRUE)
```

Register `metadata conversion recall lifecycle fp_rounding fp_flush` for each
target. Set `SKIP_RETURN_CODE 77` for the `fp_rounding` and `fp_flush` tests.
`fp_rounding` runs every available C fenv rounding mode and returns 77 only if none
could run. `fp_flush` returns 77 when x86 MXCSR is unavailable (including ARM),
or no requested flush-mode combination is supported. Unsupported combinations
are printed explicitly. An `all` invocation returns 0 if its supported selectors
pass even when the optional flush selector prints a skip, so separate CTest
registration is the appropriate way to retain platform skip accounting.

The AArch64 FPCR-preservation branch is source-only coverage here. ARM native
flush/FZ16/FIZ modes are not exercised by this test, and the skip message states
that limit. No ARM equivalence or native Windows/macOS result is inferred from
the local x86 passes.

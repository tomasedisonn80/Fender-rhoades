## Necessary corrections now incorporated

1. **Fault boundary.** The earlier blanket statement that expression cannot
   stop an arithmetic fault conflicted with applying attenuation before float
   conversion. The amended contract correctly distinguishes engine failure or
   nonfinite `monitored` output, which always faults even at expression zero,
   from a finite double brought into float range by expression, which is valid.
   It also requires final conversion when inactive outputs are omitted.
   This matches W1-005 and the existing processor's separate engine/double/float
   checks. Tests must distinguish these cases; silence alone proves none of
   them. Accepted faults retain the successful prefix, zero the remainder,
   publish the accepted configuration, and require reset under the inherited
   policy. Omitted output eliminates writes, not arithmetic or fault checks.

2. **Interpolation anchor under concurrent recall.** “Previously published
   value” could select a mailbox snapshot containing a newer UI recall without
   performing its reset. The amended text correctly uses the audio owner's
   canonical live value after the selected recall. A failed publication or
   consume race must not substitute the UI snapshot for that anchor. Both
   controls retain this rule; whole-configuration publication still follows
   the existing single-audio-owner protocol.

## Compatibility and pointer traps to retain in implementation

- **Wire identity:** exact v1/16 and v2/20 length/version pairs are coherent;
  extending an existing v1 array to twenty bytes is not migration. V1 recall
  must overwrite a prior nonunity expression with unity. The old encoder must
  reject nonunity. Controller saves, `unpack`, and state reconstruction must
  carry expression explicitly: a surviving two-field aggregate can otherwise
  compile while silently restoring its default. The existing stream helpers
  do not truncate host storage (`state_stream.hpp`); a v1 write over an
  untruncated former v2 stream must not cause the reader to accept a 20-byte v1
  packet. Use correctly sized destinations and retain exact-extent rejection.
- **Mailbox:** the thirty-bit payload fits. Validate raw bits before packing,
  canonicalize negative zero, cast to unsigned 64-bit before shifting by 34,
  and preserve the full token. Retain expression-only and identical-newer-recall
  races. No new generation field or multi-consumer guarantee is required.
- **Omission:** with `numOutputs == 0`, never form `outputs[0]`, even if the
  unused pointer is non-null. This applies to success, syntax rejection, and
  arithmetic-fault exits. Existing `render()` unconditionally forms that
  reference and must change. An omitted active output still rejects.
- **Supplied buffers:** accepted nonzero blocks use negotiated width; active
  buses require every sample buffer, supplied inactive buses require the typed
  pointer array but permit null entries. A real one-entry mono array is needed
  to expose accidental second-entry reads. Merely placing a sentinel in a
  two-entry array cannot prove that bound.
- **Cleanup and flush:** rejected supported widths use declared width, not
  negotiated width. Preserve the inherited zero-frame/zero-channel silence mask
  `0`, mono/stereo masks `1`/`3`, and no sample-pointer access during flushes.
  Unsupported dimensions remain untouched. Non-null storage must exist for its
  supported declared extent; bounded C++ traversal cannot validate arbitrary
  foreign addresses. The specification's explicit omission/cleanup extensions
  qualify its legacy-stereo compatibility language; they are intentional
  behavior changes and must remain named in regression expectations.

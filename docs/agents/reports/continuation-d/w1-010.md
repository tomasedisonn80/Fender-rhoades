# W1-010 — Expression mailbox audit

## Scope and result

Reviewed the draft `docs/specs/HOST_EXPRESSION_MONO_20261124.md`, required project
guidance/state, `include/rhodes/instrument_state.hpp`, processor publication and
abort call sites, and the state/property/FP/concurrency fixtures. **The proposed
one-word layout is viable without changing the compare/exchange protocol.** This
is a static design review: the inspected implementation still has two fields;
no Expression implementation or executable test result is claimed.

## Packing requirements

- After raw-bit validation and signed-zero canonicalization, Expression lies in
  `0x00000000..0x3f800000`, wholly below `2^30`. Cast that payload to `uint64_t`
  **before** shifting by 34. A cast after a 32-bit shift is too late. Keep the
  word and all masks unsigned; unity sets mailbox bit 63. Extract Expression by
  unsigned shift 34 followed by conversion to `uint32_t`; extracting the upper
  32 bits directly would include sustain/pending.
- Preserve gain bits 0–31, sustain 32 and pending 33. The proposed default
  `{0.5F, false, 1.0F}` has the literal clear-token word
  `0xfe0000003f000000`. Minimum positive subnormal Expression occupies mailbox
  bit 34, adjacent to pending; this is a useful independent boundary fixture.
- Validate **both raw float fields before packing** in recall and publication.
  Truncation/masking is not validation: invalid Expression `2.0F` would lose its
  only payload bit when shifted into 64 bits and alias zero. Negative finite
  inputs can alias valid positive ones. Accept only exact negative zero on the
  sign-bit side, canonicalize it, and preserve positive subnormal payloads with
  integer operations under FTZ/DAZ. Avoid floating comparisons in the oracle.
- Append the defaulted field, but update every reconstruction, especially
  `unpack`, controller serialization, v1 decode and failed/default block-token
  construction. Two-field aggregate initializers remain compilable and can
  silently replace a nonunity Expression with its default. Existing tests using
  only those initializers cannot detect that omission. `getState()` should
  continue taking one snapshot; choose v1/v2 from that same complete state.

## Concurrency and ABA boundary

The existing algorithm compares the complete 64-bit token. A UI store always
sets pending; an audio publication/abort expects pending clear. Consequently a
newer request defeats stale completion even when only Expression changed or
when all three values are identical. Keep the full word in the token, clear only
pending, and restore the original full token on preflight abort. Invalid
Expression must leave both the existing triple and its pending status intact.

An A→B→A sequence **before** the successful consume CAS may be indistinguishable
from A, which is correct for last-unconsumed-configuration coalescing. After
consume, UI-only writes cannot restore a clear token, so they do not create a
harmful ABA. This argument relies on **one serialized audio/lifecycle consumer
and no overlapping or replayed completed tokens**. Another consume can clear a
new request back to an older identical word; a stale token could then publish
or restore pending. The mailbox API does not enforce token lifetime, and the
new layout has no spare generation bits. Document/preserve the existing owner
discipline rather than claiming arbitrary multi-consumer ABA protection.

Processor syntax preflight currently precedes `begin_block`; ownership/cursor
rejection after acquisition calls `abort_block`, before mechanics mutate.
Accepted arithmetic failure publishes the accepted live configuration and must
not use rollback-oriented abort. Expression must follow those same paths.

## Independent verification to add

1. **Bit fixtures:** use literal clear-token words and a separate sign/exponent/
   fraction domain oracle, never production pack/unpack/canonicalization helpers.
   Check both fields by `bit_cast<uint32_t>`, both sustain values, default,
   ±zero, minimum/maximum subnormal, minimum normal, `0x1fffffff/0x20000000`
   (mailbox bit-63 transition), predecessor of unity, unity, and invalid neighbors,
   negative subnormals, infinities and signaling/quiet NaNs. Exercise snapshot,
   consume, abort/reconsume and publication under supported FP modes. Rejected
   publication must leave its token usable for a subsequent valid publication.
2. **Deterministic schedules:** extend barrier-ordered mailbox cases to
   Expression-only replacement, identical replacement, pre-consume A→B→A,
   post-consume A→B→A, stale publication, stale abort, and abort with no newer
   request. Assert the next consume is pending exactly once, not merely snapshot
   equality. The existing host `GatedEvents` pauses *before* token acquisition;
   it does not deterministically prove an after-consume publication race. An
   internal load/CAS loser is likewise not forced by public boundary barriers;
   do not claim deterministic coverage without a narrow test seam.
3. **Host rollback:** warm mechanics/ownership, queue a nonunity recall, then
   reject a late malformed Expression point and separately an ownership/budget
   failure after token acquisition. Compare complete raw state and subsequent
   audio with an independent continuation. A valid zero-frame retry must install
   the pending triple/reset once. Cover all three variants and both formats.
4. **Stress:** one audio owner, UI recall writer and snapshot/save observer; use
   correlated legal triples with distinct gain/Expression words, including zero,
   unity and subnormal Expression. Recognize complete tuples, not the Cartesian
   product of allowed individual fields. Build exact v1/v2 packet expectations
   independently, including length, and inject invalid Expression requests.
   Include successful automation and rejected blocks; quiesce stress writers,
   then order one final recall after the final audio token and prove it survives
   stale completion and is consumed once. A stress pass supplements these
   ordered cases; it does not prove every scheduler interleaving or deadlines.

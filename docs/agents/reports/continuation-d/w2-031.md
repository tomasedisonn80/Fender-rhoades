## Independent expected state and observability

The fixture shares the selected scalar DSP engine, but does **not** use the
processor's queue collector, translator, state encoder or ownership tracker to
derive expected results. An independent owner list drives explicit scalar
strikes/releases and ascending-key channel releases. Only fixture-admitted
actions are applied to this reference. Expected controls are exact dyadic
constants at offset zero, avoiding a second implementation of interpolation in
a suite whose purpose is transaction rejection.

The initial history is independently rendered for 256 frames at 48 kHz, with
live state `{gain=0.625, sustain=true, expression=0.75}` and six holders:

| ID | Pitch | Channel | Velocity |
| ---: | ---: | ---: | ---: |
| 7 | 60 | 3 | 0.5 |
| -2 | 60 | 9 | 0.375 |
| -1 | 72 | 3 | 0.5 |
| -1 | 72 | 3 | 0.25 |
| 44 | 84 | 15 | 0.625 |
| 7 | 65 | 8 | 0.5 |

This yields holder counts 2/2/1/1 on pitches 60/72/84/65. It includes duplicate
anonymous holders, an identified negative ID, a shared pitch across channels
and one identified ID reused across different channels. Audible seed and tail
windows are required, so silent/unexcited comparisons cannot satisfy the test.

Most rejected transactions have a distinct, non-unity pending recall
`{0.25, false, 0.125}` while the seed remains the expected live state. The newer
recall case uses `{0.75, true, 0.5}`. The test independently predicts these
successful retry states:

- Maximum Expression retry: `{0.875, false, 0.375}`, cursor 128, exactly holder
  `(channel=4, ID=99, pitch=90)`; the last of 8192 equal-offset points wins.
- Chronological ownership retry: the selected old/new recall configuration,
  cursor 128, exactly `(channel=3, ID=7, pitch=73)` after releasing pitch 72 at
  frame 32. The new ID use at frame 31 rejects; frame 32 succeeds because the
  channel release precedes the note at the tie.
- Live zero-frame release: `{0.25, false, 0.125}`, cursor still 256, with only
  the channel-9 pitch-60, channel-15 pitch-84 and channel-8 pitch-65 owners left.
  Modal coordinates are unchanged by the flush while subsequent damping is
  checked through scalar continuation.
- Recalled zero-frame retry: `{0.5, false, 0.25}`, cursor zero and no owners.
  A subsequent note and tail verify that recall was consumed only once.
- Muted inactive retry: `{0.75, true, 0}`, cursor 128 and one pitch-73 holder;
  a second omitted block reaches cursor 256. Nonzero pre-gain history is checked
  before Expression returns to unity and resumed audio must match exactly.

Every rejected call checks bitwise live/published gain and Expression, sustain,
fault latch, cursor, every modal displacement/velocity, energy, sample rate,
per-key and total ownership, and exact adaptive saved bytes. The wire oracle is
an independently authored RHST byte layout; literal 20-byte goldens also check
the seed and pending packets at compile time. Saved extent is exactly 16 or 20
bytes and the untouched destination suffix is checked. Canonical unity after
reactivation exercises the v1 save path.

Identity validation drains a copy of the observed tracker using the independent
owner list and expected last-holder releases. Matching counts alone cannot hide
replacement by an unexpected identity. Before any successful recall can erase
corruption, copied actual/reference **pre-gain engines** render 129 bitwise-equal
samples, covering the complete delayed-filter history. Every such comparison
also requires at least one nonzero reference sample.

Actual callbacks use two sample canaries per channel and an actual one-entry
mono pointer array. Rejection may clear only supplied, non-null sample buffers
within the 128-frame extent. Mono-unused storage, omitted buffers, flush samples
and guards remain bitwise unchanged. Flags are checked as 0/1/3 where applicable;
an omitted bus retains its sentinel flag. This suite does not claim that its
ordinary one-entry array is an inaccessible-page guard; that stronger pointer
test belongs to the separate mono fixtures.

## Arithmetic fault boundary: explicitly unexecuted

The requested direct-host fault cases could not be controlled through the
current API. `RhodesProcessor` fixes `HostEventProcessor` to the selected
production engine. Its diagnostics are const references, and `modal_state()`
returns a value. Existing deterministic fault tests substitute template engines
into `BasicEventProcessor`/`BasicAudioEngine`; that substitution does not reach
the concrete host's Expression, monitored-double or final host-format code.
The integrator reviewed this limitation and explicitly directed this worker
not to add private-access macros, byte corruption or production fault switches.

Consequently this report makes **no executed host-fault claim** for:

1. Expression zero retaining engine-failure or nonfinite monitored-double
   reporting.
2. A finite monitored double outside float range being validly attenuated into
   float range before casting.
3. A final float conversion fault still being detected when inactive output is
   omitted, including the accepted-prefix/reset-required semantics.

Read-only source observation, separate from test results: `render()` computes
`monitored = (32.0 * gain) * volts`, checks both the engine result and finiteness
before Expression, applies attenuation before the float cast, and performs that
cast/check independently of the output-writing loop. Its accepted-fault path
publishes current controls and latches reset-required behavior. Preflight
rejection instead preserves the audio owner and aborts any selected recall.
These source statements are not runtime verification of a generated arithmetic
fault. A separately designed narrow host-conversion/fault fixture remains the
next action for this gap.

# W1-017 — independent Expression scalar oracle design

Date: 2026-11-24. Scope: bounded read-only review and this report. No implementation,
build, full suite, Git operation, or project-state mutation was performed.

## Oracle contract

Run each fixture for model 1/direct, model 2/filtered and model 3/quadrature, with
both `kSample32` and `kSample64`: six executions per fixture. A minimum focused
rate is 48000 Hz. Warm a matching pair for 256 frames with a valid held note so
the short automation fixtures observe nonzero output beyond either filter's
startup. The independence here is the scalar control/output calculation; the
existing engine tests remain responsible for synthesis correctness.

Build expected point maps independently from supplied fixture data. Canonicalize
the normalized anchors to binary32 under an explicitly selected ordinary
round-to-nearest environment, or use predetermined binary32 bits. Assigning
`map[offset] = value` in original queue order gives the last duplicate precedence
before evaluating any sample. Do not call production interpolation/conversion
helpers. For neighboring distinct anchors `(a,A),(b,B)`, calculate

`C(n) = ((b-n)*A + (n-a)*B)/(b-a)`.

Use the known starting configuration as anchor `(-1, C_previous)`. A point at
zero replaces that anchor immediately; after the last point hold its value.
Absent and empty queues hold the initial value. Gain and Expression have separate
maps and neighboring anchors. A long-double barycentric implementation is
independent of the current processor's difference/fraction implementation.

Render a **double-output, unity-Expression peer** with identical gain, sustain,
notes, timing, and lifecycle. If its scalar output is `M64`, expected audio is
`M64` at exact Expression unity, otherwise `M64 * E(n)`, then cast **once** to the
target sample format. Do not use a float peer: `M64 = 1 + 2^-24`, `E = .75`
produces float bits `0x3f400001`, whereas scaling the float-rounded peer gives
`0x3f400000`.

For the combined-control fixture, independently validate gain too. A second
double peer with both controls at unity produces `U64 = 32*volts`. For the normal
synthetic samples, recover `V = U64/32`, assert the shift is exact and every
nonzero recovered sample is normal, and calculate `M = (32*G(n))*V`, followed by
Expression. This preserves the specified legacy multiplication order. It does
not interpolate a combined gain-times-Expression envelope.

## Minimal discriminating fixtures

| Fixture | Exact input and required observations |
| --- | --- |
| Default and queue shapes | From the default `E=1`, independently exercise a null parameter container, a zero-queue container, an absent Expression queue beside a gain queue, and a present zero-point Expression queue. Repeat these shapes after an offset-zero flush sets `E=.25`. Compare audio and saved Expression; none may reset it to unity. |
| Anchor, duplicate, and boundary | Start `E=1`, process eight frames with raw Expression points `(3,0),(3,.5),(7,0),(7,.25)`. Expect `[7/8,3/4,5/8,1/2,7/16,3/8,5/16,1/4]`. This catches an offset-zero initial-anchor error and proves duplicates replace the *earlier ramp endpoint*, not only the duplicate sample. Follow with an absent-queue frame holding `.25`, a one-frame `(0,0)` block, and a one-frame `(0,1)` block. |
| Independent combined curves | Establish `G=.25,E=1` using a zero-frame flush. For 16 frames, use gain `(3,.75),(11,.25)` and Expression `(7,.5),(15,1)`. Check the full arrays against separate curves. Products at frames `0,3,7,11,15` are respectively `.3515625,.5625,.25,.1875,.25`; the product is not piecewise linear between the input points. Repeat with queue order reversed. |
| Non-dyadic interpolation | Flush `E=.1`, whose canonical bits are `0x3dcccccd`; deliver `(6,.9)`, canonical bits `0x3f666666`. The seven-frame ramp must use those float anchors and double intermediate interpolation, not raw host doubles or float-rounded intermediate controls. Require at least one audible sample where prematurely narrowing the interpolation would change the final expected result, so the fixture is discriminating. |
| Muted continued release | Warm a held note; mute via `(0,0)` for 256 frames. While muted, strike a second note at 17, release the original at 63, release the second at 95, and lift sustain at 96 after setting it at zero. Apply these identical physical actions to the unity peer. Both owners must be gone; cursor, all modal states and future filter output must agree. Unmute only via `(0,1)` and compare 256 further frames, requiring nonzero released-tail samples. No recall/reset is allowed between mute and unmute. |
| Flush and recalled initial anchor | A zero-frame queue with duplicate offset-zero points must publish only the final value, leave cursor/modal motion unchanged, and affect the next rendered sample. Separately, recall `G=.625,E=.25`, then in the same first accepted audio call strike at zero and deliver Expression `(127,.75)`: expect `E(n)=.25+(n+1)/256`, including after filter startup. Recall overrides stale live anchors before interpolation. A recall plus zero-frame final `(0,.5)` must start subsequent processing at `.5`. |

Each audio fixture checks both stereo copies, untouched sentinels beyond the
declared frame count, finite output, actual-output silence flags, cursor,
canonical final gain/Expression bits, and ownership as applicable. A muted sample
must compare numerically equal to zero; signed audio zero is not required to be
canonical positive zero. Nonzero continuation is essential: silence alone could
conceal stopped synthesis or cleared filter state.

## Comparisons and tolerances

For the dyadic fixtures above, use bit identity against the double peer followed
by the specified operations and final cast. Exact unity must preserve the peer's
bits, including zero signs. Stereo copies must always have identical bits.
Canonical published state, cursor and ownership checks are exact.

For the deliberately non-dyadic curve, compare the independently evaluated
reference using `16*epsilon_double*abs(M64)` as the double absolute bound; a
float result may differ by at most one float ULP from the reference's final cast.
Handle expected zero separately and require finite output. These bounds admit
ordinary algebraic evaluation differences without allowing an intermediate
binary32 control value. Do not add a broad fixed absolute floor. Retain the
exact dyadic assertions as the primary multiplication-order and unity checks.

## Partition and recall subtleties

Use a 32-frame curve initialized to `G=.25,E=1`. Gain anchors are `(15,.75)` and
`(31,.25)`; Expression anchors are `(15,.5)` and `(31,1)`. Compare one block with
widths `[1,2,4,1,8,16]`, inserting each partition's final-frame anchors at the
values of the original global curves. All slopes, frame values, and interval
lengths are exact dyadic quantities. Remap event offsets by the same absolute
timeline, then compare audio, final state, ownership and a further unautomated
tail exactly. Add a second partition with boundaries exactly at a note/release
and at a curve bend if those events are not already in the first schedule.

Simply dividing the original sparse point list is invalid: an early callback
cannot see an endpoint outside its extent and holds after its last local point.
Even inserting rounded endpoints does not guarantee arbitrary partition
equivalence. A ramp from `(-1,1)` to `(2,0)` has first sample `2/3`; canonical
binary32 storage changes that to `0.6666666865348816`. Restarting from it gives
next value `0.3333333432674408`, versus the uninterrupted `1/3`, a difference of
`9.934107462565104e-9`. Such deliveries are not identical piecewise-linear curves.

`setState` is also not a harmless way to restore partition boundary controls:
accepted recall resets mechanics, FIR history, ownership and cursor. Establish
matching initial processors before the test and keep rendering uninterrupted.
For pending-recall tests, reset the peer at the same boundary, replacing only
its Expression field with unity. Otherwise the purported oracle compares
different physical histories or uses the old Expression as the offset -1 anchor.

## Evidence and limitations

Read `AGENTS.md`, `README.md`, `docs/PROJECT_STATE.md`, `docs/ROADMAP.md`, the
assigned Expression/mono specification, the processor and current automation,
filtered and test-support fixtures. A standalone Python standard-library probe
confirmed the double-before-float rounding witness, exact rational/full/split
gain and Expression sequences for the proposed 32-frame partition fixture, and
the non-dyadic discrepancy above. The probe was run directly from a heredoc;
no probe file was created. No plug-in test or implementation claim is made.
The existing test support's two-entry `ParameterChanges` fixture needs a larger
local container when gain, sustain and Expression are exercised together.
Arithmetic-fault reporting at zero Expression needs a separate fault fixture;
ordinary finite tails cannot establish that property.

target, compile it once per variant, and run both sample formats before expanding

### Nonvacuity and the actual failing layer

Every scoped call checks the exact number of process calls, total span samples,
and, for Q6, observation calls. It also checks that the real method succeeded,
returned finite data before override and used the same actual engine instance.
Real nonzero samples/observations and audible supplied-output prefixes are
required. Overrides must fire the expected number of times; forced failures
fire exactly once. A missing linker interception or silent dummy engine cannot
pass these checks.

For an upstream fault at relative frame `f`, the public event-processor fault
latch must be set and its cursor must remain at the successfully completed
prefix. When an observation fails, Q6 has `f + 1` observation calls but only
`f` boundary-advance calls. When the boundary advance is overridden as failed,
the real advance has still executed, while the event cursor excludes that frame;
the test deliberately preserves this accepted-fault/partial-progress policy.

For a host monitoring or final-float fault, the event-processor fault latch must
remain clear, the processor fault latch must be set, and the cursor must include
the completed failing frame. Thus the finite overflow tests fail if a filter
fault occurs earlier. NaN/infinite raw process output is explicitly classified
as an upstream failure for filtered/Q6 and as a host monitored-value failure for
direct. The report does not relabel a prefilter rejection as a host monitor pass.

### Finite overflow, attenuation and delay

The final monitoring witness is the exact source value `2^1021`, gain `1`, and
Expression `0` or `0.5` in the appropriate lanes. The source and all filter
arithmetic remain finite through the predicted fault, while multiplying the
filtered voltage by 32 overflows binary64. Zero Expression must still fault.
Float fresh-history monitoring uses Expression zero to prevent an earlier
binary32 conversion failure; the primed frame-zero float cases also exercise
Expression `0.5`. Double additionally exercises the nonzero-expression delayed
prefix.

The float-conversion witness uses exact source `2^128` and gain `0.5`.
Unattenuated monitored values are finite binary64 but eventually exceed binary32.
Expression `1/32` brings them within binary32 range and must succeed; Expression
zero also succeeds because this source has no engine or monitored-double fault.
The double host accepts the unattenuated stream. The unattenuated binary32
reference must contain an actual overflow witness, rejecting a vacuous
attenuation success.

A separate chronological long-double convolution uses the published coefficient
arrays, without either production FIR class or host rendering function. It
predicts the first overflow sample before the failing host call. Every tested
comparison to the overflow threshold must have a relative margin greater than
`1e-4`; a rounding-boundary witness is rejected. Valid finite double prefixes
must stay within `256 * epsilon(binary64)` relative error (approximately
`5.68434e-14`). Float prefixes must agree within one binary32 ULP. The final
monitor selector's maximum relative prefix errors were zero for direct,
`2.4565479954632461e-14` for filtered and `6.3567108905938914e-15` for Q6.
Across the mixed-format conversion selector, the largest reported relative
errors were `5.8590676950966388e-8` filtered and `5.7707367551679172e-8` Q6;
these aggregate maxima include ordinary binary32 narrowing and satisfy the
separately enforced one-ULP rule.

### Prefixes, controls, ownership and reset

Forced-result/nonfinite fault prefixes are compared byte-for-byte with a separate
unfaulted real-host execution of the same valid transaction. The finite-source
cases use the independent convolution checks above. Each supplied buffer must
retain the valid prefix and contain positive zero at the failed sample and
entire declared suffix. Mono's unused second buffer, samples beyond the declared
extent, and both buffers/flags for omitted output must retain their canaries.
Silence flags are checked against the actual one/two-channel width and retained
prefix. Nonzero prefixes and whole-block silence are both exercised.

Scheduled frame-9 failures independently expect the gain/Expression pair from
the two curves: engine-result cases retain gain `0.359375`, while monitoring and
float-conversion cases retain gain `1`; the nonzero Expression is `0.640625`.
The failing frame retains sustain true; the later sustain-off point never runs.
Ownership reflects the fully preflighted transaction, including a later note
that has not yet reached mechanics. A release at the failing frame is retained,
mechanical energy remains nonzero, and the later key's modal states stay zero.

Without a pending recall, current/published state and literal v1/v2 saved bytes
must match the failing-frame controls. A subsequent positive block and parameter
flush are rejected with no wrapped engine calls and no change to mechanics,
ownership, cursor, fault or configuration. Sixty scheduled public `setState`
interleavings place a newer `{0.375, false, 0.25}` recall between block selection
and fault publication across the final three-variant set. The current audio
owner keeps its failing-frame controls while published/saved state retains the
newer recall; a subsequent flush consumes it and resets. These are deterministic
ordered interleavings, not a scheduler-race or exhaustive concurrency proof.

Explicit reset cases cover `setProcessing`, `setActive`, successful
`setupProcessing`, and consumed valid state recall. They clear both fault layers,
cursor, note ownership and mechanical energy, preserve the required configuration,
produce a silent post-reset block and then produce nonzero real audio again.

Two defensive render guards are not artificially forced: normalized preflighted
endpoints produce finite bounded interpolated controls, and finite monitored
binary64 multiplied by finite Expression in `[0,1]` cannot introduce a new
binary64 magnitude overflow. The fixture does not corrupt those controls to
manufacture a `stored_gain/stored_expression` or post-Expression-double failure.
It executes the reachable upstream, monitored-double and final-binary32 exits
under the frozen valid-control contract; no claim of arbitrary branch coverage
is made.

1. The first strict build succeeded for all variants. The first 18-invocation
   test set passed 17 and failed Q6 `monitor_fault`: the original exact `2^1020`
   step hit the symmetric half-response at the binary64 overflow boundary.
   The fixture rejected its own threshold margin before executing that finite
   monitoring case. Its earlier nonfinite cases had executed; this was not a
   production-monitoring failure. Original source and all first logs remain.
2. The second build again succeeded for all variants. It added byte-exact
   unfaulted-host prefix comparisons and used `1.5 * 2^1020`, avoiding the Q6
   half-response boundary. Its 18 invocations passed 17: filtered `monitor_fault`
   failed the unchanged double-prefix relative check in the 96-kHz, fresh-history,
   Expression-0.5 lane. This extra source scaling changes rounding near FIR
   cancellations. Q6 monitoring passed. Source/build/logs and result hashes remain.
3. The final source uses exact `2^1021`, retaining power-of-two scaling and moving
   the overflow threshold to quarter-response. All 18 invocations passed without
   changing the `1e-4` threshold margin, `256 * epsilon(binary64)` prefix bound,
   one-ULP float check or any production file.

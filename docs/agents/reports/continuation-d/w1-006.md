## Source findings

- All three variants compile the same [processor](../../../../plugins/vst3/processor.cpp).
  [processor.hpp](../../../../plugins/vst3/processor.hpp) selects the direct,
  filtered or quadrature engine; [plugin_ids.hpp](../../../../plugins/vst3/plugin_ids.hpp)
  fixes their independent identities, state models and 0/48/48-frame latency.
- `initialize` creates one `Stereo Out`; `setBusArrangements` accepts only exact
  stereo and currently makes no SDK bus mutation. `validate_buffers`,
  `silence_outputs` and `render` hard-code two channels and silence mask `3`.
- `render` advances the engine once per frame, computes `(32.0 * gain) * volts`
  once, converts once for float32, then duplicates that identical scalar into
  each supplied stereo channel. Mono needs no DSP change or downmix operation.
- Inspected pinned SDK root `3cdf9ca5d1f5b1b21e0a86832aa4abe55607bd96`,
  public.sdk `586dc5e6c8012c3e4b01c79389375cbe96bdb1da`, and pluginterfaces
  `4f547e8e102b47de4a8b8aaf343c73b700786372` at
  `/workspace/scratch/d6370337c6a4/vst3sdk`. In `vstbus.h/.cpp`,
  `AudioBus::setArrangement` changes the bus's speaker mask; `AudioBus::getInfo`

  activation/processing; no concurrent renegotiation guarantee is proposed.

## Recommended contract and implementation

### Negotiation and metadata

Retain stereo as the default on every initialization. Accept exactly zero audio
inputs, one output, a non-null output-arrangement array, an initialized existing
output bus, and exactly `SpeakerArr::kMono` or `SpeakerArr::kStereo`.
Reject other speaker masks even if their population count is one or two.
Validate all conditions before changing anything. On success, update the SDK
bus's arrangement and name to `Mono Out` or `Stereo Out`; on rejection preserve
both. Derive the active channel count from that same bus, avoiding a second
independently mutable count. Do not call the permissive SDK default setter.

No negotiation should reset mechanics, note ownership, FIR history, configuration,
fault state or pending recall. Keep existing FUIDs, models, controls, state bytes,
sample formats/rates and latencies. The host owns bus layout; do not add it to
the 16-byte configuration stream. Termination/reinitialization returns to the
existing stereo default.

### Buffer, rendering and flush rules

| Case | Required behavior |
| --- | --- |
| Positive frames | Existing setup/mode/frame checks; exactly one bus with the negotiated channel count. Require the correctly typed channel-pointer array. Active bus requires every negotiated sample pointer. |
| Inactive bus | Accept any null/non-null combination within that array; render and advance the engine normally, writing only supplied sample buffers. A null array remains invalid. |
| Mono render | Store exactly the old left-channel scalar. Preserve gain arithmetic, conversion, sample/event ordering and one engine step per frame. No sum, average, normalization or additional conversion. |
| Stereo render | Preserve both current sample values and their equality; only make the bounded write count layout-aware. |
| Silence hints | Use mask `1` for mono and `3` for stereo; nonzero rendered output uses `0`. Apply the layout mask to every early arithmetic-fault exit as well as successful completion. |
| Zero frames | Accept no outputs, or one bus with zero or the negotiated channel count. Never inspect sample pointers. Preserve existing pre-setup, cross-format and valid-mode flush allowance, offset-zero control handling, CC123 release and no cursor advance. Empty-bus flags become `0`; a negotiated mono/stereo bus gets `1`/`3`. |

Complete buffer and event/control validation must still precede mailbox
consumption and live-state mutation. Accepted arithmetic faults retain earlier
samples and leave the pre-cleared failed sample/remainder silent, then fence
processing until the existing reset/recall path.

### Bounded rejected-output cleanup

Keep cleanup independent of whether processing or negotiation is valid. First
require recognized sample format, frames in `[0,8192]`, exactly one output and
a non-null bus array. For positive frames, permit declared counts **1 or 2**,
set mask `1` or `3`, and clear only each supplied non-null sample buffer over
the declared frame count. A null channel array permits flag update but no sample
access. For zero frames, recognize counts `0`, `1`, `2`, update their flags to
`0`, `1`, `3`, and never access sample pointers. Other counts/formats/dimensions
leave all samples and flags untouched. Validate before shifting or traversing.

Thus a mono/stereo count that mismatches the negotiated layout is rejected by
processing but receives bounded cleanup for its supported declaration. This is
an explicit extension of the old stereo-only cleanup contract, not permission
to accept mismatched layouts. Maximum work stays one bus, two channels and
8192 frames per channel. Do not clamp oversized declarations or partially clear
unsupported dimensions and claim silence.

1. Test all three variants and both formats: default stereo; mono/stereo round
   trips; arrangement, name and channel-count agreement; invalid requests
   preserving prior mono **and** prior stereo, including pending recall.
2. Compare mono samples bit-for-bit with a matched stereo left channel and
   compare stereo output with the old module over notes, automation, sustain,
   CC123, pressure, partitioned blocks, recall and filtered/quadrature history.
   Preserve configuration bytes and advertised latency.
3. Cover active/inactive pointer combinations, exact one-pointer mono arrays,
   zero-frame layouts before/after setup, mismatched layouts, partial/null

   mechanics, FIR continuation and retained recall after rejection.

   new positive cases; their malformed mono-layout cleanup expectations also

   native validation. This review establishes a source-based design only;
   actual host delivery, device deadlines and physical fidelity remain untested.

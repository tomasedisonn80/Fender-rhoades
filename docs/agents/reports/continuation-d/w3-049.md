## Helper and workflow control review

- `recorded_command` streams combined native output to an exclusive raw log, hashes it,
  records the actual child status and returns that failure; missing executables return 127.
  POSIX signal exits retain their negative child code and map to shell status; interruption maps to 130.
- Duplicate labels fail before replacing a prior log/command record; Windows retained evidence
  includes the passing duplicate-label regression. Snapshot/comparator JSON writes are exclusive.
  These workflows restore no cached diagnostic directory; no success-producing fallback is present.
- CTest inventory uses the same command/configuration/filter plus `--show-only=json-v1`;
  inventory failure stops execution. The executed command adds separate raw output and JUnit files.
  Every workflow CTest invocation requests `--no-tests=error` and returns the wrapped status directly.
- Metadata records actual Git HEAD/tree, tracked status and per-file disk hashes; mismatched SHA,
  dirty/missing/unmerged tracked inputs, missing before-snapshot or changed before/after identity fails.
  Baseline source and each pinned SDK repository are independently checked, including repository-root identity.
- Toolchain comparison reads cache plus detected compiler files, requires generator/C++ compiler
  path/ID/version, and compares all declared toolchain fields; mismatch returns 1 with retained reasons.
  Baseline publication requires the fixed source, pinned SDK, build cache and three nonempty hashed modules.
- Both matrix workflows use `fail-fast: false`; final metadata and diagnostic upload use `if: always()`.
  Foundation has three such diagnostic-upload paths; VST3 has one, after bundle steps.
- Diagnostic artifact names bind job where needed, OS, architecture, source SHA, run ID and run attempt;
  retries therefore receive distinct names. Missing upload files fail; diagnostic retention is 90 days.
- VST3 archive creation and validated-bundle upload retain the default success condition and follow
  build/CTest/final metadata. They have no `always()` or `continue-on-error` escape.
  The archive verifies required files and complete tar membership, contents, modes and symlinks;
  a failed validation step prevents publishing the validated bundle artifact.

# W1-004 — Expression state and concurrency design audit

Assigned baseline: main `6c91dab`. Scope: read-only implementation/test audit;
only this report is written. No Git or canonical project-state operation was
performed. This is a proposed contract, not implementation or passing evidence.

## Recommendation

Add `float expression = 1.0F` **after** `sustain` in `InstrumentState`, preserving
the meaning of existing `{gain, sustain}` aggregate initializers. Expression is
one global normalized digital control; MIDI channel identity does not enter
saved configuration. Keep Monitoring Gain independent. A v1 recall must set
Expression to one even if the running configuration previously had another value.

Use adaptive serialization: save exact existing v1 bytes whenever the canonical
Expression word is `0x3f800000`; otherwise save the v2 packet below. Decode both
versions. This retains old save-byte fixtures and allows a unity-expression save
to open in an old binary. Non-unity saves require the updated binary. A fixed
20-byte v2 writer is simpler, but unnecessarily changes every existing save and
many independent golden tests. Compatibility concerns are observable wire bytes,
not an obligation to preserve every internal test helper unchanged.

## Exact wire contract

All words are little-endian; model matching remains strict for 1, 2, and 3.

| Offset | Bytes | v1 | v2 |
| --- | --- | --- | --- |
| 0 | 4 | `RHST` | `RHST` |
| 4 | 2 | unsigned version 1 | unsigned version 2 |
| 6 | 2 | immutable model 1/2/3 | same immutable model |
| 8 | 4 | Monitoring Gain binary32 | same |
| 12 | 4 | Sustain exact binary32 0 or 1 | same |
| 16 | 4 | absent; Expression defaults to 1 | Expression binary32 |
| Total | — | exactly 16 | exactly 20 |

Reject every other version, unsupported/mismatched model, and version/length
mismatch, including 20-byte v1 and 16-byte v2. Validate length before header or
payload indexing. A valid v2 Expression of one may be accepted and canonicalized
to v1 on the next save. No migration silently discards a non-unity value.

Both normalized float fields accept unsigned words `0..0x3f800000` and negative
zero `0x80000000`; canonicalize only signed zero to positive zero. Sustain keeps
its existing accepted input words `0`, `0x80000000`, and `0x3f800000`. Reject
negative nonzero values, values above one, infinities and both NaN classes through
integer checks. Avoid floating equality in validation or the v1/v2 selection:
preserve positive subnormal payloads and the existing FP-control/status contract.

## One-word mailbox, unchanged protocol

Normalized nonnegative binary32 values through one require only 30 payload bits.
Canonicalize negative zero before packing, and validate before any store/CAS.

| Atomic word bits | Meaning |
| --- | --- |
| 0–31 | Existing Monitoring Gain word; bits 30–31 remain zero |
| 32 | Existing Sustain flag |
| 33 | Existing pending-recall flag |
| 34–63 | Expression word bits 0–29 |

Pack as `uint64_t(gain_word) | (uint64_t(sustain) << 32) |
(uint64_t(expression_word) << 34)`; the pending flag is added only by the mailbox.
Unpack gain from the low 32 bits, sustain from bit 32, and Expression from
`uint32_t(packed >> 34)`. Maximum Expression uses bit 63, so shifts and storage
must remain unsigned. Full precision, including the smallest positive subnormal,
survives; no quantization beyond the existing binary32 state contract is needed.

Keep the lock-free 64-bit static assertion, acquire/release orderings, one-attempt
`begin_block`/`end_block`/`abort_block`, and single audio owner. The complete triple
must be one atomic publication. A second Expression atomic could tear snapshots;
a 128-bit atomic adds an unnecessary platform requirement. Two reclaimed gain
bits could support future metadata, but changing this protocol is outside scope.
Identical later recalls must still set pending and defeat an older publication.

## Codec and stream API choice

Lowest-churn option: retain `instrument_state_bytes == 16` and
`EncodedInstrumentState = array<uint8_t,16>` explicitly as the legacy format.
Keep the existing encoder as a v1-only compatibility entry point that rejects
non-unity Expression. Add an explicitly adaptive encoder returning an optional
packet with 20-byte fixed backing, an actual 16/20 length, and a const byte-span
accessor. `write_state_stream` and new non-unity fixture loaders use that adaptive
entry point. Add separate v2/max constants. Generalize the private word writer to
a mutable span or bounded array template. The decoder already takes a byte span.

If the integrator prefers one generic encoder name for all states, migrate its
return type to the same packet value and update callers deliberately. A bare
`variant<array<16>,array<20>>` requires visitors at every size/data/iteration use;
it provides little benefit here. Avoid an implicit conversion to a 16-byte array
or a 20-byte array masquerading as a legacy packet. Existing golden arrays stay
literal independent fixtures regardless of API choice.

Reader: retain `tell`, seek-to-end and exact-position restoration checks; allow
only remaining lengths 16 or 20, read into a fixed 20-byte buffer, and decode only
the actual populated span. With positive progress, use at most the selected
length in read calls. Writer: fully validate and select the packet before the
first write, then use its actual length, with at most 16 or 20 calls. Preserve
failure on errors, zero/negative/overreported transfers; neither helper truncates
host-owned destination storage. Streams remain UI-thread helpers, with no heap
allocation or stream work in the audio callback.

## Existing coverage and required changes

Audited `instrument_state.hpp`, `state_stream.*`, both threaded state suites,
the codec/property/FP/model tests, stream-contract suite, controller/processor
state plumbing, and relevant shared fixture helpers. Current threaded coverage:

- `state_concurrency_test.cpp`: five ordered consume/publish/abort races, including
  identical recalls; three-thread 100,000-iteration stress and a quiescent final
  recall. Keep these and add distinct Expression payloads, including a pair that
  differs only in Expression, so coherence checks cover all three fields.
- `vst3_state_concurrency_test.cpp`: independent v1 wire oracle, eight ordered
  accepted/rejected preflight scenarios per variant, and callback/save/recall
  stress at float/48 kHz and double/192 kHz. Add a three-parameter automation
  fixture and independent mixed-v1/v2 packet oracles; compare both bytes and
  length. A version-byte mutation from 1 to 2 remains invalid for a 16-byte
  packet, but a v2 negative fixture must instead use an unknown version or bad
  length. Cover v1 replacing pending v2 and v2 replacing pending v1.

Existing unity fixtures can remain valid. One known intentional adjustment:
`vst3_stream_contract_test.cpp::malformed_state` currently expects zero reads
for every remaining length other than 16 through 32. Remaining length 20 now
requires reading the candidate before rejecting its v1 header; update only
that transfer-count expectation, retaining rejection and unchanged live/pending
state. Other legacy rejection expectations should not be widened casually.

Controller recall must prevalidate all three parameter objects and conversions
before setting any; controller save must include its quantized Expression.
Processor recall already assigns the whole state. Extend zero-frame automation,
audio publication and lifecycle preservation to retain the new member; do not
reconstruct a two-field aggregate from a non-unity live state. Shared
`MemoryStream::load` must use the adaptive encoder for non-unity tests.

## Independent acceptance cases

1. Preserve every literal v1 golden for all three models, and assert decoded
   Expression bits are exactly `0x3f800000`. Independently construct v2 bytes for
   `{gain=.5, sustain=true, expression=.25}`: header version `02 00`, expression
   tail `00 00 80 3e`. Check v2 unity canonicalizes to the original 16-byte save.
2. Exercise all lengths around both formats, unaligned spans, every header byte,
   all six ordered model mismatches for each version, and unchanged input bytes.
   Reject an extended v1 even if its tail happens to be a valid Expression word.
3. Extend the independent 19,474-word domain corpus to Expression. Probe zero,
   negative zero, minimum/maximum subnormal, minimum normal, nextafter(one,zero),
   one, nextafter(one,+infinity), negative subnormal, infinity and signaling NaN.
   Invalid recall/publication must preserve an existing pending triple and token.
4. Under available FTZ/DAZ modes, assert exact Expression bits through decode,
   pack/snapshot, consume, abort, publish and re-encode; preserve FP controls and
   status behavior. Do not compare subnormal expectations with float equality.
5. For both packet sizes and every chunk size 1..20, check exact transfer counts,
   prefix/tail guards and failures at every transfer position. Include non-unity
   pending recall, v1 restoration to unity, failed controller recall, and retry.
6. In ordered and stress concurrency tests, verify triples cannot mix, stale
   publication/abort cannot overwrite expression-only or identical newer recalls,
   the final recall is consumed once, and rejected blocks leave all mechanics,
   note ownership, gain/sustain/Expression and pending state unchanged.

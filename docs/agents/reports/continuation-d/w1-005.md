## Recommended exact behavior

1. **Identity and bounded collection.** Add `kExpressionId = 2`; retain gain
   `0`, sustain `1`, and CC123 IDs `0x1000..0x100f`. Set
   `kControllerParameterCount = 3 + kMidiChannelCount = 19`. The duplicate-queue
   bitmap must use slots `0/1/2` for the scalar controls and `3 + channel` for
   CC123; retaining the current `2 + channel` aliases Expression and channel 0.
   Reject unknown IDs and repeated queues, including empty repeated queues.
   Expression has at most 8192 **raw** points, independently of deduplication.
   Every point must be readable, normalized under `control::valid_normalized`,
   nondecreasing in offset, and within the existing offset envelope. Quantize
   anchors with `control::quantize`; canonicalize signed zero. A valid later
   duplicate cannot hide an earlier unreadable or invalid point.

2. **Independent interpolation.** Expression defaults to `1.0F` and follows
   gain's existing curve contract independently. Collapse duplicate offsets
   before rendering, with the last point replacing the whole interpolation
   endpoint. Start each block from its prior/recalled stored value at offset
   `-1`. For adjacent anchors `(l,L)` and `(r,R)`, evaluate
   `L + (R-L) * (double(frame-l)/double(r-l))`; use the exact widened anchor at
   its offset, and hold the last anchor thereafter. Missing/empty queues hold
   the stored value. Quantize only the persisted per-frame boundary value;
   use the interpolated binary64 value for audio, as gain currently does.
   Compute/validate both scalar boundary values before assigning their pair.
   Expression affects host-rate output at the delivered host offset, after
   any existing FIR; it adds no latency or physical dispatch event.

3. **Output and unity preservation.** Preserve the original operation order:
   `monitored = (32.0 * gain) * volts`. Check engine success and finite
   `monitored`, then compute
   `converted = expression == 1.0 ? monitored : monitored * expression`.
   Check finite final binary64 and, for 32-bit output, the final float cast.
   The explicit unity bypass introduces no extra floating operation in the
   legacy output path, including host flush modes; do not fold Expression
   into the original gain multiplication. A smaller Expression can rescue a
   finite binary64 value from float overflow, but cannot mask nonfinite engine
   or monitoring output. Expression zero mutes output while notes, ownership,
   mechanics, FIR history and cursors continue normally; never skip synthesis.

4. **Recall, lifecycle and flush.** A selected recall resets mechanics,
   ownership, cursor, filter history and fault state, then installs all recalled
   configuration before current-block automation. Legacy state decoding must
   supply Expression `1` for compatibility. Lifecycle resets preserve current
   Expression like gain. A valid zero-frame flush accepts offset-zero points
   only, applies the final Expression after recall alongside gain/sustain, and
   performs the existing staged CC123 releases without advancing time or
   accessing sample pointers. Repeated empty flushes hold configuration.

5. **Rejection versus accepted arithmetic failure.** Stage every Expression
   point before consuming a mailbox recall or mutating live state. Ownership,
   dispatch and cursor preflight must still finish before installation. Late
   malformed Expression, duplicate queues or over-budget input preserve live
   configuration, ownership, mechanics, faults and pending recall; retain the
   current bounded rejection-clearing policy. After acceptance, interpolation,
   engine or conversion failure latches reset-required, retains successful
   output prefix, leaves failed/remainder samples zero, publishes the last
   committed configuration and does not roll back accepted ownership. Commit
   the valid scalar pair before DSP, preserving gain's existing failed-sample
   configuration policy. Zero Expression must not bypass fault detection.

## Memory, work and tests

Add one instance-owned `std::array<ParameterPoint, 8192>` and its count, plus
constant-size rendering cursors. This adds `8192 * sizeof(ParameterPoint)`
bytes (64 KiB with the current 8-byte layout). Extra work is O(Expression raw
points + frames), each bounded by 8192. All three scalar queues together allow
24576 raw points, plus 256 aggregate CC123 points: at most 24832 parameter-point
getter calls. Existing note/dispatch limits and bounded CC123 sorting remain
unchanged. No allocation, locks, recursion or extra core event are required.
Host getter behavior still prevents a wall-clock deadline guarantee.

Extend the independent barycentric automation oracle to independent gain and
Expression curves, retaining binary32 endpoint and boundary assertions. Cover
last-duplicate endpoints affecting earlier ramp samples, empty queues, ties,
all queue permutations, late malformed points, pending recall, zero-frame
flushes and exact legacy unity output in float/double for all three variants.
Compare muted mechanics/FIR/ownership against an unmuted reference and verify
audio recovery after reopening Expression. Exercise all 19 distinct queues
together and rejection at 20, especially Expression alongside CC123 channel 0.
The shared `ParameterChanges` and automation fixture currently hold only two
queue pointers; extend their capacity deliberately without dropping the old
gain/sustain cases. Add max-capacity allocation probing and fault-latch coverage.

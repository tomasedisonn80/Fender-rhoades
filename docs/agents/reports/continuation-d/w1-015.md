## Minimal patch plan for the integrator

### 1. Isolate deliberate verification

Replace the two concurrency blocks with this pattern, retaining the existing
`foundation-` or `vst3-` prefix:

```yaml
concurrency:
  group: foundation-${{ github.workflow }}-${{ github.ref }}-${{ (github.event_name == 'workflow_dispatch' || github.run_attempt > 1) && github.run_id || 'automatic' }}
  cancel-in-progress: ${{ github.event_name != 'workflow_dispatch' && github.run_attempt == 1 }}
```

Initial automatic runs continue to supersede older automatic runs for the
same workflow/ref. Each dispatch and each deliberately rerun workflow uses its
own run-ID group. Including `run_attempt > 1` matters because clicking rerun
does not convert a push event into a dispatch. Changing only
`cancel-in-progress` is insufficient: an incoming push would still cancel a
manual run in a shared group. Unique manual groups also avoid replacement of
a pending manual run by another pending run.

This cannot retrofit the workflow definition attached to an old run. Start a
new dispatch from the patched ref for verification of the new feature. Old
reruns retain their original source SHA and ref.

### 2. Bind evidence to the actual checkout

Add a small `shell: bash` metadata step after checkout and before configure or
tests in each job. Use `.` as the source directory in Foundation and `source`
in VST3. Create `ci-evidence/`, record actual `git rev-parse HEAD`, Git tree,
expected `GITHUB_SHA`, workflow ref/SHA, ref, event, run ID, attempt, job,
runner OS/architecture and tool versions. Fail unless actual HEAD equals
`GITHUB_SHA` and tracked source is clean. Do not dump the entire GitHub context
or environment. Record tracked source cleanliness again after testing so a
generated or modified implementation cannot silently inherit the commit label.

For VST3, persist the already checked SDK/submodule actual revisions in this
directory rather than retaining them only in the Actions console. Preserve
all existing checkout and SDK pins. For stronger input verification, a small
stdlib manifest of tracked code/test/CMake inputs before and after testing is
appropriate; do not substitute a commit name for evidence of a dirty tree.

### 3. Retain raw outcomes without changing test selection

For all three CTest commands, keep existing options and add absolute evidence
paths for `--output-log` and `--output-junit`. Save
`--show-only=json-v1` output using the same configuration and VST3 regex;
this records selected registered tests without executing them twice. Retain
the matching `Testing/Temporary` directory, particularly `LastTest.log` and
any `LastTestsFailed.log`, alongside the console log and JUnit XML. The build
directories are `build`, `build/sanitize`, and `build/vst3`, respectively.

Capture Python unittest output and its original exit status under
`ci-evidence/`. An explicit Bash step using `tee` must preserve pipeline
failure (`pipefail`, with the test process's status retained); no
`continue-on-error` or status-masking `|| true`. Retain test commands, exit
codes and step outcomes. A missing test result after an earlier failure is
incomplete execution, not a pass. Use inventories plus actual XML/log statuses
to distinguish registered, executed, passed, failed and skipped counts.

### 4. Upload evidence on failure as well as success

Add a final `if: always()` evidence upload to each job, reusing the existing
repository pin:

```yaml
- name: Retain raw verification evidence
  if: always()
  uses: actions/upload-artifact@cf430e030ddbb5b0abf93d22962f4752f3646cd9
  with:
    name: foundation-${{ github.job }}-${{ runner.os }}-${{ runner.arch }}-${{ github.sha }}-${{ github.run_id }}-${{ github.run_attempt }}
    path: |
      ci-evidence/
      build/Testing/Temporary/
    if-no-files-found: error
    retention-days: 90
```

Use the job's correct build directory and `vst3-` prefix where applicable;
Python has no CTest path. Check the repository retention ceiling before using
90 days. Keep the existing success-only bundle archive behavior and its
seven-day retention; the longer-lived evidence artifact is small. Append run
ID and attempt to the bundle name too, avoiding immutable artifact-name
collisions when a successful run is deliberately rerun. Never overwrite the
earlier attempt's evidence. Optionally record the bundle archive SHA-256 in
the evidence manifest when that archive exists.

`always()` is best-effort collection after an executed step; it cannot create
logs for a job canceled while still queued or recover a terminated runner.
The integrator must download and hash acceptance evidence before expiration
and register immutable retained copies through the existing evidence process.
No release trigger, permission broadening, action/SDK upgrade, or new package
dependency is needed.

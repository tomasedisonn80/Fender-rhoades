## Production invariants reviewed

### State bytes and the 64-bit mailbox

The appended Expression field defaults to unity, preserving the meaning of
existing `{gain, sustain}` aggregate initializers. The v1 encoder rejects
nonunity Expression before writing anything; the v2 encoder adds exactly four
little-endian bytes. Decode length, version and requested model are checked
together, and v1 supplies unity explicitly. The adaptive stream writer chooses
the encoding from canonical bits. Its reader uses a 20-byte local buffer but
accepts only exact 16/20-byte extents. Nonnegative ordered stream positions make
`end - start` safe, and transfer counts are checked before advancing the span.
The host remains responsible for destination truncation.

Every valid canonical Expression word is in `0x00000000..0x3f800000`, strictly
below `2^30`. Casting to `uint64_t` **before** shifting by 34 therefore retains
all thirty bits and cannot overlap gain bits 0–31, sustain bit 32, or pending
bit 33. Unity occupies `0xfe00000000000000`; shifting it back yields
`0x3f800000`. Negative zero canonicalizes before packing. Unpacking with a
logical unsigned shift discards the pending bit without requiring an additional
mask. Invalid expressions are rejected by the mailbox's public write and
publication methods before the unchecked internal packer is reached.

The existing single-consumer protocol still performs one load and at most one
CAS per operation. A newer UI write includes the pending bit, preventing an
older clear publication token from overwriting it. An aborted selected recall
is restored only if that token still matches. No retry loop, lock, stream call,
or allocation was added to these operations. The reported concurrency fixtures
respect one serialized audio/lifecycle owner; they do not justify overlapping
audio consumers or exhaustive schedule coverage.

### Live anchors, recall and queue indexing

Syntax preflight copies and validates every supplied queue/point/event before
mailbox consumption. Ownership expansion then operates on a candidate tracker;
failure aborts a selected recall without committing mechanics or ownership.
Successful recall is installed before rendering or zero-frame controls.

Both interpolation anchors come from `live_state_` after that selected recall.
They do not read a potentially newer pending mailbox snapshot. Gain and
Expression have separate point arrays, counts, cursors and offset-minus-one
anchors. Each raw point is validated before duplicate offsets collapse to the
last value. Both per-frame controls validate before either canonical saved
field is committed. End-of-block publication remains whole-configuration CAS
publication, so a newer UI recall wins without changing the in-progress audio
owner's anchor.

The dense duplicate map is exactly nineteen entries: persistent IDs 0, 1 and 2
use indexes 0, 1 and 2; CC123 channel 0 through 15 uses indexes 3 through 18.
Unknown IDs reject before indexing. Queue/count validation precedes point
traversal, command accumulation retains its separate 256-point budget, and
gain/Expression do not enter the physical dispatch budget. The maximum issued
point-getter count remains the explicit new bound `3 * 8192 + 256 = 24832`.
Foreign getter execution time is outside that bound.

The controller registers the new continuous `0..1x` control at ID 2 and maps
all sixteen CC11 inputs to that ID. Text conversion retains the existing
binary64 domain check before canonical binary32 conversion. CC123 values keep
their binary64 precision and do not acquire the factor suffix. Controller
recall checks all three persistent parameter objects before applying them;
the sixteen transient command values remain separate.

### SDK layouts, actual factory metadata and output pointers

The pinned SDK's `AudioBus::getInfo()` derives its channel count from its
arrangement. Updating that bus's arrangement and name therefore keeps
`getBusArrangement`, channel count and name coherent. Those setters do not
change its activation state. Unsupported requests return before either setter.
Negotiation remains a suspended-host operation; this implementation does not
provide synchronization for concurrent live layout changes.

The SDK defines optional `Mono`/`Stereo` category tokens for plugins restricted
to that width. The corrected shared factory uses `Instrument|Synth`. The
[category correction record](../../../validation/host-expression-category-correction-20261124.json)
retains the real first loaded assertion failure and the subsequent three
loaded-expression plus six SDK/module-validator passes. The new loaded
assertion is on the actual factory, not a copied production constant. This
review does not reclassify that prior defect as newly discovered here.

For positive blocks, buffer validation selects exactly one or two pointers from
the negotiated bus width. An inactive supplied bus still requires its pointer
array; individual sample pointers may be null. A zero-output block is accepted
only when the sole output is inactive. Validation, rendering, fault handling
and rejection cleanup all avoid forming or dereferencing `outputs[0]` in that
omitted case. Zero-frame processing accepts the documented shapes without
inspecting sample pointers.

Cleanup has a separate bounded envelope: one declared bus, a declared width of
one or two, and at most 8192 frames. It may clear a supported-width mismatch,
but does not traverse unsupported channel counts. The render and fault paths
write silence masks 1/3 only when an output exists. Mono receives the same
scalar as either stereo channel; no channel sum or level compensation was added.

### Arithmetic inspection is not arithmetic execution

The inspected order is the required one: preserve `(32.0 * gain) * volts`,
check engine status and monitored finiteness, apply Expression with an exact
unity bypass, then convert/check the host sample. Conversion happens before
the channel-writing loop even when its width is zero. The fault closure
publishes the current controls, retains the successful prefix and latches the
existing reset-required behavior; initial bounded clearing leaves the failed
sample/remainder silent where buffers exist.

That source order does **not** execute an arithmetic fault. Normal expression
zero tests, malformed-input rejection, and template-core fault fixtures cannot
substitute for the concrete host path identified in [W2-031](w2-031.md).

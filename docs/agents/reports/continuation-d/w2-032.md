The raw host fixture contains exactly three 8,192-point persistent buffers and
sixteen 256-point command buffers. All complete traffic fixtures, processor
hosts, scalar engines and large snapshots are heap-owned. The nineteen queue
objects hold spans into those buffers; there are no nineteen full persistent
queue arrays on the test thread stack. Point counts, duplicate offsets, invalid
values and failing final getters are supplied directly to the adapter without
host-side sanitization. Construction, stream recall, copied-engine comparisons,
diagnostics and destruction happen outside the measured `process()` interval.

Every host getter category has an independent counter: parameter count, queue
lookup, parameter ID, point count, point retrieval, event count and event
retrieval. Each queue also counts its own ID/count/point calls, allowing the
offending queue to be distinguished from preceding valid queues. The fixture
getters themselves use fixed storage and constant work; this describes these
test hosts, not the behavior of arbitrary foreign host implementations.

The dispatch oracle maintains its own per-key holder counts and drives the
selected scalar `ResearchEngine`, `AudioEngine` or `QuadratureEngine` directly.
It does not use `NoteTracker`, adapter command expansion or adapter dispatch for
the expected actions. It checks exact output bits, modal state, holder counts,
cursor, live/published state and silence flags. The simultaneous gain/expression
curves use independent barycentric calculations on an exactly representable
64-sample dyadic span. No audio tolerance is used. This is an independent
adapter-action oracle sharing the physical core, not independent validation of
the core's physics.

Rejection checks preserve current and published configuration, ownership,
cursor, fault state and modal state. They additionally compare 129 future core
samples from heap-owned engine copies, covering the existing 96-frame filter
history before a pending recall could conceal damage. The late maximum-input
failures retain an independently authored v2 nonunity recall, which a later
valid flush must actually consume.

a bound on the execution time or internal work of a host getter.

## Allocation probe scope

The replacement operators cover scalar/array ordinary, nothrow, aligned and
aligned-nothrow `new`, and unsized, sized, nothrow, aligned, sized-aligned and
aligned-nothrow scalar/array `delete`. The calibration explicitly invokes all
eight allocation forms and all twelve deallocation forms using twelve
allocations and twelve frees. Direct operator calls keep this positive control
active in the optimized Release build; calibration is reported separately from
processor observations.

For workload observations the guard begins immediately before `process()` and
ends immediately after it returns. Assertions and exception construction run
after the guard has ended. There are no measurements of arbitrary `malloc`,
allocator implementations outside the intercepted calls, locks, stack maxima,
CPU maxima, worst-case response time, callback deadlines or audio-device
behavior. Passing this probe does **not** establish lock freedom. Foreign host
getters may do unbounded work even though the number of calls made here is
bounded.

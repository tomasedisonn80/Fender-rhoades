## Bundle and identity findings

All three bundles contain their expected native module below
`Contents/x86_64-linux/`, with names matching
[Vst3.cmake](../../../cmake/Vst3.cmake) and
[VST3.md](../../VST3.md): `RhodesResearch.so`,
`RhodesResearchFiltered.so`, and `RhodesResearchQuadrature.so`.
Each has `Contents/Resources/moduleinfo.json`, `LICENSE.txt` and
`THIRD_PARTY_NOTICES.md`.

The generated metadata contains the six distinct processor/controller CIDs from
[plugin_ids.hpp](../../../plugins/vst3/plugin_ids.hpp). Versions are respectively
`0.1.0`, `0.2.0` and `0.3.0`; the factory category is
`Instrument|Synth|Stereo`. All three independent metadata validations succeeded:

```sh
build/vst3/bin/Release/moduleinfotool -validate -path ABSOLUTE_BUNDLE_PATH
```

The official SDK tool returned zero with empty stderr for each bundle. Its
generated metadata uses trailing commas; tests should use the SDK parser rather
than incorrectly requiring Python's strict JSON parser to accept that format.

An independent byte comparison confirmed all three bundled SDK notices match
all five pinned SDK `LICENSE.txt` files. Every bundled notice index matches the
project source. No Python audit dependencies, VSTGUI, SDK examples, or research
data appear in these bundle directories.

## CI coverage and retained packaging gap

The current [workflow](../../../.github/workflows/vst3.yml) builds all three
modules, runs `^vst3\.` CTests, then archives only the three complete bundle
directories. Its inner tar preserves modes and symlinks; verification compares
archive entries, regular-file hashes and link targets before artifact upload.
Artifacts are explicitly experimental and retained for seven days. No current
archive-layout mismatch was found.

Reviewed existing `build/vst3-ctest.log`, rather than rerunning its tests: all
three SDK validators, triple-module coexistence/duplicate guard and
`vst3.bundle_resources` passed in that recorded run. The resource test validates
the notices but does not independently validate `moduleinfo.json` against the
loaded factory. The pinned SDK validator's compatibility test is not that full
metadata comparison. **A useful small follow-up is three retained CTests invoking
`moduleinfotool -validate -path`, one per bundle.** The successful commands above
establish that adding this packaging guard is feasible without new dependencies.

## Installation and portability boundary

The guide correctly requires retaining complete bundles, disables automatic
installation links, and explains generic host controls and the three instrument
names. It delegates scanning/installation to the selected host; there is no
installer or custom editor. Native DAW execution was not exercised here.

`readelf --version-info` on each current Linux module reports maximum required
symbol versions `GLIBC_2.38`, `GLIBCXX_3.4.29`, and `CXXABI_1.3.9`. These agree
with the existing portability warning; they do not establish support for older
Linux distributions. The original-code license remains an owner decision under
[RIGHTS.md](../../../RIGHTS.md); the bundled SDK notice is not a license for the
project's original code. No distribution-readiness claim follows from this audit.

## Confirmed protocol conformity

The launcher validates canonical plan SHA-256
`df03962a1c3406a7528b3e7d71c784e65f891ad940e7a04ea1c46006ddec5fad`
and iterates its exact argument lists in sequence. Independent summation of the
frozen profiles and runs gives **72 processes, 40,128 measured callbacks,
2,136 warmup callbacks, 3,846,144 measured host frames, and 338,304 warmup host
frames**. Round one visits p01–p12 and round two p12–p01; each variant occupies
each within-profile position eight times.

Each run uses a fresh child, inherited scheduler/priority, and an attempted
single-CPU binding to the lowest initially allowed logical CPU. The parent waits
for completion before starting another. Timeout is the plan's 180 seconds;
timeout kills and reaps the direct child, retains stdout/stderr and does not
retry. The native timed region contains only `processor.process(data)` between
steady-clock observations. Scheduling, warmup/reset, output verification and
JSON formatting remain outside it. Launcher monotonic start/end timestamps are
whole-process evidence, separate from callback durations.

The verifier recomputes sorted binary64 mean, nearest-rank percentiles, maximum
and strict nominal-period exceedance count consistently with the native summary.
Additional `math.fsum` and input-order means preserve rounding distinctions.
It does not turn callback speed into a pass criterion. Required workload and
identity checks cover callback counts, frames, ownership, getters, stereo,
output presence, model and latency. All 36 repeat pairs are considered.

## Two reproduced defects requiring repair before capture

**Affinity failure does not abort the protocol.** If the child cannot establish
binding, no valid affinity record is written. The parent marks that run
`incomplete` but continues the matrix and finally returns integrity failure 1.
The frozen policy requires stopping with an operational record and an inventory
of unattempted runs. A two-run mocked execution with failed children and no
affinity record spawned both children, returned 1 and recorded
`status=integrity_failure`. Preserve the attempted child's raw output and record,
then abort operationally when its declared binding cannot be verified. A
pre-exec child-error record would distinguish binding failure from later
executable failure.

**Malformed parsed output can crash repeat analysis.** The parser accepts a
syntactically valid JSON array such as `[]`; `verify_result` rejects its shape,
but `raw_results` still retains it. Repeat analysis subsequently calls `.get`
on that array and raises an uncaught `AttributeError`. A two-run mock with valid
affinity records and array stdout reproduced the exception. The final manifest
said `operational_failure` but had no `operational_error`; `main` did not return
its intended status. Require object-shaped output/integrity before repeat field
access, retaining malformed cases as explicit failed observations.

Both findings were sent to the root integrator before measurement. Neither
changes the frozen workload, timing threshold or DSP.

## Environment and verification boundary

Repeated input hashing and metadata capture happen outside callback timing.
They do not establish an idle or isolated machine. Finish compilation and all
heavy worker activity before capture, retain competing activity honestly, and
interpret both rounds as observations from a shared container. Native failures
with otherwise valid affinity may be retained and followed by subsequent runs;
loss of the required execution environment is different and must stop capture.

The design is sound subject to these transaction conditions:

- Current `process()` calls `begin_block()` before ownership/dispatch preflight. `abort_block()` restores its recall unless superseded, but this does not literally satisfy the new “complete preflight precedes mailbox consumption” wording. Resolve that distinction explicitly. Ownership translation must use empty holders when the selected token applies recall; preflighting only current holders produces incorrect capacity/release decisions. Preserve compare-exchange publication so a newer concurrent recall wins.
- `release_key()` must reject invalid keys and existing faults without calling the engine or introducing a new fault. An unexpected valid-key `note_off()` failure must latch the fault. After accepted mutation starts, stop on failure, return failure, and finish mailbox publication; never invoke rollback-oriented `abort_block()`. Audio ownership remains exclusive.
- Apply recall, final sustain, then staged physical releases. A recall legitimately resets mechanics/history; ordinary CC123 alone must preserve them. Check release results rather than silently accepting a partial flush.

Required regressions: all three engines; cursor, modal position/velocity, and subsequent FIR output unchanged except release damping; shared-channel holders; duplicate/zero-valued commands; sustain down/up; pending recall overriding old holders; malformed final point and expansion overflow preserving ownership/configuration/pending recall; concurrent identical/different recalls; null buffers and inactive buses; injected release failure, fault fence, and explicit recovery.

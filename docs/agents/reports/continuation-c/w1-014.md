# W1-014 — Generic-editor playability and compatibility

Reviewed required project documents, `HOST_MIDI_20261124.md`, `docs/VST3.md`, and controller/ID implementation. Source inspection only; no DAW tests performed.

**Recommendation:** append sixteen parameters after gain/sustain; IDs `0x1000..0x100f`, titles `All Notes Off Ch 1` through `All Notes Off Ch 16`, short titles `ANO Ch1` through `ANO Ch16`, empty units, default `0`, continuous normalized range `0..1`, and explicit `kNoFlags`. Keep writable and visible. Use strict numeric round-trip text; values convey neither strength nor latched state. Avoid `Off`/`On` labels and automatic return-to-zero host edits: zero itself triggers release. A generic editor may show sliders; document these as commands.

Every delivered point releases that channel's holders, preserving other channels' ownership, sustain and physical/convolution tails. This enables targeted stuck-note cleanup without promising immediate silence. CC120 remains unmapped.

Repeated identical CC123 values may be omitted by a DAW; same-valued editor edits may likewise deliver no processor point. The plug-in cannot reconstruct missing commands. Qualify repeated delivery only through named DAW tests. Pressure should be described as accepted and ignored, with no advertised expressive response.

Preserve gain/sustain IDs, order, ranges and automation flags, all class/model identities, and the exact 16-byte state. Never serialize commands. Appending controls preserves ID-based automation compatibility; host-specific snapshots still need testing. Update the guide's existing CC123 exclusion and two-queue description.

# Worker 001 — VST3 lifecycle audit

Scope: source audit of lifecycle and malformed-host behavior; no implementation changes, native test execution, or Git mutations.

Read `AGENTS.md`, required current project documents/state, the host contract, processor implementation, lifecycle/buffer tests, and the locally pinned SDK headers.

## Findings

1. **Lifecycle rejection has a coverage/contract gap.** `plugins/vst3/processor.cpp:90–99` unconditionally resets mechanics, ownership and pending recall for `setActive` and `setProcessing`, even before initialization or after termination. `setupProcessing:71–87` verifies setup values but cannot distinguish active/processing instances. `validate_buffers:137–156` checks initialization/configuration, so positive-frame processing remains accepted after `setProcessing(false)` or `setActive(false)`. The SDK base `Component::setActive` is a no-op success, so it supplies no missing guard. This is demonstrable source behavior, but concerns malformed call ordering: no conforming-host lifecycle defect was established.

   **Action:** first declare whether the adapter promises rejection of invalid lifecycle order. If adopted, track activation/processing and reject invalid transitions before `reset_audio_owner`; preserve legal zero-frame parameter flushes. Avoid changing this casually: `tests/cpp/vst3_host_test.cpp:680–700` deliberately renders between reset transitions without restarting, and filtered/quadrature tests use related shortcuts. A smaller compatible hardening is rejecting lifecycle calls on uninitialized instances without consuming pending recall.

   **Proposed test:** snapshot live/published state, ownership and cursor; test calls before initialization and after termination; verify rejected calls preserve everything. Separately exercise the complete initialize/setup/activate/start/process/stop/deactivate/terminate sequence for all three models.

2. **No unbounded work found in lifecycle resets.** `reset_audio_owner:131–135` uses the existing single-attempt mailbox protocol and fixed engine resets. Setup performs preparation outside the processing path. Concurrent malformed lifecycle calls are outside SDK ordering guarantees; this audit does not claim race freedom for them.

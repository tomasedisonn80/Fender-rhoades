## Source findings

The dual/triple fixtures check distinct factory/class identities, coexistence,
independent audio/reset behavior and foreign-state rejection. They close all
instances before releasing module wrappers; they do not exercise continued
processing while a peer module is removed. Loaded-MIDI visits the three variants
sequentially, using separate command/oracle instances within each module.

Normal shutdown stops processing, deactivates, terminates and releases plug-in
interfaces before final harness module ownership ends. SDK loaders clear their
factory reference first. Linux then calls `ModuleExit`/`dlclose`; Windows calls
optional `ExitDll`/`FreeLibrary`; macOS calls `bundleExit` and releases its
`CFBundleRef`, without explicitly calling `CFBundleUnloadExecutable`.

`Module::Ptr::use_count()` measures C++ wrapper ownership. It does not measure
OS image references. No fixture observes image unmapping, fresh static
initialization or named-DAW cache/unload behavior. The dual fixture's
`ModuleExit/dlclose` comment is Linux-specific; C++ remains frozen.

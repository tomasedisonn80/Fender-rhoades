# W4-066 — Portable retained-raw snapshot replacement tests

## Observed failure and diagnosis

Read the actual Foundation CI log for
[run 45373649826, Windows job 138374005202](https://github.com/baabi-boo/Fender-rhoades/actions/runs/45373649826/job/138374005202),
which checked out `ce59b0c254ab99b399f03e63094b10ce10933e71` on Windows Server
2025 with CPython 3.11.9. The reported failure was
`test_replacing_path_during_snapshot_read_is_rejected`, line 511:
`replaced` was `[]`, while the test expected `[True]`.

The fixture attempted `os.replace` from inside its `os.read` hook, while the
snapshot descriptor remained open. Its generic rejection helper accepted any
`ValueError` or `OSError`. Consequently, an error raised by the replacement
operation itself could satisfy that assertion before `replaced.append(True)`;
the assertion did not establish that the snapshot identity guard rejected an
actual replacement. The log did not retain the intercepted exception or its
WinError, so the precise original operating-system error remains unobserved.

Windows open-file sharing restrictions explain this failure path, but this
runtime diagnosis remains an inference pending the new native probe. Microsoft
documents that rename/delete access requires compatible sharing, including
`FILE_SHARE_DELETE`, and that a handle's sharing options remain effective until
it closes ([CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)).
The test now observes that capability explicitly rather than treating a failed
replacement as evidence of the snapshot guard.

## Changes and retained coverage

Changed only `tests/python/test_contact_extrema_raw.py` and this report.

- Added mandatory
  `test_changed_path_identity_during_snapshot_read_is_rejected`. It reads the
  genuine archive through the real descriptor and then makes only the leaf
  `lstat` identity (`st_ino`) differ. Size, mode, timestamps, device, bytes and
  the descriptor's real metadata remain unchanged. The test requires the exact
  `Raw reference changed during snapshot read` error and confirms that the
  complete original bytes were read. It runs on every platform and covers the
  pathname-versus-open-descriptor identity comparison without requiring a
  filesystem rename capability.
- Retained the real `os.replace` race test. It first probes replacement while a
  read-only descriptor is open, outside any expected-rejection assertion. A
  skip is allowed only for `PermissionError` on `os.name == "nt"` with native
  `winerror` 5 or 32, and only after closing the descriptor and successfully
  repeating the same replacement. Microsoft identifies these codes as access
  denied and sharing violation, respectively
  ([system error codes](https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--0-499-)).
  Missing paths, unexpected errors, non-Windows permission failures, and a
  replacement that still fails after close remain failures. The explicit skip
  reason includes the native exception text.
- Where the probe succeeds, the real replacement still occurs inside the
  snapshot read hook, must complete once, and must produce the exact snapshot
  guard error. An arbitrary `OSError` can no longer satisfy this test.

Both identity tests forbid reaching the numerical backend. Production snapshot
bounds, signature checks, file-opening flags, hashing and retained-array loading
were not changed. The deterministic fixture isolates the final pathname identity
comparison; the real replacement additionally exercises actual filesystem
behavior where that operation is supported.

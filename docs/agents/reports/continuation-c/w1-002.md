# Worker 002 — VST3 state/controller audit

## Confirmed finding

**P2: generic gain text entry accepts NaN as successful conversion.** `plugins/vst3/controller.cpp:18–19` installs the SDK `RangeParameter`; `controller.hpp` does not override `getParamValueByString`. The pinned SDK's `vstparameters.cpp:174–196` accepts `scanFloat("nan")`, bypasses both ordered range comparisons, and returns NaN. A compiled probe of the actual `RhodesController` returned `result=0 value=nan finite=0` (`0` is success). It also accepts `16junk` as 16x. `setParamNormalized` correctly rejects NaN, but the successful parsing response is inconsistent; a host forwarding it into an automation queue triggers whole-block rejection at `processor.cpp:193–198`.

Recommended fix: validate parsed output before returning success, reject nonfinite values, preserve the caller's output on failure, and explicitly decide whether trailing text is permitted. Regression: exercise gain text conversion through the public controller interface for `nan`, signed NaN, infinities, trailing junk, whitespace, endpoints and ordinary decimals; verify successful results are finite normalized values and failures cannot change saved configuration. Apply to all three variants.

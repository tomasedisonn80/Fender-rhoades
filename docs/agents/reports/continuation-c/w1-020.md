# W1-020 — Final design gate

**Scope approved with the integrator's explicit decisions below.** The earlier
W1-011/W1-017 disagreement over decimal bounds is resolved; acceptance tests must
follow this contract rather than require arbitrary-precision decimal bounds.

1. **Numeric domain:** finite parsed binary64 within `[0,32]` for gain and `[0,1]`
   for commands. Thus `32.000000000000000001` rounding to 32 is accepted.
   Leading `+` and scientific decimal notation are allowed. Optional lowercase
   `x` is exclusive to gain. Conversion must consume the complete bounded ASCII
   input; invalid conversion preserves caller output and configuration.
2. **Command text:** strict normalized numeric input without a suffix; format
   shortest round-trip numeric text. No `Off`/`On` command labels. Parsing and
   formatting do not release notes; every delivered processor command point does,
   including zero and repeated values. Commands remain transient and excluded
   from the sixteen-byte saved configuration.
3. **Zero-frame transaction:** validate syntax before acquiring the mailbox
   token, then preflight ownership against its selected recall. Apply selected
   recall first, final sustain next, then preflighted releases. Ordinary releases
   preserve mechanics, cursor and filter history; selected recall intentionally
   resets them. An unexpected release failure latches a fault and publishes the
   accepted state without rollback. Newer pending recalls must remain preserved.

**Remaining risks:** freeze the exact scan bound, whitespace/suffix spacing and
conversion underflow policy in the specification/tests. Check negative subnormals
under DAZ, output preservation, FP-control preservation versus sticky flags,
concurrent recall and injected release failure. Adapt W1-017's exact-decimal
expectations to the resolved binary64 domain. CC123 capacity/chronology and
validated pressure no-op requirements are otherwise coherent. Lifecycle hardening
is separate scope. Native DAW delivery and physical fidelity remain unvalidated.

implementation. `project.py validate`, `sync --check`, and `next --json` passed.

## Contract and implementation

The public `parse_candidate(raw: bytes) -> ParsedCandidate` interface follows
[`CONTACT_ANALYTIC_PEAK_SLICE_20261123.md`](../../specs/CONTACT_ANALYTIC_PEAK_SLICE_20261123.md)
and [the A53 native schema](../transient-campaign/w3_a53.md). The frozen result
contains the fixture identity, all eight settings in `RUN_SETTING_FIELDS` order,
normalized native run, optional peaks, explicit availability and SHA-256 of the
original bytes. Nested dictionaries disable ordinary mutation and arrays are
tuples; the records remain directly serializable by `json.dumps`.

The parser uses the standard library and imports the existing independent
fixture definitions without invoking their lazy optional numerical backend.
It never executes a candidate, imports native solver output as an oracle, or
infers physical parameters from observations. It exports the file/collection
size and count limits for the CLI. Actual collection ingestion belongs to the
separate CLI module.

The reader enforces the exact envelope, run, 26-field samples, diagnostics,
sampled maxima, peak metadata and unit fields; positive settings; finite numeric
conversion; integer magnitude and collection bounds; duplicate-key rejection;
depth 64; chronological observations/events; event and peak brackets; disabled
contact semantics; and independent initial-state checks. Expected initial zeros
must match exactly, while nonzero components admit at most 64 ULPs. String
contents do not count as JSON structure in the depth preflight. Format errors
are bounded to 384 characters.

As required by the [Wave 1 schema audit](20261124-w1-04-schema.md), a successful
supported run must span its full independent duration, whereas a failed producer
may retain a partial trajectory and zero accepted-step diagnostics. Accepted-step
bounds follow `accepted_steps`; analytic evaluation counts describe trial/replay
work and do not establish accepted intervals. Literal success and bounded
nonnegative failure codes must agree. Unsupported fixture names are classified
only after structural validation, permitting their native relaunch snapshots,
action events and action peak origins. A missing optional peak diagnostic is
distinct from a supplied null, partial or malformed diagnostic.

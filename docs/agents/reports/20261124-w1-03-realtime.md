## Hot-path observations

`BasicQuadratureEngine::process()` emits completed-cell FIR output, invokes
`ResearchEngine::observe()` six times, performs one legacy
`ResearchEngine::process()` endpoint observation/advance, then pushes one cell.
Each observation traverses all 73 keys and their three modes. Each FIR output
performs 6 × 96 = 576 coefficient/history products in a fixed accumulation order.
These are source operation counts, not measured relative costs. Silence and
one-key cases retain full traversal; active-key count is not voice allocation.

The existing endpoint process computes an electrical value that quadrature
otherwise discards, while also validating it and advancing mechanical state.
An eventual advance-only API could remove this repeated observation, but changing
it without equivalent fault detection would change the existing arithmetic-fault
contract. Treat this as a separate, evidence-driven optimization after baseline
capture, with independent waveform/state and fault-behavior regression checks.
The FIR's wrapped index branch could likewise be split into two contiguous
age ranges while preserving accumulation order; no speedup is asserted here.

`RhodesProcessor::process()` copies `NoteTracker` for atomic preflight on every
callback, even with no notes. This is bounded but may matter for one-frame calls.
`StateMailbox` uses always-lock-free 64-bit atomics and single compare-exchange
attempts, with no retry loops. These source facts do not establish worst-case
execution time, allocator coverage in all dependencies, or DAW deadline safety.

| NoteTracker | 6,736 |

Reproduce by including `rhodes/research_engine.hpp`, `quadrature_engine.hpp`,
`audio_engine.hpp`, `event_processor.hpp` and `note_tracker.hpp` in a C++20
program and printing `sizeof(rhodes::TYPE)` with `g++ -std=c++20 -O2 -Iinclude`.
These values are ABI-specific object sizes, not peak stack or resident memory.
They exclude VST3 processor scratch storage, SDK allocations and executable
code. Quadrature preparation creates fixed local candidate objects outside the
audio callback; future changes must preserve that boundary. The benchmark
already heap-allocates its large host fixture before timing.

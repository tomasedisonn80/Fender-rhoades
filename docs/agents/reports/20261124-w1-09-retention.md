## Concrete implementation recommendation

Create the requested output directory with an exclusive `mkdir` operation
(`exist_ok=False`). Refuse an existing directory, regular file or final symlink,
including a dangling symlink. Do not add the sweep runner's `--force` behavior:
the new contract requires a new directory and preserves every earlier attempt.
Use deterministic numbered raw filenames, never input basenames, so repeated
names from separate directories cannot collide or introduce output traversal.

Write an initial manifest containing the complete ordered input plan, flags,
limits, timestamps and a `running` status before numerical work. For each input,
retain bounded raw bytes before parsing, record their actual length and SHA-256,
then append its parse/comparison result. Preserve malformed JSON, unsupported
fixtures and producer failures as individual records. A failure in one case
must not discard successful earlier cases or silently omit later declared cases.
Record unread/unprocessed inputs explicitly if an operational failure stops work.

Enforce the declared 64-file, 32-MiB/file and 128-MiB/collection limits while
reading, rather than relying solely on preliminary `stat` sizes. Open only
regular input files; reject special files and apply a declared final-symlink
policy. Descriptor metadata plus bounded reads avoids a growing file bypassing
the memory cap; prechecking a pathname alone does not bind the opened object.
An oversized input should retain a rejection record; any capped prefix retained
must be labelled partial and must not be given a whole-file hash claim.

Treat `--producer-binary` only as a regular-file hash input. Never execute it or
infer that it produced the supplied candidate bytes. Keep its declared identity
separate from hashes of the parser, oracle, comparator, independent fixture
definitions and frozen contract. Hash definition JSON using sorted keys,
compact separators and `allow_nan=False`; record Python and optional numerical
backend versions without requiring SciPy for value-only operation.

Retained raw files should use exclusive creation. Manifest updates may use a
temporary file and atomic replacement of this attempt's own manifest, following
the sweep's existing `write_json` pattern. Serialize with `allow_nan=False`, and
treat serialization or write failures as operational exit 3. Best-effort final
failure recording must preserve earlier raw files and never mask the original
exception. Directory creation failure naturally cannot produce an in-directory
report and should explain that on stderr.

## Existing gaps worth avoiding

The sweep's candidate reader checks size before ordinary opening; that is not a
bounded ingestion implementation. Its outer exception handler reports an error
without guaranteeing a terminal manifest status. Existing tests usefully cover
refusing prior output, preserving partial child streams, hashes and managed
symlinks, but do not establish new-diagnostic collection caps, read failures,
serialization failures or no-execution binary handling. Add focused tests for
these new behaviors, retaining the old sweep's separate semantics.

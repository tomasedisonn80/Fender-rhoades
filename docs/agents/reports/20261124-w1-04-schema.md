## Findings

The proposed strict field sets match the native successful four-fixture output:
`emit_sample` emits 26 keys; the main envelope emits eight solver/output settings,
14 mandatory diagnostic fields and optional `located_peak_candidates`.
`emit_located_peaks` and `emit_peak` match the frozen coverage/evaluation strings,
unit-specific value keys and four peak records. All four supported fixtures have
no relaunches; only `preload_equilibrium` enables the damper. No successful-output
field-set mismatch was found.

Two parser design distinctions need explicit implementation:

1. **Producer failure must precede complete-duration acceptance.** `main` breaks
   after a failed `Reference::advance` and still emits valid native JSON with
   `success=false`, nonzero `failure_code` and a partial trajectory before exiting
   2. On an immediate failure, `Diagnostics` legitimately has zero accepted-step
   counts and both accepted-step bounds zero. The slice simultaneously requires
   complete samples and retaining producer failure. Treat complete-duration and
   positive accepted-step checks as successful-run requirements; otherwise retain
   the native failed payload as a definite producer failure rather than dropping
   its evidence as malformed. Setup/initialization exceptions instead exit 1 with
   stderr and no JSON, so ingestion must preserve those separately.
2. **Unsupported is distinct from malformed.** The native emitter supports all
   26 fixtures, including `relaunch` events, nonempty snapshots and action peak
   origins outside the four-fixture slice. Do not apply the supported fixtures'
   empty-action restrictions to a structurally valid unsupported run before
   returning `availability=unsupported_fixture`. Conversely, unsupported names
   must not bypass the generic byte/depth/finite-number and envelope checks.

Initial-state comparisons should bind the independent fixture definition and
explicitly compare all modal positions/velocities and hammer position/velocity.
They must never infer masses, contact constants or enable flags from candidate
observations. The emitter omits physical configuration, so names plus initial
state are consistency checks, not producer authentication. The 64-ULP allowance
for nonzero initial components is appropriate for independently assembled preload
rounding; expected zeros should remain exact.

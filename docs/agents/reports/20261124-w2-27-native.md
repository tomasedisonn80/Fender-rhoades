its audit file contains two interpreter-start records, one for the CLI and one
for its timing worker, and the permitted Python subprocess request. The other
two runs each contain one interpreter-start record. No child request was rejected
and no native-producer launch was observed in these Python diagnostic runs.
This is **Python-level observation and guard**, not OS process-tree tracing.

Native generation is a separate observed collection phase. Every diagnostic
manifest states `declared_producer.executed=false` and
`candidate_production_attested=false`. A stable file hash and this capture do
not attest arbitrary candidate physical configuration or constitute a
cryptographic execution attestation.

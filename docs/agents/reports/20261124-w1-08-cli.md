# Wave 1, assignment 08 — peak diagnostic CLI failure semantics

Read-only audit against `807e078` and the frozen
[analytic peak contract](../../specs/CONTACT_ANALYTIC_PEAK_SLICE_20261123.md).
The new CLI was absent when inspected. Only this report was written.

## Recommended result aggregation

Use explicit precedence, **3 > 1 > 2 > 0**, not numeric `max(exit_codes)`:

| Exit | Meaning and examples |
| --- | --- |
| 0 | Every requested comparison completed successfully. |
| 1 | Definite candidate or diagnostic failure: malformed bytes/schema, explicit producer failure, wrong peak value/time, inconsistent observations. |
| 2 | No definite failure, but required evidence is absent, unsupported or inconclusive. |
| 3 | Execution/retention failure: unreadable input, output creation/write failure, inaccessible requested binary hash. |

The operational-first choice should be documented explicitly; the contract
already requires definite failures to outrank incomplete comparisons. Retain
per-case findings regardless of the aggregate exit so an operational problem
cannot erase an established candidate failure. Check every provided case instead
of stopping after the first bad input. Do not permit an empty candidate list to
pass through vacuous `all([])`; reject missing input before creating outputs
(normal argparse usage exit 2 is consistent with missing evidence).

## Preserve distinctions

`validate_contact_reference.py::main` correctly prioritizes `fail` over
`incomplete`, but collapses input, reference and filesystem exceptions into one
failure. Its final output write is outside that catch. Neither behavior should
be copied into the new four-code CLI. `run_contact_sweep.py::execute` preserves
explicit child failure and raw streams even when JSON is otherwise valid; the
new diagnostic reads producer status without executing any supplied binary.

Retain `success=false` or nonzero failure code as exit 1 before allowing missing
peaks/partial trajectories to reduce it to exit 2. Omitted peak diagnostics mean
`not_available`; explicitly null/malformed diagnostics are exit 1. A structurally
valid unsupported fixture is exit 2, while malformed unsupported data must still
be rejected. An empty file is malformed input, distinct from no input argument.

Import optional SciPy timing lazily. Without it, schema/help and value references
remain usable; requested damped timing becomes `not_available` and exit 2 unless
another case fails. Unrequested damped timing must not block value-only exit 0.
Preload's unresolved positive timing remains visible separately from the
requested available analytic comparisons. Every report retains
`phy002_acceptance: incomplete`, even when this diagnostic exits 0.

Create output exclusively without a force option; preserve readable raw bytes
and errors before comparison, and catch final serialization/write exceptions.
Test missing files, directory inputs, existing/symlink destinations, injected
permission errors, and a failure after one successful retained case. Bound reads
while consuming bytes; a prior file-size check alone does not enforce the limit.

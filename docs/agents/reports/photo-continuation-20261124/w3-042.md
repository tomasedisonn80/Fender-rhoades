## Result

**No concrete correctness blocker found in the reviewed lifecycle paths under
the integrator's clarified refusal contract.** This is source reasoning, not a
native execution result.

- **Ordinary removal stays synchronous.** `removed()` retains the editor;
  without active callbacks/frame dispatch it immediately delegates to SDK
  removal, whose virtual `close()` reaches qualified `VST3Editor::close()`
  through `close_now()`. No timer is created for that path.
- **Callback coverage includes idle and focus.** Complete PhotoView event,
  idle, focus-loss, activation, removal and cancellation bodies carry depth
  guards. Editor attachment, focus, sizing and scaling do likewise. `fire()`
  also checks removal depth and frame event processing; nested pumping inside
  these bodies leaves the periodic timer pending for another turn.
- **Rejected scheduling preserves the attachment.** Failure returns before
  SDK `removed()` clears `systemWindow`, stops/releases the timer, drops pending
  ownership, and cancels the current interaction. Later fresh input and removal
  retry remain available. Initially flagged against W2-031's permanent-disable
  recommendation; the integrator explicitly confirmed this usable-after-refusal
  behavior is intended, so it is not an issue against the current contract.
- **Accepted pending removal is isolated.** The view is disabled, `close()`
  suppresses teardown, and public `attached()` plus `open()` refuse replacement.
  Attachment also clears the SDK's subsequently published parent when a resize
  callback requested removal during attachment. Removal depth blocks reentry
  during scheduling/cancellation.
- **Ownership is consistent.** Pending self-ownership survives host release;
  completion locally retains both editor and timer, unregisters before closing,
  and destroys the timer local before the editor local. `closing_` spans delegate
  callbacks. Destruction sets `destroying_` before synchronous cleanup and never
  schedules or retains an editor at zero references.
- **Frame identity/refcounts remain stable.** Pending/closing guards prevent a
  replacement attachment. No additional CFrame reference crosses SDK close,
  preserving its `refCount == 1` native-close branch.

## SDK checks and remaining boundary

Actual factory timers are used, avoiding `CVSTGUITimer::start()`'s discarded
registration result. Selected X11 scheduling propagates host registration
failure; Wayland is disabled. The hash-checked Win32 overlay returns the actual
`SetTimer` result and is wired into `cmake/Vst3.cmake`. Inspected X11, Win32 and
macOS dispatchers do not access callback-owned state after `fire()` returns.

Root's native fixtures must still establish callback ordering, nested pumping,
and behavior when the host destroys its parent before deferred teardown.

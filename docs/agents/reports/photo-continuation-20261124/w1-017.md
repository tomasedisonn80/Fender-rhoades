## Evidence and reasoning

- `plugins/vst3/photo_editor.cpp`: `PhotoView::draw` creates one source-image
  transform for the photograph, key mask, control outline, and feedback. Its
  `fit.valid()` guard precedes the new reciprocal-scale calculation.
  `source_position` uses the inverse of the same `image_fit`, after subtracting
  the view origin. The new mask does not change either pointer conversion or
  `photo::hit_key`.
- Feedback sizing remains source-space drawing only. The multiplier
  `clamp(0.75 / image_fit().scale, 1.0, 2.0)` changes no `ViewRect`,
  `zoomFactor`, `contentScaleFactor`, or mouseable bounds. A valid positive fit
  cannot produce a NaN reciprocal; even reciprocal overflow is bounded by the
  clamp. Its box width is 464–928 source pixels. The horizontal clamp therefore
  always has an ordered interval: its upper endpoint is at least 596, above its
  lower endpoint of 12. The box remains inside the 1536-pixel source width.
  For the immutable valid anchors, vertical placement also stays inside the
  source: an unclamped box ends at `anchor.top - 12 * scale`, while a top-clamped
  box ends no lower than source y=144. Invalid anchor bounds return before drawing.
- `PhotoEditor::onSize` computes logical zoom from physical width divided by
  `1024 * contentScaleFactor`; the native frame receives the combined absolute
  scale. The new overlay code does not enter this negotiation. `constrain_size`
  uses widened coordinate subtraction and endpoint arithmetic, limits physical
  width in four-pixel units, and returns exact integer 4:3 dimensions. Failed
  endpoint checks occur before rewriting the caller's rectangle. Content-scale
  negotiation still retains old public bounds until the host notification and
  restores prior scale, zoom, and rectangle on refusal.
- The photograph remains the complete 1536×1152 source and the UI description
  remains a 1024×768 canvas. Neither change introduces cropping or an independent
  image/hit-region scale. The key-mask renderer puts the original outline and
  bounded intersection cutouts in one closed even-odd path and suppresses white
  outline strokes. All path vertices retain original-image coordinates.

## Existing coverage and its limits

`tests/cpp/vst3_photo_editor_test.cpp` contains independent boundary/offset size
fixtures, odd-width rounding checks, extreme coordinate checks, invalid endpoint
and resize rejection, six nondefault/default DPI fixtures, malformed scale
rejection, user-zoom preservation, host refusal/missing/malformed notification
rollback, and sibling-view independence. It explicitly exercises unattached
views, so these assertions do not establish attached native rendering.

`tests/cpp/photo_geometry_test.cpp` covers full-photo fitting and key round trips
at square, wide, tall, tiny, and large viewports, plus nonfinite, negative, zero,
and underflow bounds. `tests/cpp/photo_key_highlight_test.cpp` covers the mask's
original outlines, black exclusions, dense interior ownership, exposed edges,
and invalid indices. These are source-space geometry checks. They do not assert
native text size, DPI rasterization, or antialiasing at shared edges.

The feedback multiplier uses PhotoView's local fit; frame zoom remains a separate
VSTGUI transform. Consequently this review makes no claim that the new formula
alone guarantees a fixed physical or logical text size across host resizing.
The integrator's existing native qualification should inspect minimum/maximum
editor sizes and a nonunit DPI with feedback visible. No redesign is proposed.

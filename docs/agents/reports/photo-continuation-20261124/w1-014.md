## Implementation and integration API

`photo::key_highlight(int key)` returns a `const KeyHighlight&`. The immutable
table is constructed at compile time, uses fixed arrays, and has no runtime
allocation or dependence on VSTGUI. Invalid indices return an empty shape.

| Member | Meaning |
|---|---|
| `outline` | Exact copy of the original four- or six-vertex `photo::Polygon` |
| `cutouts` | Array of two `HighlightCutout` values, each with eight point slots |
| `cutout_count` | Number of active cutout polygons |
| `stroke_outline` | True only for black keys |

For a white key, the helper intersects its convex upper-surface quadrilateral
(original vertices 0, 1, 2, 5) with each adjacent black-key quadrilateral.
Sutherland-Hodgman clipping uses bounded arrays and removes duplicate closing
vertices. Degenerate intersections are rejected. Convex quadrilateral
intersections require at most eight vertices. The white front face is below
the black keys and remains intact.

The renderer must append the outline and all active cutouts as **closed subpaths
of one even-odd filled path**. Full black polygons would incorrectly paint their
portions outside the white outline under an even-odd fill; these cutouts are
restricted to the actual intersection. Only stroke when `stroke_outline` is
true. An original white outline crosses black interiors even after its fill is
corrected, so white outlines are deliberately suppressed.

The hit-test geometry and black-first precedence remain unchanged. The test
reproduces the original finding that all 30 black centers lie inside a white
base polygon, then checks that the new composed white paths exclude them.

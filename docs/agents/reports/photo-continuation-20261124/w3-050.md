reset with `cursors.fill(XCB_CURSOR_NONE)`. The connection is set to null
immediately after `xcb_disconnect()` and before the existing external event
handler unregister call. A surviving frame keeps `useCount` nonzero and does
not enter this final teardown.

## Composition, pin checks and generated files

The lifetime helper must run immediately after
`rhodes_patch_vstgui_x11_keyboard()`. It verifies both original SDK sources and
the exact generated keyboard copy before changing anything. It then substitutes
exactly one keyboard-adapted platform entry and exactly one original frame
entry in `vstgui`'s `SOURCES` property. An unadapted platform entry left in that
list is rejected, as are missing or duplicate expected entries.

Both original SDK sources are registered in `CMAKE_CONFIGURE_DEPENDS`.
Original CRLF inputs are normalized to LF before hashing. The generated
keyboard copy must match its exact known LF bytes. Four replacement anchors
are independently checked to occur exactly once: the device member, final
exit function, setter insertion and frame surface registration. Final hashes
bind both complete outputs, including the existing keyboard mapping.

The outputs are confined to the calling build directory:

```text
rhodes-vstgui-overlay/x11platform-lifetime.cpp
rhodes-vstgui-overlay/x11frame-lifetime.cpp
```

Each generated source receives the original SDK's
`vstgui/lib/platform/linux` include directory. Existing output files are
rewritten only when their bytes differ from the frozen result. Source ordering
and unrelated source entries are preserved.

# Worker 016 — audition cancellation ordering

Scope: bounded read-only review of `plugins/vst3/controller.cpp`,
`plugins/vst3/photo_editor.cpp`, and the allocation/dispatch/sibling cases in
`tests/cpp/photo_view_interaction_test.cpp`. No production changes or execution
results are claimed. Only this report was written.

## Finding

`RhodesController::auditionNote` assigns `state->key` before
`sendAuditionNote`, whose allocation, message/attribute calls, and `sendMessage`
can call host code. `PhotoView::move_audition` assigns `held_key_` only after
that call returns. Consequently a nested `cancel_interaction` sees no local
held key, releases nothing, and the outer call subsequently publishes the
cancelled note as held. Moving `held_key_ = key` before the controller call is
unsafe: allocation-time cancellation would send Up before the pending Down.
An early controller-ownership query inside `release_key` has the same problem.

## Smallest proposed production change

Keep controller ownership, V1 transport, and the processor unchanged. Add/use a
PhotoView cancellation generation and defer cancellation cleanup of an in-flight
Down until the controller call has returned:

1. At the start of cancellation, advance the generation before any host callback
   and clear drag flags. Keep the existing local-key clear-before-release rule.
2. In `move_audition`, capture the generation before releasing the previous key.
   After `release_key` returns, stop if cancellation changed it. This prevents
   cancellation during the previous Up from starting the next glissando Down.
3. Leave the new `held_key_` unset while calling
   `auditionNote(owner, key, true, 0.75F)`. Nested focus cancellation now records
   cancellation without releasing the controller's provisional ownership.
4. After that call returns, check the generation before publishing held state or
   restoring feedback. If cancelled, query `heldAuditionKey(owner)` now. If it
   still equals this attempted key, call
   `auditionNote(owner, key, false, 0.0F)` exactly once, then return. Otherwise
   return without cleanup: another path already removed the ownership.
5. Publish the local held key/feedback only for the still-current successful
   interaction, with controller ownership still matching its key. Do not revive
   drag flags after a callback.

The deferred cleanup uses the controller's existing last-owner rule. A sibling
on another key retains its note; a sibling on the same key suppresses the Up
until its own release. Do not call `releaseAuditionNotes` for local focus loss.
Failed sends already invoke the controller's emergency mechanism and clear all
owner keys; the post-return ownership check prevents duplicate emergency cleanup.

## Required observable order

| Case | Expected ordinary V1 note sequence |
| --- | --- |
| Normal glissando | Down(0), Up(0), Down(1), Up(1) |
| Cancellation from accepted Down dispatch | Down(0), Up(0) |
| Cancellation during Down allocation | Down(0), Up(0) with the proposed minimal deferral; never Up(0), Down(0) |
| Sibling holds key 1, primary cancels key 0 | Down(1), Down(0), Up(0); Up(1) only on sibling cleanup |
| Cancellation during the previous key's Up | Previous Down, previous Up; no next Down |

transport-failure expectations in `tests/cpp/vst3_audition_ownership_test.cpp`.

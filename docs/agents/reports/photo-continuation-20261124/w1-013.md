## Fixture boundary

PhotoView is private to `plugins/vst3/photo_editor.cpp`. The test includes that
production translation unit directly so it can instantiate the real class and
call its actual event methods without exporting a test API or copying event
logic. Its executable must **not** compile `photo_editor.cpp` a second time.
The real `RhodesController` and `PhotoNativeFocus` implementation still link
normally, alongside the SDK and VSTGUI libraries.

Each fixture initializes a real controller with a fixture-owned
`IHostApplication`, installs a recording `IComponentHandler`, and connects a
recording `IConnectionPoint`. Host edit callbacks record the exact parameter,
canonical value, order, and outstanding accepted begin count. The receiver
decodes the real SDK `IMessage` traffic and records literal V1 note messages and
their final accepted held-key state. No processor mock determines the expected
event behavior. Fixed photographed coordinates and literal expected wire/edit
traces serve as the input/output oracles.

Persistent normalized values are compared with an independent C++
`double(float(expected))` conversion, matching the public binary32 storage
domain without calling production quantization helpers. The tolerance remains
`1e-12`, well below a binary32 ULP in the tested range. Fine wheel cases each
start from an exact 0.5, avoiding a false failure caused by accumulated
quantization when comparing two rounded increments to a single decimal sum.

The view uses a null bitmap because this fixture never draws. It has an
independently retained VSTGUI shared reference, a source-sized logical rectangle,
and no native `CFrame`. The main function initializes VSTGUI's actual platform
factory for event timestamps. Linux's factory accepts a null module handle;
its resource-path lookup is guarded by a nonnull handle. No native window,
bitmap decode, OS event loop, or display connection is requested.

Reentrant focus loss invokes `PhotoView::cancel_interaction()`, exactly the call
forwarded by `PhotoEditor::onFocus(false)`. This is logical cancellation while
the view remains alive. It does not simulate `removed()` or destruction of a
live VSTGUI dispatch tree; W1-010's whole-editor-close lifetime risk remains a
separate native dispatch test requirement.

## Cases and behavioral assertions

| Case | Required observable behavior |
| --- | --- |
| `rapid_switches` | Sustain and Vibrato toggle on every press of native count sequences 1/2 and 1/2/3, from both Off and On; every press has exactly one begin/perform/end. |
| `continuous_reset` | Volume, Bass, Treble, Intensity, and Speed preserve a seeded value on an unmoved first press, then reset to their declared controller default for counts 2 and 3. |
| `host_shortcuts` | Control, Alt, and Super combinations, also combined with Shift, leave the event unconsumed and perform no edit or focus traversal; Super-Escape does not cancel an existing drag. |
| `fine_steps` | Ordinary/fine keyboard, wheel, and drag inputs produce the independently declared numeric increments and exact canonical host values. |
| `rejected_edits` | A rejected begin produces no perform/end or later active drag; an ordinary rejected perform restores the previous value and pairs its accepted begin. |
| `end_cancel_idempotent` | An end callback that reenters cancellation sends one end only; subsequent cancellation/up/move remains inert. |
| `begin_cancel_drag` | Cancellation during an accepted begin immediately pairs that begin, leaves the value unchanged, and prevents later left-held movement from editing. |
| `begin_cancel_wheel` | Cancellation during a one-shot begin prevents its following perform/value change while preserving exact begin/end pairing. |
| `begin_cancel_switch` | The same pending-begin cancellation prevents a rapid switch press from toggling. |
| `end_cancel_new_press` | Cancellation during the old gesture's end prevents the outer new-press continuation from opening another gesture. |
| `perform_cancel_drag` | Cancellation during an accepted perform closes exactly once, retains the last accepted value, and prevents later drag callbacks. |
| `perform_cancel_host_update` | A host callback that cancels, writes 0.75, then rejects the pending 0.52 UI edit retains its newer 0.75 update. |
| `audition_drag` | Ordinary key-down/glissando/up produces the literal down-0/up-0/down-1/up-1 sequence, with no duplicate cleanup or parameter callbacks. |
| `audition_cancel_dispatch` | Cancellation during accepted note delivery produces an ordered owned note-up before the outer event returns; later move/up/cancel emits nothing. |
| `audition_cancel_allocation` | Cancellation during SDK message allocation leaves the eventual receiver and controller ownership quiet; a release preceding an in-flight note-on is insufficient. |
| `audition_cancel_sibling` | Cancelling one in-flight audition releases that view's key while preserving another view's held key; cleanup stays owner-specific. |

The allocation fixture reserves a fresh message slot **before** calling its
reentrant hook. A nested release therefore cannot overwrite an in-flight down's
attributes, and the test does not accidentally conceal an ordering defect by
reusing a single fake message. The receiver records and accepts the current
message before calling its delivery hook, preserving nested wire order.

Reentrant assertions run immediately after the outer event returns, before
fixture destruction. Destructor cleanup cannot turn a leaked accepted edit or
stuck audition into a passing case. The runner catches each case's assertion
failure, prints its name, continues through the remaining requested cases, and
returns failure if any case failed. Assertions remain active with `NDEBUG`.

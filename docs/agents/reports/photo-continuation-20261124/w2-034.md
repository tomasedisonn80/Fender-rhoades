# W2-034 — audition transport review

## Scope and verdict

Independent static review of `plugins/vst3/controller.cpp/.hpp`, `tests/cpp/vst3_audition_reentrancy_test.cpp`, and retained `docs/validation/photo-continuation-20261124/transport-{before,after}*` evidence. **The bounded emergency-cancellation target is met; no concrete remaining defect found within the reviewed allocation, attribute, notification, and sibling-cleanup cases.** This does not establish arbitrary host-callback, audio, or whole-editor correctness.

## Findings

- `sendAuditionNote` captures the release generation before allocation, checks it immediately afterward and after message/attribute construction, and suppresses stale unsent notes. The caller avoids another emergency when a nested release already changed that generation.
- A generation change during successful down notification produces one compensating release after notification returns. This covers the dangerous ordering `ReleaseAll, Down, ReleaseAll`. Failed compensation retains pending state and cleared ownership. Recovery attempts reject the current note even when their release succeeds; a subsequent call may start a fresh note.
- The release-in-progress guard prevents nested release/retry/down requests from allocating or notifying recursively. Nested emergency requests clear ownership and coalesce into the current release. Clearing pending after accepted release is sound here because pending blocks all new downs throughout that release.
- Ownership is assigned before outgoing down construction. Closing a same-key sibling therefore emits no premature up; distinct-key sibling cleanup releases only its key. The final owner sends the shared key’s up.

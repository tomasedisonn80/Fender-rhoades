## Findings sent to root

1. **Close visibility can race across XCB connections** (fixture lines 321,
   396, 409, 416). SDK `X11::RunLoop::Impl::exit()` disconnects its own
   connection; immediate geometry queries use the host's separate connection.
   Server-side child disappearance is not an immediate cross-connection fence.
   Root reported a runtime failure here. Require event registrations and close
   timer retirement synchronously, then bound disappearance checks using only
   host XCB queries/polling. Do not use `Host::until`, which dispatches plug-in
   work and could hide delayed structural cleanup.

2. **Pending-input assertions omit late performs** (402–410). They check only
   begin/end counts after wheel/key injection. Preserve and assert the perform
   count too; an unbracketed late `performEdit` otherwise passes.

3. **Released-view completion lacks a destruction witness** (370, 407–410;
   cleanup 214–226). A leaked `deferred_close_owner_` can leave the child closed
   and timer retired while the editor survives. SDK `CPluginView` retains
   `IPlugFrame` through `IPtr`; expose the host reference count and require its
   initial value after orderly view/controller/factory/module cleanup, outside
   the destructor. This checks ownership without production instrumentation.

4. **Parent destruction makes child disappearance insufficient** (369, 409).
   XDestroyWindow already removes descendants. Require native event/timer
   registrations to retire, or reattach the same view to a fresh parent, before
   fixture cleanup can conceal an uncleared frame.

Root also identified the refusal case's missing fresh-input assertion; a new
accepted wheel gesture before ordinary removal is the appropriate addition.

## Supported scope

Public SDK hosting and XCB SendEvent reach the loaded native editor. Strong
handler snapshots plus generation checks safely support unregister/reentry;
SDK adapters retain raw callback pointers, so they do not themselves keep the
editor alive. However, `Host::pump` calls every event handler without checking
descriptor readability, unlike the SDK run-loop contract. This stresses native
callbacks but cannot establish poll-driven host behavior or exclude buffered-XCB
readiness starvation. No platform pass follows from this source inspection.

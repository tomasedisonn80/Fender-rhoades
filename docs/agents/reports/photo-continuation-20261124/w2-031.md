# W2-031 — Application lifecycle deferral recommendation

Date: 2026-11-24. Bounded read-only review; only this report added. Read the
operating contract, project context, W1-019/W2-030, current application code,
and pinned SDK sources. No program execution, reproduction, build, test, SDK

## Smallest recommended change

Preserve synchronous qualified `VST3Editor::close()` when no live application
callback or frame dispatch exists. Defer host-requested removal otherwise.

Override public `removed()` and retain the editor throughout that wrapper.
Before delegating to SDK `removed()`, establish one pending generation,
disable interaction permanently for this attachment, and cancel gestures and
owned audition notes. Preflight registration of one actual UI timer. The SDK
wrapper can then invoke a pending-aware `close()` without structural teardown.
If registration fails, return `kResultFalse` **before** SDK removal clears
`systemWindow`; leave the native attachment intact and interaction canceled,
retire unscheduled ownership, and permit a later safe removal retry. Never
fall back to synchronous teardown on the active callback stack.

Use an application-owned `IPlatformTimerCallback` and timer handle, retaining
`IPtr<PhotoEditor>` for the pending generation. Crucially, `CVSTGUITimer::start()`
discards the platform start result: its boolean proves allocation only.
Linux/macOS platform timers expose useful registration results. **The pinned
Windows `WinTimer::start()` unconditionally returns false, even after successful
`SetTimer`.** Therefore a portable checked helper needs a narrow Windows
adapter that observes the actual `SetTimer` result, with the SDK platform
timer elsewhere. Treating all platform false results as rejection is safe but
would reject every Windows deferred removal; ignoring them is incorrect.

Track callback-active depth across complete PhotoView callback bodies that
can reach the host, including `onIdle`, focus/activation, cancellation, edit,
and audition paths; cover editor `onFocus` too. `inEventProcessing()` alone
misses idle/focus. Timer firing must wait while either guard remains active,
including nested message pumping; leave the periodic timer registered for
another actual UI turn. A `doAfterEventProcessing` closure is insufficient
because native mouse-handler work follows frame dispatch.

On a safe timer callback, retain local editor/timer ownership, validate the
generation, enter `closing`, unregister the timer, and perform base close once.
Keep `closing` through delegate callbacks, then retire pending ownership. Do
not retain `CFrame` across base close: that changes its reference-count branch.
Reject public `attached()` and `open()` during pending/closing; SDK attachment
otherwise reports success even when `open()` fails.

Destructor cleanup must be synchronous and non-retaining, never scheduling or
constructing `IPtr(this)` at zero references. The pending owner prevents
destruction until completion. Deferred native teardown after a host immediately
destroys its parent remains a required platform lifecycle check, not a proven
property of this source review.

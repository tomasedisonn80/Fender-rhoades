## Initial failure and correction

The first environment handoff passed module-version queries, SDK configuration,
and Xvfb startup, but those checks did not validate expanded include directories.
The integrator's first project build progressed to 102/303 steps and then failed
in VSTGUI's `cairofont.cpp` because `glibconfig.h` could not be found. The observed
root log was `/home/agent/rhoades-9a04c9726e31/build-gui.log`.

The faulty relocation expression interpreted the `/lib` suffix in
`${prefix}/lib/x86_64-linux-gnu` as a new absolute path. This generated:

```text
/home/agent/rhoades-9a04c9726e31/sysroot/usr/home/agent/rhoades-9a04c9726e31/sysroot/lib/x86_64-linux-gnu/glib-2.0/include
```

All relocated metadata was regenerated from the preserved package originals.
The corrected rule changes only literal absolute `/usr`, `/lib`, or `/etc`
values that follow a line beginning, equals sign, or whitespace, optionally after
`-I`/`-L`. Variable-relative suffixes such as `${prefix}/lib` are preserved. The
correct GLib configuration-header directory is:

```text
/home/agent/rhoades-9a04c9726e31/sysroot/usr/lib/x86_64-linux-gnu/glib-2.0/include
```

The same correction is included in the recovery script below. CMake caches
pkg-config results, so an existing build configured before the correction must

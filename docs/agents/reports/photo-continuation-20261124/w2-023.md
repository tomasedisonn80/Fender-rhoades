## Finding and change

The synchronous-callback issue retained in `w1-005.md` needs a mutation identity,
because a host can write the same value during a rejected editor edit. Value
comparison alone cannot distinguish that newer host write from the editor's
provisional value.

Added the nonvirtual GUI-thread API
`std::uint64_t RhodesController::parameterRevision(ParamID) const noexcept`.
Each controller instance owns eight initially zero revision counters, indexed
by the existing persistent IDs `0..7`. Every accepted persistent
`setParamNormalized` call increments exactly its own counter, including calls
whose input equals or canonicalizes to the current value. The increment happens
before the SDK setter can synchronously notify observers. The API returns zero
for all other IDs, including the sixteen transient CC123 commands.

Malformed inputs, unknown IDs, calls outside initialization, and a missing SDK
parameter object are rejected before any increment. Existing `setComponentState`
and `setState` already route every persistent write through the setter and were
left unchanged. Counters are ordinary GUI-thread `uint64_t` values, retained for
the lifetime of the controller and subject to defined unsigned wrap. They are
not serialized. No public parameter count, ID, class UID, state codec, DSP path,
or audio-thread behavior changed.

## Regression source

Added `tests/cpp/vst3_controller_revision_test.cpp`, with a single argument-free
test entry point. The fixture covers:

- Equal values, changed values, binary64 inputs that quantize to the same
  binary32 value, and boolean inputs that resolve to the same stored value.
- Independence of all eight counters and of separate controller instances.
- Rejection of malformed, unknown, uninitialized, and terminated setter calls;
  transient command writes leave all persistent counters unchanged.
- Repeated literal v1/v2/v3 recalls through both state entry points, including
  recalls that reapply unchanged values, advancing all eight counters once.
- Null, empty, truncated, and late-invalid recalls leaving counters unchanged;
  saving leaves counters unchanged and preserves the exact literal v3 packet.
- Actual SDK `UpdateHandler`/`IDependent` notifications: the observer sees the
  incremented stamp on entry; a nested equal write advances the stamp without
  creating an extra SDK value-change notification; a nested changed write
  observes the next stamp; a nested write to another parameter leaves the
  outer parameter's stamp unchanged.

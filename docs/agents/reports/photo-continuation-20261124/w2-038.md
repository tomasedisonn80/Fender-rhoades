## Findings

`set_logical_zoom` rejects nonfinite/nonpositive input, preserves equal values,
and invalidates after a change. `didOpen` initializes it from `getZoomFactor`;
successful `onSize` updates it after the SDK commits the size.

With local fit `F` and logical zoom `Z`, feedback uses
`S = clamp(0.75/(F*Z), 1, 2)`. The 16-unit help font therefore has nominal
logical size `16*S*F*Z`: 12, 12, and 16 pixels at minimum, default, and maximum
editor sizes. Device/content scale remains in the frame transform; excluding it
from `S` preserves logical sizing. The setter and feedback multiplier do not
change photograph painting, hit regions, or DPI geometry.

Resize preflight refusals precede zoom mutation. A refused frame zoom restores
`zoomFactor` without updating the view's logical zoom. Rejected content-scale
requests restore prior scale/zoom; if a host callback already changed the rectangle,
`onSize(old_rect)` performs the native/view rollback. These are source observations,
not newly exercised rejection paths.

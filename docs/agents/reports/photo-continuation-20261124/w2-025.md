## Exact new selectors and expected behavior

| Selector | Independently specified invariant |
| --- | --- |
| `observer_cancel_rollback` | Both wheel and active-drag setter callbacks cancel before perform. The only host callbacks are `begin(0), end(0)`. Observer traces are `(0.52, revision 2), (0.5, revision 3)` for wheel and `(0.6, revision 2), (0.5, revision 3)` for drag. No further capture or duplicate end survives. |
| `observer_cancel_host_changed` | The observer cancels and writes `0.75`. The host still receives only begin/end, the observer sees the provisional `0.52` then `0.75`, and final revision 3 retains the host write. |
| `observer_cancel_host_equal` | The observer cancels and writes the exact submitted canonical value. There is one SDK value-change notification, but final revision 3 and value `0.52` prove that the newer equal write survived. No perform follows the end. |
| `perform_reject_host_equal` | With and without cancellation inside a rejected perform, an exact host echo of the submitted value retains `0.52` at revision 3. The literal host trace is begin, perform `0.52`, end. |
| `perform_reject_other_parameter` | With and without cancellation, a rejected Volume perform plus a new Bass write rolls Volume back to `0.5` at revision 3 while Bass retains `0.75` at revision 2. Another parameter's revision cannot suppress rollback. |
| `keyboard_cancel_edit` | Right, Home and End each attempt to finish an old Volume drag. Cancellation from that end callback prevents a new begin or parameter mutation; revision remains 1 and later captured movement is inert. |
| `keyboard_cancel_tab` | Forward and reverse Tab encounter cancellation in the prior gesture's end callback. A separate fresh Right event must still target Volume, with a literal `0.51` perform; Treble and Sustain remain unchanged. This observes that the canceled Tab did not move focus. |
| `keyboard_audition_cancel_edit` | A keyboard edit cancels an existing audition note. Cancellation during either allocation or receiver notification of its up prevents parameter editing, leaves only down/up on key 0, and clears capture. |
| `audition_glissando_cancel_dispatch` | Moving from key 0 toward key 1 cancels inside notification of key 0's up. The exact wire trace remains key 0 down/up, with no key 1 down, no held note and no resumed capture. |
| `audition_glissando_cancel_allocation` | The same glissando invariant is required when cancellation occurs during allocation of the old key's up, before that up reaches the receiver. |

Callbacks check that they fired at the intended boundary, rather than merely checking a quiet final state. For example, glissando allocation sees one previously delivered down, while dispatch cancellation sees the second delivered event and verifies it is key 0's up. Receiver-held state and exact message counts are both checked after cancellation and cleanup.
